# 门诊病历共写与场景赋能设计


## 可行性与规范调整

可在现有 React 门诊医生站、AI 生成/流式生成、采纳审计、病历撤销、历史处方和检查报告接口上增量实现，无需另建医生工作台。

智医 `src/prompts/prompts.ts` 的 `MedicalRecordGenerationPrompt` 明确要求既往史“只写已有事实，未提及则留空”。因此原方案中自动补出“既往体健、否认过敏、查体正常、病情控制平稳”的做法不宜照搬。本次扩展文书结构和表达，未知内容写为待询问/待查体；处置建议和初步诊断继续等待医生核对。口述最高体温不当作当前实测体温。

## 明确边界

- 现有报告 DTO 没有独立“医生已解读”状态，本次不伪造未解读标识。异常报告或明确回诊意图触发报告辅助；正常报告无回诊意图时可手动切换。若需跨医生、跨会话追踪未解读队列，应另行增加报告解读确认实体与审计事件。
- 历史就诊复用现有授权目录：当前机构/科室范围，最近20次中筛选近90天最多10次已完成就诊；不是跨院全量纵向病史。报告最多50份，每份送模型最多30项观察值，界面和模型结果仍须结合原始报告核对。
- 快速续方限近90天已完成就诊的已开立西药/中成药。抗菌药、需皮试、输液及草药进入现有医嘱区重新评估；不复用历史处方ID，不自动签署或开立，当前目录、价格、库存与过敏等仍由既有开立链路校验。
- AI 扩写是辅助草稿，Prompt 约束不能替代临床审核。模型不可用时显示错误，不以固定模板冒充真实生成结果。
- 原有未提交改动保留；本次没有提交或推送 Git。

## 截图反馈与语音问诊模式补充（V8）

已参考智医语音问诊的 `voiceTreatmentRecommendationGeneration.ts`、`useVoiceCatalogMatching.ts`、`ordinaryVoiceDiagnosisGuard.ts` 和 `diagnosisCatalogMatch.ts`，补齐病历、标准诊断、院内治疗项目的联动：

- 移除病历上方单独的流式预览。五段内容直接在原病历表单中逐步显示，最终生成成功并完成采纳审计后才写入表单草稿；失败或上下文变化恢复原内容。生成期间禁止保存/签署预览，保留撤销和折叠段落对照。
- 顶部改为旋转光环、呼吸点与阶段文案组成的单行状态；1440px 实测整条 AI 摘要栏为49px。输入区压缩为两行，保持病历与诊断/医嘱左右布局。
- 第一阶段生成病历、诊断方向和治疗检索意图；诊断按有效 ICD-10 编码映射，编码缺失/无效时按标准名称或有效别名精确查询，歧义不自动采纳。前端采纳前再次复核标准目录。
- 第二阶段查询当前科室路由药房的可开药品，并逐品规检查库存和目录生命周期；检查检验查询机构已启用、有效、门诊可用的项目。模型只能从这些候选中选择，返回标识再次校验并回填目录正式名称、规格；虚构或越界标识不下发为可录入建议。
- 修正库存检索返回同通用药全部品规的问题：每个库存结果只携带对应库存产品，避免误选无库存的同名品规。
- 病历采纳引起的已知上下文变化允许保留本次诊断、治疗建议；医生后续手工编辑、患者切换或其他上下文变化仍使旧建议失效。诊断单独勾选采纳。
- “核对并录入”重新读取当前目录并定位医嘱编辑器，使用目录默认值和现有安全审核；不会自动添加、保存、签署或开立医嘱，不覆盖正在编辑的项目。目录无匹配/第二阶段失败时保留已生成病历和诊断，并提示在医嘱区检索。

## 当前就诊页一体化补充（V9）

根据医生站截图反馈，将原全宽“AI 辅助”入口与“病历共写”合并为一个 `AI 病历共写` 区域，场景识别、自动准备、文字/语音采集、接诊摘要、段落对照和更多辅助均从该区域进入，不再占用病历与诊断医嘱上方的独立横条。

- 点击“直接生成并带入病历”后自动收起采集区，生成阶段仅保留旋转光环、呼吸点和“病历 → 诊断 → 治疗建议”阶段提示；1440px 实测活动行高30px、整个共写区约222px。
- 病历结果继续直接流入原主诉、现病史、既往史、查体所见、诊疗计划字段；完成生成和采纳审计后成为待医生核对的表单草稿，顶部保留一键撤销。
- 诊断建议作为 `AI 建议 / 待医生确认` 行插入“本次诊断连续录入列表”，逐条“确认录入”后再次核对标准诊断目录并留痕，不再显示独立诊断建议面板或批量勾选区。
- 药品、检验和检查建议作为 `AI 待确认` 行插入“本次医嘱连续录入列表”；“确认并编辑”重新读取当前可用目录并进入原医嘱编辑行，仍需医生核对用法、剂量、数量、嘱托和执行要求。
- 手工修改临床上下文后，尚未确认的诊断与治疗建议失效；AI 结果不会自动保存病历、录入诊断、加入草稿医嘱或审核开立。

本轮前端7个相关测试文件共71项通过。ego-browser 在1440px和1920px完成真实模型验证：五段病历直接带入；诊断“急性上呼吸道感染，未特指（J06.9）”显示于诊断表；`C反应蛋白测定`与`对乙酰氨基酚`显示于医嘱表；目录复核可进入原医嘱编辑行。两种视口均无页面横向溢出。验收后已撤销病历、退出医嘱编辑，未保存病历、录入诊断或加入/开立医嘱。

## 治疗推荐性能与批量确认补充（V10）

本轮定位到推荐偏慢的主要原因是串行两阶段模型调用：第一阶段生成病历、诊断及治疗意图，查询院内目录和药品库存后，第二阶段再次调用模型选择目录候选。现调整为：名称或编码仅有一个精确有效目录匹配时由后端确定性采用，直接跳过第二次模型调用；只有候选存在歧义时才保留受限候选集的第二阶段选择。药品仍逐品规复核机构启用、可发药、路由药房和实时库存，不以性能为由放宽目录及库存校验。

- AI 药品、检验和检查行默认全选，也可逐项取消，统一通过“确认所选”批量处理；目录复核并行执行。
- 检验和检查直接转为数量 1 的现有待确认医嘱草稿。药品仅在目录已配置默认剂量、单位、给药途径和频次时转为可编辑草稿；缺少必要用法、命中过敏、库存不足、草药或输液分组场景会留在建议区并明确提示，不猜测临床用量。
- 转入成功的 AI 行立即移除，生成的普通草稿可在原表格中直接编辑，并继续由“审核开立”完成最终保存与开立；不会打开另一条录入行，也不会生成第二份同项目草稿。
- 当前草稿和已开立医嘱按 `类型 + catalogItemId` 去重。批量转入导致的药品/诊疗草稿指纹变化被记录为本次建议的连续状态，不再触发自动推荐；病历、诊断、患者或场景发生变化时旧建议仍会失效。
- 治疗建议转入继续记录 AI 采纳事件，便于审计来源和接受条目。
