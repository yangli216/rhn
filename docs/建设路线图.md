# 建设路线图

## 产品边界

总体按县域医共体设计，首期按一家基层机构验证。产品基线支持租户、机构和跨机构居民主索引；实施从单机构门诊闭环开始，不把住院、全量公卫和互联网医院放进首期关键路径。

## 里程碑

| 阶段 | 目标 | 主要验收物 |
|---|---|---|
| Foundation 1.0 已完成 | 业务开发基础 | 组织术语、参数当前值、MPI、临床文档、Outbox、模块边界 |
| M1 已验证 | 居民与接诊切片 | MPI、挂号、接诊、诊断、临床文档草稿、健康时间轴 |
| M2 | 门诊医疗主链 | 医嘱、处方、处置、检验检查申请、文档签署和打印 |

## 下一批建设项（M2）

1. 门诊病历签署流程与岗位工作台，复用临床文档版本底座。
2. 诊断、医嘱、处方状态机及撤销/作废轨迹。
3. 处方用药规则、药品目录和机构本地码映射。
4. 打印模板服务与处方、门诊病历打印。首批纵向切片已完成。
5. LIS/PACS 申请与结果接入契约，不在首期自建 LIS/PACS。首批纵向切片已完成。

当前已完成诊疗项目请求、门诊处方组、门诊病历签署、受控打印以及 LIS/PACS 接入契约的首批纵向切片：接诊中可按机构目录开立诊疗项目；检查检验申请固化项目类型、标本/检查类型、扩展属性和标准映射快照，可进入按机构科室隔离的外部交换队列，记录传输状态与业务接收/拒绝回执。外部报告按端点、外部报告号和连续版本追加保存，检验值进入结构化观察结果，影像报告保存结论，更正版本显式替代上一版本；相同业务消息号重复上报幂等返回，内容变化则失败关闭。药品处方支持“通用药品必选、具体产品和包装可选”，既可由临床仅按通用名开立并等待药房选品，也可直接选择产品形成包装换算和费用预览。处方组具备草稿、整单提交、单条撤销和整单撤销轨迹，药品明细固化通用药品知识、默认用法、机构采用、价格、扩展属性与标准映射快照。门诊病历每次保存形成受保护版本和科室签署待办，旧待办被新版本替代；当前版本签署生成不可否认证据并自动结束待办，未签署时禁止完成就诊。受控打印只接受已签署病历和已提交未撤销处方，服务端按版本化模板生成嵌入中文字体的 A4 PDF，保存来源快照、摘要、操作者和原始/重打任务链。当前不自建 LIS/PACS 的采集、排程、设备控制和影像存储；药房选品接方与追加式审方已完成 M3.1，批次、不可变库存账、余额投影和 FEFO 原子预留已完成 M3.2，普通门诊药品配药复核、部分发药、患者退药和批次追溯已完成 M3.3，基于实际发退药的不可变收费事项、结算凭证、收退款、冲正和日对账已完成 M3.4 普通门诊纵向切片。

M3 按“药房接方与审方 → 不可变库存账与预留 → 批次发退药 → 费用账务”推进。M3.1 已完成临床意图与药房选品分层、幂等接方和追加式审方；M3.2 已完成批次/货位、库存期间、不可变数量分录、带版本余额投影、FEFO/FIFO 整单预留、释放责任和并发超卖门禁；M3.3 已完成普通门诊药品的配药责任、预留消费、部分发药、原批次退药、库存处置和批次追溯；M3.4 已完成普通门诊实际发退药计价、应收、结算凭证、收退款、不可变借贷分录及日对账，PC 药房与收费工作台形成业务闭环。受控/高警示药品双身份会签、医保结算和财政票据按独立切片继续验收。详见 `foundation/M3药房接方与审方契约.md`。

M4 按“候选识别 → 照护计划 → 随访执行与异常回流 → 公卫上报回执”推进。M4.1 已落地首个高血压纵向切片：接诊血压保存为 LOINC 结构化观察结果，成年居民单次异常只生成 `SUSPECTED` 病情和权威复测任务；显著升高进入立即复测及转诊评估提示，但系统不自动确诊或自动转诊。任务规则编码、版本、两条观察结果、阈值、判断和 SHA-256 证据随追加式事件保存，并投影到岗位工作台；PC 连续照护工作台同时展示候选队列、血压事实、规则证据和“单次异常不等于确诊”安全边界。下一批 M4.2 建设照护计划、目标、临床确认和任务编排。详见 `foundation/M4医防一体化契约.md`。

基础数据扩展属性已作为本轮横切底座同步收口：V19/V20 落地项目类型树、药品/检验/检查强类型扩展、属性定义与装配、作用域覆盖、确定性解析和不可变快照；本轮补齐了租户属性定义/类型装配配置、科室覆盖、显式空值、字典型单选/多选、追加式审计和多租户排序隔离。门诊诊疗申请与药品请求持久化开立时快照，M3 发药任务行复制并使用该快照；跨模块回归已验证配置变化不改变既有请求与任务解释。缓存表、属性发布版本、通用审批和任意 JSON/EAV 检索仍不列入本轮。详见 `foundation/基础数据扩展属性本轮实施方案.md`。

M2 进入生产联调前必须先选定密码产品/服务、个人证书与可信时间戳方案，并将处方、医嘱、检验检查和打印行为登记到关键数据密码保护目录；开发阶段可以使用统一适配层模拟流程，但不得把开发签名当作上线密评能力。

## 完成定义

每个业务能力必须同时具备：领域规则、数据范围、异常分支、数据库迁移、接口契约、自动化测试和用户验收场景。正式权限、安全、监控、备份和发布要求在相应专项启动后纳入上线完成定义；仅有页面或演示数据不算完成。
