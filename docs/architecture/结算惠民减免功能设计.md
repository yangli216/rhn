> 状态：一期实施中。已完成：数据模型与迁移 `V1_129_15__billing_relief_policy`（含 `BILLING_RELIEF.MANAGE/ROSTER/APPROVE` 权限、“惠民政策管理员”角色、结算 `AMT_RELIEF` 与收款 `ID_RELIEF_APPLY`）；`ReliefCalculator`；政策/名单服务与 `/api/billing/relief` 接口；结算集成——开具账单时按 `settlementMode` 执行医保前减免，医保正式结算回执后自动执行医保后减免，`/api/billing/settlements/{id}/relief`（概况与预览）与 `/relief/confirm`（自费确认、人工核准），RELIEF 贷方账务、额度占用与结算完成确认，财政票据将减免按“其他支付”申报。退费冲销已实现：开具贷项账单生成冲正结算时，按原政策版本对保留费用重算并冲回差额（医保前为冲正行负向优惠，医保后为负向减免收款），直接退费冲销收费事项时同步冲回；记 RELIEF_REVERSAL 借方账务并恢复额度（全部冲回时恢复次数）。叠加政策冲销时按单项政策独立重算。前端已完成：收费管理下的“惠民政策”（`/billing/relief-policies`，主从页：政策目录 + 基本信息与时机 / 资格条件 / 费用范围与规则 / 额度与组合 / 版本记录，草稿保存、发布、暂停、恢复、停用）与“惠民资格名单”（`/billing/relief-roster`，查询、新增、修改有效期、停用、CSV 批量导入预检与导入）；收费结算新增“惠民减免”块（已执行减免、可享受的医保后减免确认、人工核准录入），开具结算时按结算方式传递 `settlementMode`，新结算单因医保前减免应收变小或存在待确认的医保后减免时暂停收款，医保正式结算后以结算单待收金额为准收款。人工核定与对账查询已实现（迁移 `V1_129_16__billing_relief_manual_and_query`）：含“人工核定”规则的医保后政策作为核定类别，收费员在收费结算“惠民减免”块按需展开“核定”，在本次可核定金额内填写金额、原因与依据；`BILLING_RELIEF.DECIDE`（收费员核定，随收费访问授予门户操作员）可在政策“核定审批阈值”内核定，超过阈值需 `BILLING_RELIEF.APPROVE`；预览返回每项可核定上限与审批阈值。收费管理新增“惠民减免查询”（`/billing/relief-records`，`BILLING_RELIEF.QUERY` 或政策管理权限，接口 `GET /api/billing/relief/records`）：按减免记录时间、政策、承担主体、时机、人工核定、结算是否完成与关键字查询当前机构的减免与退费冲销，按政策与承担方汇总减免、冲销、净额与享受人数，明细带出患者、资格依据、核定原因/依据/核定人与经办人，可导出 CSV（单次最多 5000 条）供承担方对账报销。本期只接入门诊与药房收费；挂号、住院（预交金顺序）、外部资格接口、退费预检的减免冲销展示、日结列示、模拟试算待做；查询暂不含身份证号。医保后按行分摊沿用医保比例分摊，尚未使用医保明细审核金额。
> 归属：rhn-clinical `billing` 领域（后端 `com.rhn.billing`，前端 `features/billing/` 与收费类设置页）。

## 1. 目标与覆盖场景

统一的“惠民减免引擎”，以 **政策配置 + 资格认定 + 费用范围 + 计算规则 + 额度管理 + 结算集成** 六部分组成，门诊挂号、门诊收费、住院中途/出院结算共用。

| 典型政策 | 资格 | 时机 | 费用范围 | 规则 |
| --- | --- | --- | --- | --- |
| 家医签约居民免挂号/诊查费 | 签约居民名单（或签约平台接口） | 医保前 | 明细：普通挂号费、一般诊疗费 | 全免 |
| 签约居民免费血压/血糖测量 | 签约居民 | 医保前 | 明细：血糖测定 | 全免，年度 12 次 |
| 65 岁以上老人免费体检 | 年龄 ≥ 65 | 医保前 | 体检套餐项目 | 全免，每自然年 1 次 |
| 孕产妇惠民减免 | 孕产妇名单/妇幼接口 | 医保后 | 全部剩余自付 | 30%，单次上限 100 元 |
| 民政救助（低保、特困） | 民政名单/医保人员类别 | 医保后 | 全部剩余自付 | 单次 ≤ 200 元，年度 ≤ 1000 元 |
| 退役军人/离休优抚 | 优抚名单 | 医保后 | 大类：西药费、检查费 | 比例减免 |
| 本院职工及家属优惠 | 职工名单 | 医保前 | 大类：诊查费、检查费，排除药品 | 50% |
| 义诊/专项活动 | 全部患者，限活动期 | 医保前 | 指定明细 | 全免或固定价 |
| 院长特批/困难救助 | 人工核准 | 医保后 | 全部剩余自付 | 人工核准金额，需授权 |

**差距**

1. 没有任何减免计算、政策、资格与额度模型；`discountAmount` 只有读取，没有写入入口。
2. 账务只有 `CHARGE`(借)/`PAYMENT`(贷)/`PAYMENT_REFUND`(借)，减免不进账会让患者账户长期挂欠。
3. 医保结果按比例 `allocateLines` 分摊到行，医保后“按明细减免”需要行级自付（可利用医保申请行 `approvedAmount`）。
4. 住院结算在开具凭证时立即冲抵预交金（`applyInpatientPrepayments`），与“减免后再抵付预交金”顺序冲突。
5. 系统内没有家医签约、人群标签模块；签约居民等身份需由名单或外部接口提供。
6. 财政票据资金分摊 `ReceiptFundingService` 未处理非医保来源的 `HOSPITAL_DISCOUNT/SUBSIDY`。

## 3. 核心概念与计算规则

### 3.1 减免时机（本次重点）

| 时机 | 业务含义 | 计算基数 | 记账方式 | 对医保的影响 |
| --- | --- | --- | --- | --- |
| `PRE_INSURANCE` 医保前 | 价格让利/免收，医院不向任何一方收取该部分 | 行原额（已扣前序医保前减免） | 写 `SettlementLine.discountAmount` 与 `Settlement.discountAmount`，`netAmount` 下降；账务记 `RELIEF` 贷方 | 医保按减免后金额结算；全免行净额为 0 |
| `POST_INSURANCE` 医保后 | 对患者个人负担的补助/减免 | 行级剩余个人自付（净额 - 医保统筹 - 其他基金 - 前序医保后减免），可配置是否扣除个人账户 | 新增 `SettlementTender`（`HOSPITAL_DISCOUNT` 或 `SUBSIDY`，按承担主体）；账务记 `RELIEF` 贷方 | 不影响医保 |

- 自费患者两种时机都直接作用于自付金额，但仍分别记为“优惠”或“补助支付”，统计口径不变。
- 医保前减免存在合规边界：项目上报医保时“单价 × 数量 ≠ 金额”或 0 元行可能被拒，需在适配器中按地区规则处理（上报折后单价、或全免行不上传）。政策配置时对“医保前 + 医保患者”给出提示，由医院医保办确认口径。
- 医保后的计算基数默认“剩余现金自付”；个人账户是否计入基数作为政策参数（`BASE_INCLUDES_PERSONAL_ACCOUNT`）。

### 3.2 费用范围

政策下挂多条**减免规则行**，每行 = 范围 + 方式 + 行级限制：

- 范围类型：`ALL` 全部、`ACCOUNTING_CATEGORY` 会计大类（字典 `BD_ACCOUNTING_CATEGORY`）、`CATALOG_ITEM` 收费项目明细、`SOURCE_TYPE` 来源（挂号/药品/检查）、可选 `INSURANCE_CLASS` 医保甲乙丙类（仅医保后）。
- 支持排除清单（如“全部费用，排除药品费”）。
- 匹配优先级：明细 > 大类 > 来源 > 全部；一个收费行只命中同一政策内最具体的一条规则。

### 3.3 计算方式

| 方式 | 说明 | 场景 |
| --- | --- | --- |
| `RATIO` 比例 | 基数 × 减免比例 | 孕产妇 30%、职工 50% |
| `FREE` 全免 | 基数全部减免 | 签约免挂号费、免费体检 |
| `FIXED_AMOUNT` 固定金额 | 本次减免固定额（按行基数比例分配） | 民政每次补 200 元 |
| `UNIT_AMOUNT` 单位减免 | 每单位减 x 元 | 某检查每次减 10 元 |
| `PRICE_CAP` 个人限价 | 患者每单位最多负担 x 元 | 签约居民血糖测定按 1 元收 |
| `MANUAL` 人工核准 | 收费员录入，需权限及原因、依据、核准人 | 院长特批、困难救助 |

计算公式沿用沟通稿：`本项实际减免 = min(原始减免, 当前可减免余额, 单次上限, 周期剩余金额)`；周期次数用尽则不减免。所有中间值 6 位精度，单政策合计按收费精度（分）四舍五入且不超过上限及各行可减余额（按分向下取整）之和；拆分到行时先按权重向下取整到分，剩余的分按最大余数法补给仍有余额的行，保证行合计 = 单据合计（满足 `ReceiptLineService` 校验）。

### 3.4 资格认定

引入**资格类别**（字典，如签约居民、孕产妇、低保、特困、优抚、本院职工），政策引用资格类别而不是直接引用名单，多项政策可共享同一名单。资格来源：

| 来源 | 实现 |
| --- | --- |
| `ALL` 全部患者 | 无条件 |
| `ROSTER` 名单 | 计费域维护的资格名单：居民 ID、证件号、有效期、依据附件、来源批次；支持 Excel 导入（证件号经 MPI 匹配居民）、到期提醒 |
| `ATTRIBUTE` 属性条件 | 年龄段、性别、医保险种/人员类别（医保读卡 `PersonInfoView`）、就诊科室、诊断编码等，使用简单条件表达式 |
| `PROVIDER` 外部接口 | `ReliefQualificationProvider` SPI（妇幼、民政、家医签约平台）；配置失败策略：阻断 / 视为不符合 / 允许人工确认 |

资格判定结果连同依据（名单记录 ID、接口流水号、条件快照）写入减免明细，用于追溯。

### 3.5 额度与组合

- 额度：单次上限；周期（每次/日/月/季/自然年/政策期/自定义孕程）金额上限与次数上限；规则行可单独设“该项目周期次数”（如免费体检每年 1 次）。
- 共享范围：门诊/住院是否共享、机构是否共享 → 生成额度键 `政策 + 居民 + 周期键 + 共享键`。
- 组合：执行优先级；互斥组（同组仅取一个）；互斥选择方式 `PRIORITY`（按优先级）或 `BEST`（试算择优，二期）；是否允许与其他政策叠加。
- 执行顺序固定为：**医保前政策（按优先级）→ 医保预结算/结算 → 医保后政策（按优先级）→ 住院预交金抵付 → 患者支付**。

### 4.3 结算流程集成点

```text
试算 POST /billing/accounts/{id}/relief-preview      (只读，不占额度，可重复)
  │
开具凭证 issueInvoice(+reliefSelections)             ← 医保前减免在此落账
  └─ createFromInvoice → SettlementReliefService.applyPreInsurance
       写行/单 discountAmount、RELIEF 账务、额度 RESERVE
  │
医保预结算/结算（按折后净额）                         ← 不变
  └─ recordInsuranceResponse 末尾 → applyPostInsurance
       用医保行级 approvedAmount 推算行自付，写 HOSPITAL_DISCOUNT/SUBSIDY tender、RELIEF 账务、额度 RESERVE
自费：POST /billing/settlements/{id}/relief/confirm-self-pay → applyPostInsurance
  │
住院：预交金抵付移到医保后减免之后
  │
结算 SETTLED（含个人应付为 0）→ 额度 CONFIRM
结算放弃/冲正 → 额度 RELEASE / REVERSE
```

- `IssueInvoiceCommand` 增加 `reliefSelections`：收费员取消可选政策、录入人工核准金额与依据；后端用可信费用重新计算，前端值只作为意图。
- 已应用医保后减免的结算若再发起医保预结算，需先撤销该减免（避免先按自费减免再走医保）。
- `Settlement` 增加 `applyPreInsuranceDiscount(...)`，复用 `netAmount` 公式；医保后减免作为 tender 计入 `totalTendered`，`applyPaidAmount` 无需改动即可在应付为 0 时完成结算。
- 挂号：`RegistrationBillingService` 走同一 `SettlementReliefService`（场景 `REGISTRATION`），覆盖签约免挂号费。

### 4.4 退费与冲销

退费沿用“冲销收费事项 → 贷项凭证 → REVERSAL 结算”：

1. **医保前**：冲销行按原结算行的减免比例带出负 `discountAmount`，账务写 `RELIEF_REVERSAL`。
2. **医保后**：对保留费用用原政策版本重算 `R'`（额度计算排除本单自身占用），冲销额 = 原减免 `R` − `R'`，写负 tender 与 `RELIEF_REVERSAL`。
3. 额度：按冲销额恢复金额；仅整单冲销时恢复次数（政策可配置）。
4. 因减免进出都过账，`refundPayment` 的“账户贷方余额”校验自动保证 **退款 ≤ 患者实付**；`RefundPreCheckService` 预检中展示减免冲销额与实退金额。

### 4.5 配套改造

- `ReceiptFundingService`：`HOSPITAL_DISCOUNT/SUBSIDY` 非医保来源映射到财政票据“其他支付/医院减免”栏。
- 日结 `CashierClose*`：减免、补助单独列示（非现金，不进收款合计），对账公式 `总费用 = 优惠 + 医保 + 减免补助 + 患者实收 ± 舍入`。
- 医保适配器：医保前减免行的单价与 0 元行处理（地区开关）。
- `reporting/BillingReportSources`：新增减免明细数据源，供统计分析。
- 权限：`BILLING.RELIEF.POLICY`（政策维护）、`BILLING.RELIEF.ROSTER`（名单）、`BILLING.RELIEF.MANUAL`（人工核准）、`BILLING.RELIEF.QUERY`（查询统计）；人工核准金额超阈值需二次授权（复用 `SettlementAuthorizationDirectory`）。
- 领域事件：`BILLING_RELIEF_APPLIED / BILLING_RELIEF_REVERSED`，供统计与审计订阅。

## 6. 分期建议

| 期次 | 内容 |
| --- | --- |
| 一期（可上线最小闭环） | 数据模型与迁移；政策（含两种时机）、资格类别与名单（手工+导入）；比例/全免/固定/限价/人工五种方式；大类与明细范围；单次与周期金额/次数额度；优先级与互斥组；门诊收费 + 挂号接入；退费冲销与部分退费重算；收费界面减免块；减免明细查询；日结列示 |
| 二期 | 住院中途/出院结算（含预交金顺序调整）；财政票据映射；统计报表与分析数据源；属性条件资格（年龄、医保人员类别）；项目周期次数（免费体检）；人工核准二次授权 |
| 三期 | 外部资格接口（家医签约、妇幼、民政）；择优互斥；孕程等自定义周期；医保甲乙丙类范围；地区医保适配器口径开关 |

## 7. 待业务确认

1. 签约居民名单来源：手工导入还是对接家医签约平台？更新频率？
2. 医保前减免对医保患者是否允许，医保上传口径（折后单价/0 元行）由医保办确认。
3. 医保后基数是否包含个人账户支付。
4. 部分退费时次数额度是否恢复。
5. 人工核准的金额阈值与二次授权角色。（已按政策设置核定审批阈值；超阈值由有审批权限的人员在收费界面核定，暂无异地二次授权。）
6. 周期额度在门诊、住院、多机构之间的默认共享方式。
