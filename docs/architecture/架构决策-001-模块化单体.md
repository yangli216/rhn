# 架构决策-001：首期采用模块化单体

- 状态：已采纳
- 日期：2026-08-24

## 决策

首期使用一个主要后端部署单元，按 `platform`、`healthcore`、`outpatient` 领域模块隔离。模块拥有自己的表；跨模块同步调用公开 API，业务变化通过领域事件传播。

## 约束

- 禁止模块直接修改其他模块的数据表。
- 禁止把居民、诊疗、药品、收费等业务对象放入 `common`。
- 健康时间轴是事件投影视图，不将全系统改造成事件溯源。
- 业务事实先写入事务 Outbox；当前进程内同步投影按事件 ID 幂等，未来跨进程分发复用同一事件信封。
- 架构测试检查模块循环依赖。

## 原因

模块化单体可保留清晰领域边界，同时避免首期承担分布式事务、部署和现场运维复杂度；当独立伸缩或独立发布的证据出现时，再按模块边界拆分。
