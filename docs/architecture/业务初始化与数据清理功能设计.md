# 业务初始化与数据清理功能设计

日期：2026-10-13。状态：功能设计建议，尚未实现。

已确认需求：上线前基础数据初始化、测试业务数据清理；支持按租户、按机构、按业务模块勾选清理。“业务版本”已确认为“业务模块”，系统发布版本只作为任务留痕。

## 1. 功能定位与场景

建议在“系统管理”下新增“业务初始化与数据清理”，集中管理初始化方案、清理计划和执行记录。

| 场景 | 主要行为 | 默认保留 |
| --- | --- | --- |
| 基础数据初始化 | 按方案补齐机构业务配置、目录启用与价格、业务基础配置；支持导入正式数据 | 已有配置、业务记录、平台元数据 |
| 测试业务清理 | 清理选定机构/租户、模块、测试批次内的业务记录及其必要关联 | 租户、机构、人员、账号权限、基础目录及配置 |
| 上线前业务重置 | 在尚未正式上线的范围内，清理所选模块的全部业务记录；完成后单独发起初始化 | 系统骨架、平台元数据、默认保留的基础配置 |

初始化与清理是独立任务。组合方案可依次执行“清理 → 校验 → 初始化”，但分别生成执行记录；清理失败不得继续初始化，初始化失败不得把已完成清理描述为整体回滚。

范围上线后关闭“上线前重置”。正式生产范围仅开放有明确来源的测试批次清理；真实诊疗、资金或库存业务通过原有作废、退费、退药等流程处理。本功能不提供正式业务的任意物理删除。

## 2. 选择范围

一次任务限定一个租户。租户来自已认证且获授权的上下文，不允许提交任意租户 ID 获取执行资格。平台运维跨租户维护需通过已有授权入口切换目标租户，每个租户独立预览和执行；第一期不建设跨租户批量清理。

| 条件 | 规则 |
| --- | --- |
| 租户范围 | 明确选择“当前租户全部机构”，需要独立的租户级维护权限；机构权限不能推导出该权限 |
| 机构范围 | 支持一个或多个获授权机构；机构均须归属当前租户 |
| 下级机构 | 默认不包含，明确勾选后由服务端展开实际机构清单；科室不自动当成独立机构 |
| 业务模块 | 多选可用的业务数据集，未接入清理能力的模块显示“暂不支持” |
| 数据范围 | 优先测试批次；上线前重置允许选定范围内全部业务数据 |
| 时间范围 | 第二期增加，必须明确每类业务采用的时间字段；只是根业务筛选条件，关联明细按依赖闭包处理 |

机构清理只删除机构拥有的记录。患者主档等租户共享实体不能以“在本机构出现过”作为删除依据；没有机构字段的明细，通过所属业务主记录及租户条件限定，不能直接按明细创建时间删除。

租户级清理也不等于删除租户：租户、机构、登录及权限骨架默认保留。租户注销、机构撤销另属账号与组织管理流程。

## 3. 数据分类与模块粒度

功能界面展示业务名称，底层维护经过评审的数据集清单。以下是候选范围，具体实体及执行能力在模块接入时确认，不依据表名前缀推断。

| 分类/模块 | 候选业务数据 | 默认策略 |
| --- | --- | --- |
| 平台保护数据 | 租户、组织、人员、账号、角色权限、系统字典定义、元数据、迁移记录、维护审计 | 不进入普通清理选项 |
| 机构基础配置 | 目录启用、机构价格、排班基础配置、库房/货位配置、业务参数 | 默认保留；重置为独立高级操作，检查引用及共享来源 |
| 门诊 | 挂号、就诊、病历、诊断、医嘱及相关业务状态 | 可勾选；收费、执行、药房关联另列影响 |
| 住院 | 入出转、床位占用、住院医嘱及关联记录 | 可勾选；释放占用，检查收费和药品供应依赖 |
| 收费/结算 | 费用、收费单、支付/退费、票据、医保申报关联 | 可勾选；真实支付、正式票据、真实医保交互阻断物理清理 |
| 药房/库存 | 审方、发药、退药、处方冻结、出入库、库存余额 | 模块下再拆数据集；默认保留库房及期初库存，余额不得直接置零 |
| 检验检查/治疗 | 申请、执行、结果、治疗和皮试记录 | 接入后可勾选；已送外部系统的申请先检查同步状态 |
| 排队/业务派生数据 | 候诊、业务投影、业务专属缓存、可重建统计结果 | 随所属业务处理，须限定范围并完成重建/失效校验 |
| 患者/居民主档 | 主索引、标识、关联来源及合并关系 | 默认保留；仅在证实为测试数据且全部引用均可安全解除时单独清理 |

药房至少区分“处方审发与冻结”“库存单据及流水”“期初与当前库存”。只清理发药单据而保留其库存扣减会产生不一致，因此由药房规则决定阻断或扩大为完整库存重置范围，预览必须展示库存前后差异。

上级机构或目录来源机构的配置可能供其他机构使用。重置该配置时检查全部消费者；不能以单机构选择绕过共享目录引用。

## 4. 初始化方案

建议第一期提供“基础配置补齐”“机构目录导入”两类方案；演示业务数据生成随后接入测试批次管理。

每个方案记录编码、名称、版本、适用范围、依赖项、数据来源、适用程序/结构版本、内容指纹。已执行版本保持可追溯；改动方案形成新版本，不混用实体乐观锁版本。

执行顺序按依赖生成：机构及科室映射 → 业务基础配置 → 机构目录及价格 → 期初数据 → 完整性校验。组织、人员、账号的建设复用原有管理服务或导入能力，初始化任务不能重新生成现有系统账号。

初始化写入策略：

- 默认“仅补缺”，相同业务键的数据跳过；已有数据不静默覆盖。
- 需要更新时明确选择“更新选定配置”，预览旧值、新值及引用影响，通过既有应用服务的版本校验和变更原因规则写入。
- 导入错误按行返回，执行前检查字典编码、组织归属、价格/金额语义、目录引用及必填项。
- 期初库存复用库存入账语义，并在允许的业务状态下执行；第一期不支持在已有库存流水上直接覆盖期初余额。
- 同一范围、方案版本、输入文件指纹及命令标识支持幂等，失败后查询原任务或恢复未完成步骤。

现有 Flyway 公共元数据迁移与 local/oracle-local 开发样例保持原职责。业务初始化页面不重复执行 Flyway、不清空迁移历史，也不把开发医院 SQL 直接包装为通用正式初始化方案。

## 5. 测试批次与数据来源

按模块清理必须可区分测试记录与正式记录。建议新增受控批次及业务对象来源登记，在业务根对象创建/导入时写入来源；派生费用、冻结、执行记录等继承根业务来源，不能仅标记初始化工具直接写入的行。

批次记录租户、目标机构、用途（正式初始化/测试/演示）、方案版本、创建人、创建时间和对象清单。正式初始化批次不自动归为可删除的测试批次。

批次归属证明“如何创建”，不代表永久可以删除。若对象被修改、与正式业务关联，或形成真实支付/库存影响，重新做依赖检查并阻断不安全删除。初始化曾更新的已有共享记录不能作为本批次新对象删除，需保留变更前后值及恢复条件。

历史数据无可靠来源时显示“来源未确认”。不得根据姓名、创建账号、ID 段或创建时间自动认定测试数据。可生成候选对象清单供核对，登记明确来源证据后再清理；新功能不能宣称自动识别全部既存测试数据。

## 6. 清理计划、影响预览与确认

操作流程：选择场景和范围 → 勾选模块/数据集 → 生成预览 → 解决阻断 → 确认执行 → 查看进度及校验报告。

预览至少包含：

- 租户、机构名称及实际展开机构数；所选模块、批次、根业务对象清单。
- 各模块业务对象数量、物理记录数量、关联明细数；二者分列，避免重复计数。
- “将清理”“将保留”“必须关联处理”“阻断执行”四类结果及原因。
- 资金与库存影响摘要、外部交互状态、共享实体引用、对象来源不明等阻断项。
- 数据库记录之外的附件、缓存、投影和事件处理步骤，以及备份恢复依据。

例如选择“机构 A 的门诊测试批次 T”：其处方存在费用、冻结和发药记录时，预览提示收费/药房的具体关联对象。用户须明确接受扩大模块范围或缩小根对象范围；系统不能静默追加其他模块，更不能扩大到机构 B 或正式数据。仅缺乏外键不代表没有业务依赖。

服务端生成不可变计划及计划指纹，记录范围、对象 ID/版本、依赖闭包、规则版本和有效期。提交执行携带计划 ID、指纹及幂等键，不重新解释客户端的一套筛选条件。规则变化、权限变化、对象变化或预览过期均要求重新预览。

确认界面展示目标环境、范围、模块及记录数，填写操作原因；清理用共享危险操作按钮，要求输入目标机构/租户名称确认。正式环境的测试批次清理增加独立授权/复核能力；第一期可保持正式环境物理清理入口关闭，待上线策略落实后开放。

## 7. 执行与失败处理

建议采用后台任务；页面关闭不取消任务，重开后可查询。

1. 重新核验授权、计划和目标环境，取得范围维护锁。租户级与其下机构级任务互斥；共享配置影响按消费者扩大锁定范围。
2. 暂停该范围的写入口、后台任务和事件消费，等待在途事务结束；外部回调需有持久暂存/拒绝及后续核对策略，不得丢弃。
3. 在写入冻结状态下校验对象版本与全部业务依赖。发现新增关联则停止、重新预览，不删除预览之外的记录。
4. 核验适合本次范围的可恢复备份/快照及恢复流程，记下引用。整体库备份不能被描述成可无影响地恢复单机构；需要同范围导出或隔离恢复后的定向回灌方案。
5. 按领域规则解除测试业务占用，并按依赖逆序清理关联对象。资金、库存和外部交互存在不可撤销真实影响时阻断。
6. 范围内缓存失效、投影重建；待发送事件失效/隔离，防止重放重新生成已清理业务。附件采用持久待处理记录驱动，数据库提交后再删，失败可以重试。
7. 校验无孤儿记录、无残留占用、库存账实/流水关系正确、保留配置完整；校验和后处理完成后释放维护状态。

不能用表级 TRUNCATE、关闭外键约束、任意表名/SQL输入或全库 Redis flush 代替受控清理。业务编号生成器及已用序列默认保留，不因清理测试记录而重用历史编号。

小规模、同库且经评审的闭包可在一个事务中执行；大规模按领域确定一致性单元、分步提交并保存检查点，不承诺跨数据库、文件与缓存的一键事务回滚。各阶段发生中断时保持维护阻断，恢复任务或按已验证方案恢复数据，不能直接开放残缺业务。

推荐状态：待预览、预览阻断、可执行、准备中、执行中、校验中、成功、失败、部分完成、已取消。执行开始前可取消；执行后只能请求在安全检查点停止，已提交步骤保留，状态显示“部分完成”。失联执行器用租约及隔离令牌防止重复写，维护阻断不随租约自动失效而开放。

## 8. 页面设计

入口页签建议为“基础初始化”“业务清理”“执行记录”，页面顶部固定展示当前环境、租户、目标范围及上线状态。

- 业务清理采用 MasterDetailPage：左侧范围及模块选择，右侧宽表展示影响预览；主操作固定于详情底部，预览有效且无阻断时启用“执行清理”。
- 基础初始化采用 FormPage：方案、版本、机构和写入策略以 2–3 列排布；正文显示导入校验及变更预览，底部固定当前步骤的主操作。
- 执行记录采用 ListPage：按机构、类型、状态、时间筛选；列表展示任务号、范围、模块、数量、操作者、时间和结果，详情展示步骤、影响、失败位置及恢复依据。

沿用共享 Tabs、Button、Select/DictionarySelect、FormField、DataTable、Dialog 和页面模板；普通固定选项与字典选项按已有标准区分。列表/详情的工具区固定，正文独立滚动，同一栏不套第二个正文滚动区；适配 1280/1440/1920px 及标准/大字档，不另做移动端界面。

切换租户、机构、模块、批次或方案后立即使旧预览失效；迟到响应不得重新激活旧计划。无权限、未接入模块、零条数据、来源未知、运行中和失败各有明确状态，日志与样例对象默认脱敏。

## 9. 项目落地边界

当前项目已有 TenantContext、ExecutionContext、OrganizationDirectory、幂等服务、机构目录版本规则和分领域模块。平台模块只允许依赖 shared，不能为了清理直接导入门诊、收费或药房仓储。

建议在 rhn-platform 新增维护计划、任务、批次及执行能力接口；各业务领域实现自己的预览/校验/执行适配器，应用组合根负责装配。平台调度只面向公开能力接口；查询、删除顺序、库存不变量及数据归属由拥有该数据的领域负责。迁移表名与字段按数据库规范登记，本轮不预定迁移编号。

建议持久化对象：初始化方案及版本、数据来源批次及对象登记、不可变预览计划、执行任务、步骤回执、追加式维护审计、范围维护状态。审计和恢复凭据不进入业务清理闭包；日志仅存必要标识/汇总，避免复制完整诊疗记录。

建议 API 能力：查询方案/数据集 → 校验初始化输入 → 创建预览计划 → 按计划启动任务 → 查询任务及步骤 → 安全停止/恢复。路径、权限编码及 OpenAPI/生成类型在实现阶段沿用现有约定，不另造通用数据库控制接口。

异步任务显式绑定租户、目标机构和操作者，并在执行及恢复时重新鉴权；不能依赖 HTTP 请求线程的 ThreadLocal 自动传到工作线程，也不能以后台“system”身份绕过原授权。

## 10. 分期与验收

| 阶段 | 交付边界 |
| --- | --- |
| 第一期 | 基础配置补齐/机构目录导入；租户与机构范围；门诊、收费、药房测试业务闭包；批次来源、影响预览、范围维护、备份依据、异步任务和审计。上线前全量业务重置仅对已完整接入的数据集开放 |
| 第二期 | 住院、检验检查、治疗、更多基础数据重置；带明确业务时间语义的筛选、模板复用、正式环境复核策略 |
| 后续增强 | 演示数据生成、历史测试数据归属核对、恢复演练自动化、批量机构实施及上线检查单 |

第一期验收重点：

1. 清理租户 T1/机构 A 不影响 T2/机构 B；伪造租户、机构、计划或任务 ID 均拒绝访问/执行。
2. 同一患者在 A/B 就诊，清理 A 后患者主档和 B 的记录保留；共享目录消费者保留。
3. 门诊关联收费、冻结、发药时，未接受完整依赖范围则阻断；处理后无孤儿费用/明细、库存残留冻结或错误余额。
4. 缺少来源、真实支付/医保交互、真实业务引用、不能恢复的备份或未接入模块均不能误标为可执行。
5. 预览后数据或权限变化、双击提交、任务重复恢复、后台重启、锁过期等不会扩大范围或重复处理。
6. 部分执行、附件失败、投影重建失败可定位并恢复；阻断状态持续到校验通过，事件重放不恢复已清理记录。
7. 重复初始化不产生重复配置，已存在数据按策略跳过；明确更新遵守版本校验，失败不覆盖无关记录。
8. 基础配置、编号序列、迁移历史及维护审计默认保留；上线前重置与正式业务作废的入口和语义明确。

本轮仅新增设计文档，检查链接和设计一致性，不运行应用测试、构建或真实浏览器 QA。未来实现涉及租户权限、跨模块契约、迁移、库存和资金不变量，需隔离 H2 测试及相应完整后端/契约检查，按项目 verify-scope 维护范围选择；Oracle 适配与人工视觉/恢复演练另行记录。
