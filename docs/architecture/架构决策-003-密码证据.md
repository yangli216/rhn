# 架构决策-003：关键数据完整性与不可否认统一密码证据底座

- 状态：已采纳
- 日期：2026-08-25

## 背景

医疗系统的关键数据保护不是在业务表旁增加一个散列字段即可完成。完整性需要证明“受保护原文没有改变”；不可否认还需要证明“谁在何种业务语义下、对哪个版本、于何时作出了什么行为”，并能够用可信身份、证书、签名密钥和时间证据复核。

现行密评基线为 [GB/T 39786-2021《信息安全技术 信息系统密码应用基本要求》](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=53282C88712CE157043B7A2C590278FC)，测评要求为 [GB/T 43206-2023《信息安全技术 信息系统密码应用测评要求》](https://openstd.samr.gov.cn/bzgk/gb/newGbInfo?hcno=EE1B34C97A17C6F13FA9A9D891C144C2)。国家密码管理局的应用层解读明确覆盖用户/管理员身份真实性、行为不可否认性以及重要数据的机密性和完整性；最终保护对象、强度和测评边界仍须由项目密码应用方案与测评机构确认。

## 决策

建立 `platform.cryptography`，业务模块只能依赖其 `api` 契约，不能直接调用具体密码库、签名服务器或密钥设备。

一次保护操作产生一份追加式 `cryptographic_evidence`：

1. 对业务实际持久化的原文字节计算摘要；
2. 生成版本化的精确签名声明，绑定租户、目标类型、目标 ID、业务版本、操作、保护策略、原文摘要、操作者、关联号、发生时间和上一证据摘要；
3. 由密码服务对完整声明签名；
4. 保存算法、服务商、密钥标识、签名值、签名主体、证书、签名时间及可信时间戳材料；
5. 验证时同时检查原文摘要、声明摘要、数字签名、声明与数据库列的绑定及前序证据链。

保护策略由平台枚举统一管理。业务只能选择已经评审的策略，不能自行选择算法或拼装待签名字符串。第一批策略为：

| 策略 | 目标 | 签名主体 | 可信时间 |
|---|---|---|---|
| `CLINICAL_DOCUMENT_CONTENT` | 临床文档版本内容完整性 | 系统 | 可选 |
| `CLINICAL_DOCUMENT_SIGNATURE` | 医务人员签署行为不可否认 | 当前人员 | 必需 |
| `DOMAIN_EVENT` | 关键跨模块事实完整性 | 系统 | 可选 |
| `AUDIT_EVENT` | 高价值审计事件完整性 | 系统 | 必需 |

临床文档作为首个纵向验证：每次创建、修改、签后修订都会生成完整性证据；签署前先验证当前版本完整性，再生成包含签名含义的不可否认证据。业务表只保存证据引用和展示所需摘要，不复制密码实现。

## 生产与开发的严格边界

仓库内 `development-jca` 仅用于本地开发和自动化测试：它使用进程内临时 EC 密钥、SHA-256 和 ECDSA，保障开发链路连续并验证篡改检测逻辑，但其保证等级固定为 `DEVELOPMENT_ONLY`，不代表国密合规，也不构成医务人员个人签名。

生产配置默认没有密码服务并开启合规门禁。关键数据写入会失败关闭，只有适配器同时满足以下策略才允许生成证据：

- 声明为经项目核验的合规密码产品或服务；
- 按密码应用方案提供 SM3 摘要和 SM2 签名，或提供方案明确批准的算法组合；
- 人员不可否认签名绑定当前账号主体与个人证书，私钥由签名服务器、密码设备或合规云密码服务受控使用；
- 需要可信时间的策略返回可独立保存、验证的时间戳材料；
- 验证端校验证书链、有效期、吊销状态、密钥用途、签名值和可信时间戳，不能信任证据表内自带的公钥；
- 支持密钥/证书轮换后历史证据长期验证，并保留供应商、产品型号、认证证书与配置基线等测评材料。

共享 HMAC、应用数据库中的私钥或“账号名 + 当前时间”不能替代个人不可否认签名。

## 数据与运维约束

- `cryptographic_evidence` 在应用模型中无更新接口；生产数据库账号需只授予插入和查询权限，归档后应写入独立防篡改存储或外部锚定。数据库超级管理员仍可修改数据，因此单库散列链不是最终信任根。
- 签名声明编码 `RHN-EVIDENCE-JSON-1` 和版本号进入证据。字段或规范变更必须增加版本并保留旧版验证器。
- 证据留存跟随其业务对象及法规要求；密评原始记录的留存按《商用密码应用安全性评估管理办法》执行，不能用删除业务数据的方式破坏仍需验证的证据。
- 密码失败、验证失败、证书异常和服务不可用必须进入安全监控；不得为了可用性绕过保护或静默降级到开发实现。

## 仍需完成

该决策完成的是可替换架构、证据模型、失败关闭策略和首个业务接入，不等于系统已经通过密评。真实数据进入前还必须：确定密评等级和边界、完成密码应用方案及评估、选定密码产品/服务、CA 与个人证书体系、可信时间戳、密钥全生命周期、数据库最小权限和防篡改归档，并与测评机构确认关键数据目录。

《商用密码应用安全性评估管理办法》要求重要网络与信息系统的密码保障系统同步规划、同步建设、同步运行，并在投入运行前及运行后定期开展评估；卫生健康行业制度也要求密码应用同步规划、建设和运行。因此这些工作不能推迟到业务系统开发完成后补做。

## 后果

新增业务只需定义受保护原文和选择平台策略，即可复用统一的摘要、签名声明、证据存储、证据链、验证和合规门禁。代价是关键数据写操作依赖密码服务可用性，且项目必须长期维护版本化验证器和外部密码产品适配器；这是不可否认能力成立所必需的约束。
