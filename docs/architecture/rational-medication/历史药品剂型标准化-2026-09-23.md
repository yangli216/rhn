# 历史药品剂型标准化（2026-09-23）

## 原因

历史药品主档生成器使用宽泛剂型映射，而标准参考目录保存精细药学剂型。数据库重建重新执行历史主档数据后，之前在运行库修正过的剂型再次回退。

典型映射包括：注射用无菌粉末被保存为 `INJECTION`，软胶囊被保存为 `CAPSULE`，丸剂被保存为 `OTHER`，凝胶被保存为 `CREAM`，口服、吸入和外用溶液被合并为 `ORAL_LIQUID`。旧生成器无法识别剂型时还会默认保存为 `TABLET`。

标准关联校验要求类型、剂型、规格和已定义的制剂单位一致。因此名称和规格正确的历史记录仍会进入“身份字段需修正”，同一标准条目下的所有规格都会显示为候选，但没有候选可以直接选择。

## 本轮处理

处理前共有 766 条身份字段不一致记录。逐条读取关联候选，仅选择“恰好一个候选，且差异仅为剂型”的记录：

| 项目 | 数量 |
| --- | ---: |
| 安全修正并建立关联 | 545 |
| 清除与目标剂型冲突的默认途径及频次 | 12 |
| 仍需核对身份字段 | 221 |
| 批处理失败 | 0 |

修正后的有效标准关联由 1370 条增加至 1915 条，未关联由 839 条降至 294 条。剩余记录包括身份字段不一致 221 条、多候选 17 条、当前目录无候选 56 条。

截图中的代表记录已修正为：

| --- | --- | --- |
| 丁卡因注射用无菌粉末 | `INJECTION` | `POWDER_FOR_INJECTION` |
| 丁卡因凝胶剂 | `CREAM` | `GEL` |

## 防止重建回退

`scripts/build-essential-drugs-artifacts.mjs` 现在优先按标准目录中的 `legacyCode + 剂型名称`复用精细剂型编码。无法映射的剂型改为 `OTHER` 且不填制剂单位，不再默认成片剂。默认途径判断同步支持粉针、注射用浓溶液、吸入制剂、眼用制剂、阴道制剂、凝胶和贴膏等精细剂型。

`scripts/reconcile-medication-dose-forms.mjs` 提供独立的只读核对和应用模式。`scripts/restore-medication-standard-baseline.mjs` 在数据库重建恢复时也会识别受控清单中的唯一纯剂型差异，修正后重新校验再建立关联。

221 条剩余身份差异没有自动处理，因为它们还涉及规格、单位、复方结构或来源原文问题。不能通过批量改剂型消除这些差异。

后续剩余缺口治理统一了规格符号和特殊剂型限定，安全新增 43 条关联。仍无法证明唯一身份且没有产品依赖的 247 条历史记录已退役；4 条有产品依赖的机构补充样例继续启用并进入标准待建队列。最终启用目录为 1958 条已关联、4 条待建，身份差异为 0。详见[标准药品剩余缺口治理](标准药品剩余缺口治理-2026-09-23.md)。
