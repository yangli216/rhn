# RHN 合理用药现代化建设落地规划与实施分案

> **定位**：本规划基于项目架构基线（[ADR-007](../架构决策-007-合理用药临床语义与AI规则治理.md)）、本地循证医学知识库（`medical-llm-wiki`）与行业主流审方底座实践，将合理用药与临床决策支持（CDSS）的建设拆分为可落地、可验证、颗粒度适中的三个工程实施分案。

## 二、 分案一（Phase 1）：底座收敛与循证母体接入

### 1. 任务拆解与交付物

#### Task 1.1：重构在行规则目录中的“新建规则”入口与规范化草稿向导
- **现状痛点**：在行目录右上角的“新建规则草稿”弹窗为简单表单，仅支持 4 个写死模板、手写依据文本、单选 1~10 个药品，易误导用户直接上线非标规则。
- **改造内容**：
  - 调整在行目录页面主操作区：明确区分“在行生产监控”与“规则资产起草”，强力引导优先通过【AI 规则需求分析（`MedicationRuleIntake`）】和【知识草稿（`MedicationKnowledgeDrafts`）】进行标准起草；
  - 重构快速起草弹窗：
    - 引入结构化依据（来源类型：说明书/指南/法规/制度文件，文号与章节定位）；
    - 支持绑定安全分类（`MedicationSafetyCategory`），不再强迫用户单选具体药品；
    - 增加严格的准入风险提示（草稿需经用例验证、药学审核与旁路观察后生效）。
- **验收标准 (DoD)**：
  - 页面无歧义文案，引导清晰；
  - 支持按分类建立草稿；
  - 前端测试用例 100% 覆盖。

#### Task 1.2：打通 `medical-llm-wiki` 循证规则资产与安全分类
- **现状痛点**：`medical-llm-wiki` 沉淀了 35 条国家标准处方安全拦截红线（`clinical_safety_rules.json`），但 RHN 尚未将其完全对齐为标准分类与规则候选。
- **改造内容**：
  - 梳理 Wiki 中的核心规则（双重 RAS 轴阻断、ARNI 洗脱期、普利/沙坦妊娠禁用、全身用 NSAID 重复等）；
  - 在 `MedicationSafetyCategory` 中补充系统级安全分类定义（如 `RAS_ACEI`、`RAS_ARB`、`RAS_ARNI`、`SYSTEMIC_NSAID` 等）；
  - 建立标准映射与种子数据。
- **验收标准 (DoD)**：
  - 系统内置常见安全分类，药品可批量加入分类；
  - 提供规范的分类查询与会员检索接口。

## 三、 分案二（Phase 2）：参数化规则工坊与门禁闭环

### 1. 任务拆解与交付物

#### Task 2.1：后端抽象三大参数化规则模板引擎
- **模板 A（双分类冲突/DDI）**：`Category X + Category Y -> WARN/BLOCK`
- **模板 B（分类 + 人群事实）**：`Category X + (Age < N || Pregnancy || eGFR < M) -> WARN/BLOCK`
- **模板 C（分类 + 聚合数量）**：`Category X 同方出现 >= N 种 -> WARN/BLOCK`
- **架构设计**：基于 Java 强类型 Predicate 与内存倒排索引，单次处方判定小于 1ms，杜绝解释器 GC 停顿与空指针风险。

#### Task 2.2：构建向导式 Rule Studio（前端 5 步向导）
- **步骤 1**：选择模板类型与绑定循证证据源（必须包含 Wiki 词条或红头批号）；
- **步骤 2**：从安全分类树中选择目标分类（X、Y）；
- **步骤 3**：设置阈值、动作（WARN / REQUIRE_OVERRIDE / BLOCK）与参数化提示文案；
- **步骤 4**：强制正反例测试（Positive / Negative TestCase）并通过；
- **步骤 5**：提交版本化审批（生成 `RuleVersion`）。

#### Task 2.3：历史处方沙箱预演（Backtesting）与旁路观察（SHADOW）常态化
- **回放沙箱**：部署前允许抽取最近 500 张真实脱敏处方进行预跑，输出预估命中率；
- **强制旁路**：新规则审核通过后强制以 `SHADOW` 模式运行至少 7 天，经研判后方可正式启用（`ENFORCED`）。

## 四、 分案三（Phase 3）：全域智能化与复杂引擎

### 1. 任务拆解与交付物

#### Task 3.1：轻量动态表达式引擎集成
- 引入 Aviator 表达式引擎，支持复杂复合逻辑（如根据公式计算 eGFR、结合检验指标与用药天数）；
- 提供受限沙箱环境与语法校验器，防止恶意脚本或耗时死循环。

#### Task 3.2：门诊拦截端穿透 Wiki 循证图谱
- 医生端拦截弹窗提供“展开循证依据”抽屉，直接拉取 `medical-llm-wiki` 对应的指南原文与双向链接图谱；
- 药师审方工作站展示完整的规则触发链路与证据指纹。

#### Task 3.3：审方反馈与告警疲劳动态调优
- 联动 `PharmacyReview` 药师干预数据与医生覆盖理由；
- 统计高频无效告警规则，自动向药事管理团队推送降级或优化建议 Candidate。
