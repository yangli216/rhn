# QMED-0 与远程规则工作台合并记录

合并来源：本地 `defb769` 与远程 `c0781b2`。本文说明两条并行开发历史的兼容方式，不改变既定的业务链路优先策略。

## 功能兼容

- 处方输入统一输出 `qmed-prescription-v2`，保留 QMED-0 已保存的成分、剂量及频次语义，同时携带远程新增的患者年龄、性别、过敏记录和皮试免试证据。引擎继续接受 v1 历史输入。
- 保留远程规则工作台、候选规则试跑和七类基础规则；处方评价仍为 SHADOW，评价结果不自动提交、撤销或阻断业务医嘱。
- 药品编辑同时保留既有编码修复和标准目录采纳时的预填编码、属性。
- 物理表目录以远程基线为基础增加临床语义版本表，消除自动合并造成的五张 QMED-1 表重复记录。

## 两套目录产物

标准参考目录继续由 `docs/essential-drugs/build_essential_drugs.py` 生成，保留 794 条目录条目、2,078 条规格和可追溯的未知字段。

远程已发布的 V1.47 药品预置迁移保持原文，包含另一套按规格拆分的 2,197 条药品和其既有临床默认值；新建库或尚未执行 V1.47 的库在下次正常迁移时会载入这些记录。本次没有将其自动视为 QMED-0 标准目录，也没有为其补造已核验的成分语义。两套条目数量与编码不能直接等同，后续通过实际调试整理数据。

旧生成器输入与导入 CSV 保存在 `docs/essential-drugs/legacy/`。`scripts/build-essential-drugs-artifacts.mjs` 使用该归档输入，输出到忽略的 `output/essential-drugs-legacy/`，不覆盖已发布的 V1.47。标准目录的重建不覆盖这批历史预置产物。

## 数据库迁移冲突

| 版本 | 合并后的职责 |
| --- | --- |
| 1.43 | 保留远程物理目录注释迁移 |
| 1.45 | 保留远程规则工作台迁移 |
| 1.49 | 本地标准目录剂型，以字典编码判断是否已存在 |
| 1.50 | 本地临床语义版本表，已有表与索引不重复创建 |
| 1.51 | 补齐物理目录注释和可能缺失的规则工作台表、索引 |

本地旧 1.43、1.45 原文移至不在 Flyway 扫描路径内的 `db/legacy-qmed0/`，用于识别并重现历史，不改写脚本内容。已运行本地 QMED-0 的 Oracle 库沿用 `oracle-local` 原有历史兼容配置，保留原 Flyway 历史；1.49–1.51 补齐双方结构，不执行 repair、不删除版本记录或业务表。远程历史和空库也收敛到相同结构。

严格校验迁移历史的其他数据库不能直接套用 Oracle 开发配置；继续遵循数据库基线文档的空 Schema 初始化约定。本次自动化升级测试仅连接随机 H2，未操作人工验证 Oracle 库。

## 验证范围

覆盖空库初始化、两种并行历史的升级与数据保留、物理表目录一致性、处方快照组合、规则引擎与工作台、门诊收费发药链路、住院医嘱及频次版本，以及相关前端测试和构建。人工验证服务保留当前运行实例；新版本 Oracle 迁移尚未在这两套服务上执行。

验证结果：89 项后端测试、46 项前端测试、18 项目录回归通过，前后端构建通过。标准目录生成一致性检查通过；历史生成器重现的 PostgreSQL/Oracle V1.47 与远程发布脚本逐字节一致。两套人工验证服务的后端健康状态均为 UP，前端均返回 HTTP 200。
