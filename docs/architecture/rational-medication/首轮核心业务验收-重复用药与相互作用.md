# 首轮核心业务验收：重复用药与相互作用

2026-09-21。本轮验收只检查知识是否能形成可运行的规则，以及开方和药师处置是否衔接。版本管理、日志、目录迁移等不作为本轮新增验收条件。

入口：合理用药规则工作台 → **规则知识草稿 → 重复用药与相互作用验收样例**。

两个样例为人工编写，原始依据已经核对，采用当前标准参考目录身份。它们不是 AI 生成结果，也不是已批准的临床规则。页面读取时运行 18 个合成场景，显示人工预期和实际结果；读取不会保存知识、创建患者或发布规则。

## 样例一：同标准条目重复开立

依据：[《处方管理办法》第三十五条第五项](https://www.nhc.gov.cn/wjw/c100221/202201/6a4ee53e4a3a407fbd9f520e1e2662c5.shtml)要求审核是否有重复给药现象。

验收策略：同一处方、同一标准条目的不同有效医嘱达到两条时提醒核对；所有年龄和途径参与筛查。**两条、同标准条目和提醒动作是验收方案设计，不是法规给出的判定阈值。** 命中不能直接认定不合理用药，需核对是否有意分次或分组开立。

| 场景 | 预期 |
| --- | --- |
| 辛伐他汀 10mg 与 20mg 两条有效医嘱 | 命中同条目重复开立提醒 |
| 两条医嘱顺序反转 | 结果不变 |
| 只有一条，或同一医嘱重复传入 | 未命中 |
| 第二条已撤销 | 未命中 |
| 辛伐他汀与克拉霉素两个不同条目 | 本条重复规则未命中，不表示不存在其他风险 |
| 有效医嘱缺少标准身份 | 无法评价，不能当作通过 |

不覆盖复方成分重复、同成分不同标准条目、跨处方重复以及执行时间重叠判断。

## 样例二：克拉霉素片与辛伐他汀片配对核对

依据：[DailyMed 的 CLARITHROMYCIN tablet 说明书，4.5 与 7 节](https://dailymed.nlm.nih.gov/dailymed/drugInfo.cfm?setid=98580dee-d2f4-4f62-a2d4-7434bab2421e)，页面更新日期为 2023-12-05。该说明书列明克拉霉素与辛伐他汀的合用禁忌。英文名称与中文标准条目的对应、国内具体产品的适用性仍需药师核对。

为便于首轮验收，样例限定年龄≥18岁、口服克拉霉素片 0.25g（25万单位）与口服辛伐他汀片 10mg、同一处方。**这些是样例覆盖范围，不是说明书的全部风险范围。** 其他规格未命中本例不代表安全。

当前程序只能发现同处方配对，不能确认实际用药时间重叠。因此本例的建议动作为提醒核对，提示应联系医师处理；不能把提醒确认解释为允许实际合用，也不能假称已经实现完整的合用禁忌阻断。

| 场景 | 预期 |
| --- | --- |
| 成人、两组目标规格各一条、均为口服 | 命中配对提醒 |
| 顺序反转 | 结果不变 |
| 仅一组、同一医嘱重复传入、另一条已撤销 | 未命中 |
| 改为辛伐他汀 20mg | 超出本次明确规格范围，未命中本例 |
| 年龄 18 岁 / 17 岁 | 命中 / 不适用 |
| 年龄、标准身份或受限途径缺失 | 无法评价 |

## 实际操作

1. 打开验收样例，核对原文、范围设计和结果；可下载依据摘录与方案。文件指纹对应下载的文件，不冒充官方全文指纹。
2. 点击“填入未保存知识草稿”，逐项核对来源、标准范围和适用条件，填写保存原因后保存。此时仍不生效。
3. 在已保存的知识中点击“生成规则候选 → 生成并纳入规则目录”。进入“在行规则目录”，选择对应规则及候选版本，点击“人工验证样例”，新建样例后点击“载入验收样例”。核对与候选的范围一致，保存并运行；编辑样例或知识后重新验证。
4. 通过既有审核、旁路和正式启用操作验收执行行为。真实机构上线仍需负责人确认具体规则及处置策略；本次开发没有代为启用规则。
5. 开方端核对涉及药品、提示和依据。返回修改后重新检查；正式策略要求理由时逐张填写；正式阻断不能通过“已知晓”绕过。
6. 药师在现有审方入口核对处方提交时的规则提示、医生理由，记录当前药品任务的干预或审方结论。整张处方配对提示不等于整张处方已完成药师审核。
7. 在已保存的药师处理结果旁点击“转为 AI 改进需求”。选择具体提示，或选择“未关联提示”提出漏报/新增知识需求；编辑并确认待发送文字，执行 AI 分析和澄清。关联知识规则时进入该知识的最新草稿；内置规则或未关联提示时建立新知识。保存草稿后复用现有验证、审核与启用流程。此入口需要药房业务与药品知识管理权限；药师说明、处方和患者资料不会自动发送给模型。

## 已批准旁路的知识规则如何正式生效

在“在行规则目录”选中知识规则及其候选版本，右侧提供以下入口：

| 入口 | 完成什么 | 确认结果 |
| --- | --- | --- |
| 人工验证样例 | 保存并运行与本候选对应的验证场景 | 本版本人工样例全部通过 |
| 审核与提交 | 提交知识候选，由不同于编写/提交人的审核人核对来源与处置策略 | 审核通过，明确命中及无法评价时的动作 |
| 旁路部署与观察 | “启用当前科室旁路”，积累观察后逐项“查看与研判” | 旁路已启用，待上线材料中的缺口已处理 |
| 正式启用与回退 | 选择来源旁路，核对页面材料后点击“确认正式启用当前科室” | 当前科室正式生效，来源旁路暂停 |

“批准旁路”不会自动变为正式生效。操作按钮不可用时，查看同一窗口列出的材料缺口及当前身份可执行操作；需要保持相同的工作机构、科室。这里复用现有启用约束，没有增加新的审批步骤。

规则目录可按“全部状态”统一查看草稿、待审核、旁路、正式、暂停及历史规则。“内置规则验证沙箱”仅验证内置基线，不能用它判断新知识规则是否生效；新知识规则的验证入口为目录中的“人工验证样例”。实际处方审查结果会分别标为“旁路观察”或“正式审查”。

## AI 验收与尚未完成项

载入知识草稿后，可使用“AI 从原文提取知识”对比人工预期。验收重点是分清原始依据与验收策略、正确理解重复/配对关系、提出遗漏条件，并能让人工确认标准范围。不得因为结构样例通过就认定真实模型效果合格。

已验证：两份样例能够保存为知识、编译为候选，18 个预设场景通过现有运行引擎；开方处理入口、处方提交理由、药师读取与干预均有隔离测试覆盖。

真实模型已完成五组输入、25 项检查的首轮验证，并修复了配对关系与临床意义抽取不完整的问题，详见[真实 AI 验证结果](真实AI首轮验证-重复用药与相互作用.md)。结果不代表所有材料均能正确理解，标准身份和临床适用条件仍须人工核对。

尚未完成：两条完整业务流程的用户手工验收。药师业务反馈已接入 AI 改进需求与知识草稿；后续围绕实际验收发现的断点修复，不扩大外围治理。
