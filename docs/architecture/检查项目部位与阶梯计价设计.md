# 检查项目部位与阶梯计价设计

状态：已确认（2026-10-25），第 10 节全部按推荐执行，从 P1 开始实施。

## 1. 背景与结论

走查 AI 推荐医嘱时发现：AI 返回“头部CT”“腹部彩超”这类“检查方式 + 部位”，而诊疗服务目录里的检查是物价收费项，例如“B超常规检查（一个部位）”“CT平扫（≥三个部位）”“16层及以上多排螺旋CT扫描加收”。两者不是一对一：

| 医生开立 | 应收费 |
| --- | --- |
| 彩超 · 腹部 | B超常规检查（一个部位）×1 |
| 彩超 · 肝胆脾胰 | B超常规检查（≥二个部位）×1，或（一个部位）×1，按物价口径 |
| CT平扫 · 头颅 + 胸部 | CT平扫（二个部位）×1 + 16层加收 ×2 |

结论：

1. **开立项目和物价项分层**。开立项目按“检查方式”组织，部位挂在部位方式上。物价项只收费，不能单开。
2. **新增按部位数阶梯切换收费项目的计价模式** `TIERED_ITEM`，部位方式上增加“计费部位数”。
3. **一条检查申请可以生成多条收费明细**，每条对应一个物价项。现有附加项目和多部位加收项目才能真正落账。
4. **新建标准部位词典**（概念 + 别名 + 层级），AI 和医生开单共用。
5. **AI 输出结构化的检查意图**（方式、增强、部位），匹配按“方式 → 开立项目 → 部位方式”分两步，收费完全由计价规则推导。

现状缺口：

- **G1 开立项目即物价项**：主收费行永远是被开立项目本身，开立项目只能等于物价项。
- **G2 无法表达档位替换**：“一个部位”和“≥二个部位”是互相替代的两个物价项，不是“基础 + 加收”。
- **G3 收费方案没有落账**：`examinationChargePlan` 只被维护端的计费模拟器（`ExaminationChargeSimulator.tsx`）调用。开单只用 `baseQuantity`，计费只生成一条主项目收费。附加项目和 `BASE_PLUS_ITEM` 的加收项目目前**不会真正收费**。
- **G4 部位没有标准词典**：变体的 `ID_CONCEPT_BODY_SITE` 没有值域可选，AI 只能靠写死的词表。

G3 不论本方案是否实施都是问题，阶梯计价依赖它先解决。

## 3. 概念模型

```text
开立项目（可开立，不单独收费）        物价项（可收费，不可单开）
  CT平扫  ── 部位方式 ── 头颅 ──┐        CT平扫（一个部位）
          ├─ 胸部              │        CT平扫（二个部位）
          └─ 腹部              │        CT平扫（≥三个部位）
                               │        16层及以上多排螺旋CT扫描加收
  计价规则 ─────────────────────┘
    TIERED_ITEM：1→一个部位，2→二个部位，3+→≥三个部位
    附加：16层加收，ALWAYS，PER_SITE

部位方式 ── 标准部位概念（RHN_BODY_SITE）── 别名：头部 / 颅脑 / 脑
                                          层级：腹部 ⊃ 肝胆脾胰 ⊃ 肝、胆、脾、胰
```

- **开立项目**：`FG_ORDRBL=1`、`FG_CHGBL=0`，有检查配置和部位方式。医技执行、报告模板、执行科室都挂在开立项目上。
- **物价项**：`FG_ORDRBL=0`、`FG_CHGBL=1`，有价格和医保映射，只被计价规则引用。截图里现有的数据就是这一层，保留不动。
- **兼容**：没有部位规则的检查（例如心电图）仍然可以是“可开立 + 可收费”的单一项目，计价模式 `SINGLE`，主收费行就是自身。

## 5. 计价规则

### 5.1 计费部位数

```text
selected        = 规则校验后的部位方式（去重保序，现有 select 逻辑）
chargeableUnits = Σ selected.QTY_CHGBL_SITE_UNIT，同一部位概念重复出现时只计一次
effectiveUnits  = max(1, chargeableUnits)，再受 QTY_MAX_CHGBL_SITE 封顶
extraUnits      = max(0, effectiveUnits - QTY_INCLD_SITE)
```

部位数上限（`QTY_MAX_BODY_SITE`）按选择的部位方式个数校验，和计费部位数无关。

### 5.2 主收费行

| 模式 | 主收费行 | 加收行 |
| --- | --- | --- |
| `SINGLE` | 主收费物价项 ×1 | 无 |
| `PER_SITE` | 主收费物价项 × effectiveUnits | 无 |
| `BASE_PLUS_FIXED` | 主收费物价项 ×1 | 固定金额 × extraUnits（现状） |
| `BASE_PLUS_ITEM` | 主收费物价项 ×1 | 加收物价项 × `QTY_ADDL_SITE` × extraUnits（现状） |
| `TIERED_ITEM` | 命中档位的物价项 × `QTY_CHG` | 无（档位本身已含部位数） |

“主收费物价项” = `ID_CATALOG_ITEM_BASE_CHG`，为空时为开立项目自身。

### 5.3 附加项目

沿用现有逻辑，只把判断条件换成计费部位数：

- `MULTI_SITE` 触发条件由“选择的部位数 > 1”改为 `effectiveUnits > 1`；
- `PER_SITE` 数量 × effectiveUnits，`PER_EXTRA_SITE` 数量 × extraUnits。

例如“16层及以上加收”配置为 `ALWAYS + PER_SITE`；“CT平扫同时增强加收”挂在“CT平扫+增强”开立项目上，配置为 `ALWAYS + FIXED`。

### 5.4 示例

| 开立 | 配置 | 收费 |
| --- | --- | --- |
| 彩超 · 腹部 | TIERED：1→一个部位，2+→≥二个部位；腹部计 1 | B超常规检查（一个部位）×1 |
| 彩超 · 肝胆脾胰 | 肝胆脾胰计 2 | B超常规检查（≥二个部位）×1 |
| 彩超 · 腹部 + 甲状腺 | 各计 1 | B超常规检查（≥二个部位）×1 |
| CT平扫 · 头颅 + 胸部 | TIERED 三档；附加 16层加收 ALWAYS+PER_SITE | CT平扫（二个部位）×1 + 16层加收 ×2 |
| CT平扫 · 头颅 + 胸部 + 腹部 + 盆腔 | 封顶 `QTY_MAX_CHGBL_SITE=3` | CT平扫（≥三个部位）×1 + 16层加收 ×3 |

### 5.5 开单与落账

1. 医生站选部位时，前端用收费方案接口预览（复用现有 `examinationChargePlan`，扩展 `TIERED_ITEM`）。
2. 签发时服务端重新计算收费方案，作为医嘱事实快照写入申请。领域事件载荷由“单价 + 总额”改为 `chargeLines[]`，每行带物价项、数量、价格来源（priceId / revision / type）、行类型。
3. 计费投影按 `chargeLines[]` 生成 N 条 `ChargeItem`，行号与方案一致；整条医嘱撤销时逐行冲销。
4. 退费仍然按医嘱整体处理，不支持单独退其中一行；执行后的退费门禁不变。
5. 档位由规则推导，医生和收费员都不能手工改档位。

旧事件（只有单价）按一行处理，兼容已经发出的申请。

### 6.2 使用

- 维护端：部位方式选择部位概念时，只能从 `RHN_BODY_SITE` 中选；
- 医生站：部位选择器显示部位方式名称，搜索同时命中概念别名；
- AI：部位名称 → 概念（别名精确匹配）→ 开立项目下绑定该概念的部位方式；
- 以后的重复检查判断也可以基于概念层级（同一天“腹部”和“肝胆脾胰”有重叠），不在本期范围。

## 7. AI 结构化输出契约

### 7.1 模型输出

`treatmentRecommendations` 中 `type=EXAMINATION` 的条目新增 `examination` 对象，`name` 保留作展示和兜底：

```json
{
  "type": "EXAMINATION",
  "name": "腹部彩超",
  "rationale": "右上腹痛伴墨菲征阳性，评估胆囊结石",
  "purpose": "排查胆囊结石与胆囊炎",
  "examination": {
    "modality": "US",
    "technique": "COLOR_DOPPLER",
    "contrastPhase": null,
    "bodySites": ["肝胆脾胰"],
    "laterality": null
  }
}
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `modality` | `US / CT / MR / DR / MG / ECG / ENDOSCOPY / FUNCTION / OTHER` | 必填，对应检查方式 |
| `technique` | 超声：`B_MODE / COLOR_DOPPLER`；其余可空 | 彩超与 B 超的区分 |
| `contrastPhase` | `PLAIN / ENHANCED / PLAIN_ENHANCED`，非 CT/MR 为空 | 平扫与增强 |
| `bodySites` | 1–6 个中文部位名称 | 使用常用名称，不写体位 |
| `laterality` | `LEFT / RIGHT / BILATERAL`，可空 | |

提示词改动（[OpenAiCompatibleClinicalAiModelGateway.java](../../backend/rhn-intelligence/src/main/java/com/rhn/ai/infrastructure/OpenAiCompatibleClinicalAiModelGateway.java) 的 treatmentRecommendations 段）：

- EXAMINATION 必须输出 `examination`；部位写临床部位，不写物价档位（不要写“一个部位”“≥二个部位”）；
- 同一检查方式、同一增强方式的多个部位，合并成一条，`bodySites` 列多个；
- 心电图、肺功能等无部位检查，`bodySites` 为空数组。

`TreatmentSearchIntent`（重新匹配接口）同步增加可选的 `examination` 字段。没有该字段的旧请求，由服务端解析器从 `name` 推导（见 7.3）。

### 7.2 返回给前端

`TreatmentRecommendation` 新增：

```json
{
  "bodySites": [{"code": "US-HBSP", "name": "肝胆脾胰", "variantId": 123}],
  "siteResolution": "MATCHED",
  "chargePreview": {"lines": [{"itemName": "B超常规检查（≥二个部位）", "quantity": 1, "amount": 80.00}]}
}
```

`siteResolution`：

- `MATCHED`：所有部位都对应到唯一的部位方式；
- `PARTIAL`：部分部位对应上，其余需要医生选择；
- `UNRESOLVED`：开立项目对上了，部位都没对上，前端打开部位选择器；
- `NOT_REQUIRED`：项目不需要部位。

`TreatmentMatch.status` 不变：`MATCHED / AMBIGUOUS / NO_ORDERABLE_SERVICE / CATALOG_ERROR`。开立项目唯一但部位不是 `MATCHED` 时，状态为 `AMBIGUOUS`，原因写“请核对检查部位”。

## 8. 匹配流程

```text
1. 取检查意图
   有 examination → 直接使用
   无 → 解析 name：方式关键词（彩超/B超/CT/MRI/磁共振/DR/X线…）+ 增强关键词
        + 部位词典别名最长匹配；替代写死的 ANATOMICAL_SITES
2. 定位开立项目
   候选 = 可开立的 EXAMINATION 项目
          ∩ 检查方式 = modality（technique 有值时再按超声方式过滤）
          ∩ 增强方式 = contrastPhase（CT/MR）
   唯一 → 进入第 3 步
   多个 → AMBIGUOUS，候选列表交医生选
   零个 → 回退到现有名称检索 + 别名（兼容未改造的目录），结果标记为需核对
3. 解析部位
   对每个 bodySite：
     别名精确匹配 → 部位概念 C
     在该开立项目的 ACTIVE 部位方式里找绑定 C 的 → 命中
     未命中 → 沿 PART_OF 查找上下级概念：
              只找到 1 个上下级部位方式 → 作为候选预填，标记需核对（不自动认定等价）
              多个或零个 → 留空
   校验必选、上限；超过上限时只预填前 N 个，并提示
4. 预览收费
   部位全部确定时，调用收费方案得出 chargePreview；收费从不取自 AI 输出
5. 合并建议
   同一次推荐中，多条意图落到同一个开立项目（例如“头颅CT”和“胸部CT”各一条）时，
   合并成一条、带多个部位，并在 reason 说明“已合并为一次检查，按多部位计价”
```

决策观察日志补充 `modality / contrastPhase / bodySites / siteResolution / chargeItemIds`，仍然不记录提示词和患者身份。

别名 JSON（`clinical-catalog-aliases.json`）中引用物价项名称的 EXAMINATION 条目（例如“胸部CT”的 reviewNames 里有“CT平扫（一个部位）”）在开立项目上线后删除，由第 2 步替代。

## 10. 确认结果

用户于 2026-10-25 确认以下五项全部按推荐执行：计费部位数按部位方式配置；彩超与 B 超建成两个开立项目；左右侧由医院建部位方式；只在同一开立项目内合并部位；所有检查都支持主收费物价项。

原问题与推荐保留如下：

1. **计费部位数口径**：“肝胆脾胰”“泌尿系”“双侧乳腺”在本地物价中各算几个部位？本设计做成按部位方式配置，需要一份默认值。
2. **彩超与 B 超**：物价目录里是否区分彩色多普勒和 B 超常规？区分的话，彩超和 B 超建成两个开立项目（推荐），而不是一个项目的两种方式。
3. **左右侧**：“双膝”算两个部位还是一个？推荐由医院建“左/右/双”部位方式，用计费部位数表达。
4. **跨开立项目合并**：只在同一开立项目内合并部位；CT平扫和CT增强不合并，各自按档位收费。是否符合本院物价执行？
5. **主收费物价项**：`PER_SITE / BASE_PLUS_*` 模式的开立项目是否也需要把主收费改成指向物价项（4.1 的 `ID_CATALOG_ITEM_BASE_CHG`）？推荐支持，这样所有检查都可以开立与收费分层。

## 11. 分期与验证

| 期 | 内容 | 验证范围 |
| --- | --- | --- |
| P1 收费落账 | 收费方案进入医嘱快照；事件 `chargeLines[]`；一单多条 `ChargeItem`（修复 G3） | `master-data,diagnostics,billing`；迁移 + 资金，完整 CI |
| P2 阶梯计价与部位词典 | `TIERED_ITEM`、档位表、计费部位数、主收费物价项、部位编码体系与层级、维护端界面 | `master-data,diagnostics,billing`；Oracle 对等迁移 |
| P3 数据分层 | 开立项目样例数据、模板引用迁移、物价项改不可单开 | `master-data,round1` |
| P4 AI | 结构化契约、提示词、解析器、两步匹配、合并建议、前端部位预填与收费预览 | `ai-matching,outpatient-draft`；OpenAPI 与生成类型 |

P1 是 P2 的前置条件；P4 可以在 P2 完成后和 P3 并行。

### P1 实施记录（2026-10-26）

- 迁移 `V1_129_67__examination_order_charge_lines`：新表 `RHN_EX_SVC_REQ_CHG` 快照申请收费明细；`RHN_BIL_CHARGE_ITEM` 增加 `SN_CHG_LINE`、`SD_CHG_ROLE`，来源唯一键 `UK_BIL_CHARGE_ITE_CHARGE_SOURC` 换成含行号的 `UK_BIL_CHARGE_ITEM_SRC_LINE`。直接退费冲销沿用原收费行号。用户确认历史业务数据可清空，未做回填。
- 开立：有检查配置的项目按 `ExaminationSiteDirectory.chargePlan` 定价，只有方案多于一行时才写快照；加收、附加项目按执行机构、价格类型和业务日期取价，未开放收费或无价格时拒绝开立（`EXAM_CHARGE_ITEM_UNAVAILABLE`）。不单独收费的附加项目不生成收费行。多部位固定加收没有价格版本，单价取配置金额除以数量。
- 事件：`SERVICE_REQUEST_*` 载荷增加 `chargeLines`，顶层金额为各行合计；没有 `chargeLines` 的医嘱仍按顶层价格单行处理。
- 计费：逐行生成收费事项与借方流水，撤销逐行冲销，取消签署整单删除；结算锁按全部行判断。结算（`INVOICE_ORDER_LINES_INCOMPLETE`）和直接退费（`REFUND_ORDER_LINES_INCOMPLETE`）要求同一检查申请的收费行一并勾选，前端收费与退费勾选同步联动。
- P1 限制：主收费物价项（4.1 的 `ID_CATALOG_ITEM_BASE_CHG`）在 P2 实现，P1 中方案主行必须是开立项目本身。每期都要更新 OpenAPI、`generated.ts`，并在 H2 和 Oracle 上验证增量迁移。

### P2 实施记录（2026-10-26）

- 迁移 `V1_129_68__examination_tiered_pricing_and_body_sites`（`migration/` 与 `oracle/` 同版本）：
  - `RHN_BD_EXAM_SVC` 增加 `ID_CATALOG_ITEM_BASE_CHG`，计价模式检查约束改名为 `CK_BD_EXAM_SVC_SITE_PRICING` 并加入 `TIERED_ITEM`，另加约束保证阶梯模式不配主收费物价项；
  - 新表 `RHN_BD_EXAM_PRICE_TIER`（外键到检查配置）；
  - `RHN_BD_SVC_VAR`、`RHN_EX_SVC_REQ_SITE` 增加 `QTY_CHGBL_SITE_UNIT`；
  - 新表 `RHN_BD_CONCEPT_REL`；
  - 平台级编码体系 `RHN.BD.CS.BODY_SITE`（即 4.4 的 `RHN_BODY_SITE`，编码沿用现有 `RHN.域.CS.名称` 规范），首批 62 个部位、别名与 PART_OF 层级。
- 主数据：
  - 档位接口 `PUT .../examination-price-tiers` 整组替换，与检查配置共用修订号；校验从 1 连续、只有最后一档可无上限、物价项启用且可收费。阶梯模式要求档位非空且覆盖最大计费部位数。物价项是否有价格在开立时按执行机构校验。
  - 部位方式只能引用部位词典中的有效概念。部位词典接口：`GET /api/platform/terminology/body-sites`、`PUT .../body-sites/{id}/parents`（防环）。
  - 收费方案返回 `chargeableSiteCount`。
- 与 5.1 的差异：计费部位数不按标准部位概念去重。左右侧由不同部位方式表达且映射同一概念，按概念去重会把“左膝 + 右膝”算成 1 个部位。
- 开立：主收费行是阶梯档位或主收费物价项时，开立项目本身不需要可收费，全部收费行按方案取价，只有一行时也写快照。申请顶层价格快照取主收费行。未签署申请改部位换档时，主收费行重新取价。
- 计费事件：首行可以是 `BASE_SERVICE`（可为其他物价项）或 `TIER`。价格来源须与顶层一致，首行就是开立项目时再校验项目、单位与数量。
- 维护端：
  - 计价模式新增“按部位数阶梯计价”，可设主收费物价项，并有档位维护对话框；
  - 部位方式可选标准部位、填写计费部位数，列表显示这两列。
- 未做：
  - 对比剂期相 `SD_CNTRST_PHASE` 和字典 `EXAM_CONTRAST_PHASE` 只服务于 AI 区分平扫/增强，移到 P4；
  - 部位层级维护目前只有接口，没有维护界面；别名沿用术语管理。

### P4 实施记录（2026-10-26）

- 迁移 `V1_129_69__examination_technique_and_contrast_phase`：`RHN_BD_EXAM_SVC` 增加 `SD_EXAM_TECHNIQ`（`B_MODE / COLOR_DOPPLER`，只用于超声）和 `SD_CNTRST_PHASE`（`PLAIN / ENHANCED / PLAIN_ENHANCED`，只用于 CT/MRI）。两列用检查约束限定取值，不另建字典。维护端在检查配置里选择。
- 契约：
  - `TreatmentRecommendation` 增加 `examination`（结构化意图，只出现在意图上）和 `examinationSites`（服务端解析的部位与收费预览，只出现在院内候选上）。7.2 里的 `bodySites / siteResolution / chargePreview` 归到 `examinationSites` 一个对象里：`resolution`、`bodySites[{code,name,variantId,requestedName,requiresReview}]`（记录名 `ExaminationSitePrefill`）、`unresolvedSites`、`note`、`chargePreview{lines,totalAmount}`。
  - `TreatmentSearchIntent` 增加可选的 `examination`。
  - 模型输出经 `TreatmentUsageIntents` 清洗：非检查条目、检查方式不认识的条目丢弃 `examination`；`examinationSites` 一律移除。
- 提示词：RECORD_DIAGNOSIS 与 TREATMENT_ONLY 阶段要求 EXAMINATION 输出 `examination`。部位写临床部位，不写收费档位；同一方式的多个部位合并成一条。
- 匹配（新类 `ExaminationIntentMatcher`，接在 `ClinicalTreatmentCatalogResolver` 上）：
  - 意图：没有 `examination` 时从名称推导，按检查方式、超声方式、增强方式关键词，加部位词典别名的最长匹配。名称里认不出检查方式时，沿用原来的名称检索。
  - 定位开立项目：检查方式对应检查类型（US→ULTRASOUND、CT→CT、MR→MRI、DR→RADIOGRAPHY），再取本机构可开立的项目。超声方式、增强方式优先完全一致；没有一致的，只保留没设置该属性的项目。唯一则进入部位解析；多个则待核对；没有则回退名称检索。
  - 部位解析：先找绑定同一标准部位的部位方式（多个时按侧别挑），再找名称相同、未映射标准部位的部位方式；都没有时，沿上下级部位找唯一的部位方式，作为待核对候选。超过部位上限只预填前 N 个。
  - 收费预览：部位全部确定时，按收费方案逐行取本机构销售价；任一行无价时合计为空。
  - 状态：开立项目唯一但部位不是 `MATCHED/NOT_REQUIRED` 时转为 `AMBIGUOUS`，原因为“请核对检查部位：…”。原名称检索的结果也补充部位解析。
  - 合并：同一次推荐里落到同一开立项目的多条意图合并，部位取并集，原因写“已合并为一次检查，按多部位计价”。
  - 日志 `clinical_ai_examination_match` 记录检查方式、超声方式、增强方式、部位、结果、候选、部位解析结果、收费物价项，不记录提示词和患者身份。
  - 写死的 `ANATOMICAL_SITES` 只在没有接入匹配器时兜底，正常情况由部位词典提供。
- 医生站：
  - AI 检查建议带入医嘱草稿时预填服务端解析的部位；
  - 建议行显示部位（待核对标记）、未对应部位和预计费用；
  - 目录核对重新匹配时带上原始的结构化意图。
  - 另外修正了 P2 遗留问题：医生站按部位计价的数量现在按部位方式的计费部位数预估，服务端开单数量不受影响。
- 未做：
  - 别名 JSON 中引用物价项名称的检查条目还没删，要等 P3 开立项目数据上线后再清理；
  - 决策模型复核（Jev）没有使用部位信息。
