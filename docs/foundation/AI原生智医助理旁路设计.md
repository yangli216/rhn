# AI 原生智医助理旁路设计

## 1. 目标与边界

本能力将独立桌面版智医助手中的有效交互沉淀到 HIS 门诊医生站，但不改变现有临床主流程。

- AI 只生成结构化建议、待核对病历草稿、缺项提醒、风险提示、诊断候选和既有诊疗方案推荐。
- AI 不直接保存或签署病历，不确认诊断，不开立或提交医嘱，不执行诊毕。
- 医生采纳后，内容仅进入当前页面的本地草稿；后续仍经过原医生站既有校验、保存、签署、审方和医嘱提交流程。
- AI 不依赖本地悬浮窗、设备标识、本地密钥或本机 HTTP 桥接，能力由 HIS 服务端统一控制、授权和审计。

## 2. 旁路架构

```text
门诊医生站当前草稿
        │  最小必要上下文 + 上下文指纹
        ▼
智医助理独立抽屉 ──> Clinical Assistant API ──> 能力模式 / 访问校验
        ▲                         │
        │                         ├─ LOCAL_ASSIST：保守规则辅助
        │                         ├─ MODEL：预留服务端模型适配器
        │                         └─ DISABLED：安全降级，不影响医生站
        │
        └── 结构化建议 + 风险依据 + 有效期
                    │
                    ├─ 医生明确采纳并写入 AI 审计事件
                    └─ 合并至本地草稿，继续走原临床写入链路
```

AI 模块不调用病历、诊断、处方、医嘱或诊毕的写服务。现有临床表与业务服务仍是唯一临床事实来源。

## 3. 首期能力

| 能力 | 首期行为 | 安全边界 |
| --- | --- | --- |
| 病历完整性 | 检查主诉、现病史、既往史、查体、计划等缺项 | 只提示，不自动补造阴性事实 |
| 病历草稿 | 根据已有主诉和真实生命体征生成保守补充文本 | 仅填空字段，进入本地草稿 |
| 风险提示 | 生命体征异常和已登记活动性过敏提示 | 不替代临床判断，不自动处置 |
| 诊断辅助 | 对当前草稿中的诊断编码做院内 ICD-10 精确校验 | 服务端及采纳前客户端双重校验 |
| 方案推荐 | 匹配当前医生可见的既有诊疗方案 | 不自由生成药品、剂量或用法 |
| 反馈与审计 | 记录生成、查看、采纳、忽略和反馈事件 | 不把 AI 事件伪装为临床操作 |

## 4. 上下文隔离与采纳门禁

建议生成时同时记录浏览器侧上下文指纹和服务端临床版本锚点。浏览器指纹负责即时阻止本页草稿变化后的误采纳；服务端锚点以 SHA-256 保存，并在采纳事务中重新读取比对，负责阻止其他标签页或并发操作导致的陈旧建议。覆盖范围包括：

- 就诊、患者、机构、科室和接诊医生；
- 就诊状态、病历状态与当前文档版本；
- 结构化病历上下文；
- 药品草稿、服务草稿；
- 过敏事实及加载状态；
- 当前是否正在保存、签署或提交医嘱。

服务端锚点至少包含就诊版本与状态、门诊病历文档标识/版本/状态，以及排序后的活动性真实过敏事实；否定性过敏声明不会被当作过敏风险。采纳事件还要求就诊仍为接诊中状态。

下列任一条件发生时，不允许采纳旧建议，必须重新分析：

- 切换患者或就诊；
- 病历、诊断、医嘱草稿或过敏上下文变化；
- 建议过期、已忽略、已完整采纳或服务端上下文不匹配；
- 病历正在保存、签署或医嘱正在提交；
- 采纳方案时过敏信息尚未成功加载。

方案采纳还必须由医生完成药品与过敏复核；命中过敏信息时必须填写覆盖理由。AI 审计成功后才允许合并到本地草稿。

## 5. 服务端模式

配置项：`rhn.ai.mode`

- `DISABLED`：生产默认值。AI 不可用，但医生站全部原有能力正常工作。
- `LOCAL_ASSIST`：开发、本地和测试环境启用。仅执行可解释的保守规则、术语校验和既有方案匹配。
- `MODEL`：外部模型适配预留值。未配置适配器时返回独立的不可用状态，不影响医生站。

后续接入模型时必须坚持服务端网关、最小必要数据、结构化输出 Schema、版本化提示词、超时与熔断、脱敏日志以及全过程审计，不向浏览器或桌面端下发模型密钥。

## 6. API

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| `GET` | `/api/ai/clinical-assistant/capabilities` | 查询模式、可用性和能力清单 |
| `POST` | `/api/ai/clinical-assistant/encounters/{id}/suggestions` | 为当前接诊生成建议 |
| `GET` | `/api/ai/clinical-assistant/encounters/{id}/suggestions` | 查询该就诊的建议历史 |
| `POST` | `/api/ai/clinical-assistant/suggestions/{id}/events` | 记录查看、采纳、忽略或反馈 |
| `GET` | `/api/ai/clinical-assistant/suggestions/{id}/events` | 查询建议事件轨迹 |

服务端在生成和记录事件时均要求门诊接诊权限，并校验租户、机构、科室、执业人员、当前接诊医生及患者归属。方案维护和使用时，方案内诊断还必须通过当前院内 `ACTIVE` ICD-10 术语目录校验。

## 7. 表结构

### `ai_suggestions`

保存建议本体、结构化内容、最小化证据、双重上下文哈希、服务提供方与模型版本、有效期和申请人。证据只记录来源、版本、哈希、实际存在的输入字段和“未调用临床写服务”等可审计元数据，不重复保存完整病历草稿。它只引用患者与就诊，不引用或修改临床诊断、处方和医嘱记录。

### `ai_suggestion_events`

以幂等命令记录生成、查看、采纳、忽略、反馈、过期和失败事件，保留状态迁移、操作人、采纳区域和上下文哈希。

两表均使用租户复合外键、状态约束、幂等唯一约束及外键左前缀索引，并提供 PostgreSQL/H2 与 Oracle 迁移。

正式启用模型模式前，应把 AI 建议和事件纳入医院病历数据分级与留存制度，明确访问审计、归档和清理周期；模型调用日志不得记录完整病历正文或密钥。

## 8. 验收基线

- AI 服务关闭、异常或超时时，医生仍可完整使用原医生站。
- 生成、查看或反馈建议不会写入任何临床核心表。
- 未明确采纳、上下文已变化或建议已过期时，不得写入本地草稿。
- 采纳诊断前必须通过当前院内术语目录校验。
- 采纳方案前必须完成过敏信息加载与医生安全确认。
- 最终保存、签署、医嘱提交和诊毕仍由原功能完成，并保留原有权限与校验。
- 所有 AI 建议和采纳行为可按租户、就诊、医生和时间回溯。
