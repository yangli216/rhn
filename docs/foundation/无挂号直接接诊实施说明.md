# 无挂号直接接诊

直接接诊不要求排班、号源或挂号窗口，内部保留挂号与就诊事实。默认关闭，在业务参数配置中启用后，门诊医生站显示“直接接诊”入口。

## 参数

| 参数 | 作用域 | 默认 | 行为 |
|---|---|---|---|
| `outpatient.direct-visit.enabled` | 机构、科室 | false | 允许没有有效挂号时自动挂号并接诊 |
| `outpatient.direct-visit.catalog-item-id` | 仅科室 | 空 | 自动新建就诊时记一次门诊服务费；留空或显式空值不产生服务费 |

服务参数可以在参数值编辑器中按名称、编码选择本机构有效的门诊诊查项目。清空选择保存为显式空值。服务费使用本机构当天有效销售价格，缺价或无效服务配置会阻止自动接诊，并回滚自动挂号，不静默漏收。普通挂号复用、继续接诊及重复读卡均不补收本参数费用；更改参数不追溯修改历史费用。

服务费进入本次就诊的门诊费用账户，来源为 `DIRECT_VISIT_SERVICE`，不创建挂号支付单、不自动收款。药品和其他项目使用同一就诊账户，可合并生成结算凭证。服务项目名称保留在费用明细，费用汇总归入诊疗费。

## 接诊规则

1. 确认姓名和至少另一项身份信息，后端按当前登录医生的机构、科室定位患者。
2. 使用现有 `outpatient.registration.validity.*` 参数判断挂号效期，仅考虑待接诊、接诊中和暂挂就诊。
3. 一条有效记录直接复用；多条记录返回供医生选择。其他医生已经接诊或指定其他医生的挂号不自动接管。已完成、已退号或过期记录不重开。
4. 无有效记录时重新校验启用参数，并检查是否存在尚未完成的挂号收费业务，防止绕过原挂号付款。
5. 自动挂号、可选服务费记账、身份核验和开始接诊在同一事务内完成。锁定患者并使用请求幂等号防止重复刷卡、并发操作和网络重试重复建诊或收费。

## 接口

- `GET /api/encounters/direct-visit/settings`：当前科室启用状态和可选服务 ID。
- `POST /api/encounters/direct-visit`：提交 `residentId`、`commandCode`、`factorResults`、可选 `encounterId` 和 `terminalCode`。
- 返回 `CREATED`、`REUSED` 或 `SELECT_REGISTRATION`；前两者携带就诊，后者携带候选记录。客户端在不确定网络结果时保留原幂等号重试。

机构、科室不由接诊请求体指定，来源为已授权的工作上下文；仅有门诊接诊权限且绑定医生身份的用户可以调用。

## 患者识别与验收

复用 `PatientIdentitySearch`，支持档案检索、唯一证件/卡号匹配以及读卡适配器返回患者。当前项目未配置实际读卡硬件接口，不伪造读卡结果；设备适配器需接入现有 `PatientIdentityMethod.identify` 契约。

默认不使用真实浏览器验证。自动测试使用 test 配置与随机 H2，覆盖免收、有效挂号复用、并发幂等、未支付挂号保护、跨医生保护、多记录选择、无效配置回滚及与其他费用合并结算。
