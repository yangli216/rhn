# 临床卡片与执行单打印管理设计

## 1. 建设结论

本轮建议在现有 `platform.printing` 受控打印底座上增建“临床卡片与执行单管理”，不新建一套前端拼 HTML 或各业务模块自行调用打印机的旁路。

产品边界分为六个独立但可组合的概念：

1. **卡片类型**：口服药卡、输液瓶签/静滴卡、输液巡视卡、注射卡、雾化/治疗卡、护理执行单等业务语义。
2. **数据提供器**：从医嘱、执行任务、处方、发药和患者主索引构造版本化打印快照，不复制临床事实。
3. **可视化模板**：定义单张逻辑卡片的内容、坐标、样式、分组和溢出策略。
4. **介质/纸张方案**：定义物理尺寸、方向、边距、标签间隙、排版行列和 DPI；同一卡片可映射多种介质。
5. **打印设备方案**：定义工作站默认打印机、能力、打印语言、校准值和失败回执。
6. **批次与组版规则**：定义选人、日期/班次/时点、医嘱分组、一人一页或一次执行一卡、A4/A5 多卡排版和补打范围。

最关键的建模决策是：**业务卡片与物理纸张分离**。“输液瓶签”是业务卡片，它可以输出到 70 mm x 50 mm 标签，也可以在 A4 不干胶纸上多联组版；不应把它建成两个互不相关的模板。

## 2. 调研结论与依据

### 2.1 业务场景

国内医院常见的临床打印物大致分为三类：

| 类别 | 主要用途 | 常见内容 | 主要用纸 |
|---|---|---|---|
| 贴附型标签 | 贴于输液瓶/软袋、口服药袋、标本容器 | 患者身份、医嘱组、药品/溶媒、剂量、途径、执行时点、条码 | 热敏或热转印不干胶，按实际耗材定宽高和间隙 |
| 携带型卡片 | 护士配药、核对、发药或床旁执行 | 口服药卡、注射卡、静滴卡、治疗卡 | 小幅热敏连续纸、A5，或 A4/A5 上多卡组版 |
| 列表/记录型执行单 | 按病区、日期、班次统筹给药，巡视和签名留痕 | 护理执行单、口服药执行单、输液巡视卡 | A4/A5 普通纸，纵向或横向 |

医院信息系统实践中，执行单通常先选患者，再选单据类型和待打数据；样式由医院按自身制度维护。这说明系统需要“可配置模板 + 受控发布”，不应将某家医院的纸张格式当成全国统一标准。

### 2.2 规范与安全约束

- 国家卫健委发布的 [WS/T 433—2023《静脉治疗护理技术操作标准》](https://www.nhc.gov.cn/wjw/pjl/202309/d09188781db944f8936728280cba4759.shtml) 适用于各级各类医疗机构；其 6.4.2.2 明确要求输液过程中定时巡视，观察输液反应和穿刺部位等情况。因此“输液巡视卡”不只是排版问题，必须保留巡视时间、状态、异常与执行人的可追溯位置。
- [《医疗质量安全核心制度要点》](https://www.nhc.gov.cn/yzygj/c100068/201804/42ab2552298047679cd6ec733f233862.shtml) 要求医疗机构落实查对制度等核心制度。打印物需要支持人、药、时间、途径、剂量和执行人的清晰核对，但不能把“已打印”当成“已执行”。
- 权威规范主要规定临床操作和质量安全要求，**没有统一规定口服药卡、静滴卡或巡视卡的固定纸张尺寸和视觉版式**。产品应提供受控的机构自定义能力，同时对患者识别、药品信息、条码、字号和签名区设定不可随意删除的安全约束。

### 2.3 打印方式

公开采购信息可验证医院对条码打印机、腕带打印机、输液条码纸、不干胶标签和碳带的长期需求，例如：

- [重庆大学附属涪陵医院输液条码打印机采购需求](http://www.fl.gov.cn/zwxx_206/gsgg/202601/t20260109_15304767.html)；
- [新疆医科大学第一附属医院条码打印机、腕带打印机采购](https://www.ccgp.gov.cn/cggg/dfgg/jzxtpgg/202407/t20240717_22657122.htm)；
- [重庆大学附属涪陵医院条码纸、输液条码纸、碳带和配套打印机需求](http://www.fl.gov.cn/zwxx_206/gsgg/202607/t20260706_15802573.html)。

因此打印通道建议分两层：

1. **服务端标准 PDF**：作为预览、审计和 A4/A5/普通驱动打印的统一产物。
2. **本地打印桥**：对需要静默打印、固定机路由、状态回执或 ZPL/TSPL/ESC-POS 等指令的热敏/热转印设备提供统一适配。

基层试点不应被本地打印桥阻塞：首期可以使用浏览器 PDF 打印配合 USB 打印机，同时保留 A5 和 58/80 mm 连续纸预设；需要批量无对话框打印的三级医院再启用本地打印桥。

## 3. 首批卡片范围

| 优先级 | 卡片 | 建议粒度 | 必备信息 | 默认介质 |
|---|---|---|---|---|
| P0 | 输液瓶签/静滴卡 | 一次给药事件的一个输液组 | 姓名、住院/就诊号、床号、组号、药品/溶媒、总量、途径、时间、滴速、过敏/皮试/高警示标识、条码 | 自定义标签；A4/A5 多联备用 |
| P0 | 口服药卡 | 一人一时点或一药袋 | 患者、床号、药名、规格、单次量、频次、给药时点、特殊说明、条码 | A5 多卡或热敏标签 |
| P0 | 输液巡视卡 | 一人一日/一次输液过程 | 开始/结束时间、滴速、穿刺部位、巡视时间格、反应/异常、执行与复核签名 | A5 纵向；A4 一人一页 |
| P1 | 注射卡 | 一次注射执行 | 患者、药品、剂量、注射途径、部位、时间、皮试状态、执行人 | A5 多卡/热敏 |
| P1 | 雾化/治疗卡 | 一次治疗执行 | 项目、频次、时长、时点、注意事项、执行人 | A5 多卡/热敏 |
| P1 | 护理执行单 | 一病区一班次/一日 | 床号、患者、执行项目、计划时间、完成/跳过标记、签名和备注 | A4/A5 横向优先 |

首期不建议纳入腕带、标本标签和血袋标签。这些对耗材、条码标准、专用设备及外部系统闭环要求更高，可复用本次底座，但应按独立项目验收。

## 4. 用纸和设备模型

### 4.1 介质预设

系统应提供预设，但尺寸必须允许机构按实际耗材克隆调整：

- `A4_PORTRAIT` / `A4_LANDSCAPE`：210 mm x 297 mm；
- `A5_PORTRAIT` / `A5_LANDSCAPE`：148 mm x 210 mm；
- `THERMAL_58_CONTINUOUS` / `THERMAL_80_CONTINUOUS`：固定宽度、按内容或业务限制定高；
- `LABEL_CUSTOM`：标签宽、高、横向/纵向间隙、黑标/间隙定位、DPI；
- `PRECUT_SHEET`：A4/A5 不干胶多联，配置页边距、行列、格子尺寸和间隙。

不在代码中把 50 mm x 30 mm、60 mm x 40 mm、70 mm x 50 mm 等常见标签规格写死为“行业标准”；它们只能作为快速创建预设。

### 4.2 输出策略

| 场景 | 首期 | 专业期 |
|---|---|---|
| A4/A5 激光打印 | 服务端生成 PDF，浏览器预览后打印 | 本地打印桥按科室/工作站自动路由 |
| 热敏连续纸 | 固定毫米宽度的 PDF，人工确认纸张比例 | 本地桥静默打印，可按驱动或 ESC/POS 输出 |
| 标签/瓶签 | 精确尺寸 PDF，单张或整页组版 | 按设备能力产生 ZPL/TSPL/驱动任务，回传队列状态 |

任何通道都必须禁用“适合页面”默认缩放，并在首次绑定设备时打印校准页。对条码标签，不仅做视觉预览，还要校验实际物理尺寸、静区、对比度和扫码成功率。

## 5. 模板设计器

### 5.1 交互布局

PC 端采用三栏工作台，避免多层弹窗：

- 左栏：组件库和数据字段树；
- 中栏：毫米标尺画布，支持缩放、网格吸附、对齐、层级和真实样例数据预览；
- 右栏：选中组件的尺寸、字体、边框、数据绑定、条件显示和溢出策略；
- 顶部工具栏：介质切换、撤销/重做、校验、预览、保存草稿、提交审核和发布。

### 5.2 受控组件

首期支持文本、数据字段、表格/重复行、条码/二维码、直线/矩形、图片/机构标识、条件区块、分页符、签名/时间格。

不允许上传或编辑任意 HTML/JavaScript。条件和格式化只允许白名单表达式，例如 `skinTestRequired == true`、日期格式化和枚举翻译，避免模板获得业务执行权限。

系统级安全组件包括患者核心身份、医嘱/执行标识、过敏与高警示区、打印版本和重打标记。设计者可以移动或调整尺寸，但发布校验不允许必填信息被删除、遮挡或缩小到不可读。

### 5.3 版本生命周期

`DRAFT -> IN_REVIEW -> PUBLISHED -> RETIRED`

- 草稿可频繁覆盖保存，发布版不可修改；
- 设计、审核、发布按权限分离，基层机构可通过角色兼任简化人员配置；
- 发布时锁定模板内容摘要、数据协议版本、介质方案和生效范围；
- 支持按租户、机构、科室和业务场景发布，解析顺序为“科室 > 机构 > 租户 > 平台”；
- 回滚不修改旧版，而是将旧版内容复制为一个新版本发布。

## 6. 批量打印工作台

建议布局为“左侧患者/床位范围 + 中间待打清单 + 右侧批次汇总和打印设置”，预览使用页内全屏工作区，不再连续打开弹窗。

### 6.1 筛选与组版

- 机构、病区/科室、业务日期、班次、计划时间段；
- 床位范围、患者、卡片类型、给药途径、频次；
- 新增、变更、未打、已打、需补打和已作废；
- 一患者一页、一执行事件一卡、一输液组一签、一班次/一日一巡视单；
- A4/A5/预切不干胶纸按行列组版，支持“从第 N 格开始”复用未用完的标签纸。

输液组必须使用医嘱的结构化组号和执行次序，不允许通过药名或文本换行猜测分组。

### 6.2 打印前确认

打印前一屏完成：待打对象数、逻辑卡片数、物理页/标签数、排除数、模板版本、介质方案和目标设备的对账。系统在以下情况阻断：

- 必填临床数据缺失；
- 文本溢出、条码不可扫或字号低于模板安全下限；
- 介质尺寸/DPI 与打印机能力不匹配；
- 卡片已打且未选择重打原因；
- 来源医嘱已变更、停止或作废，当前快照已过期。

### 6.3 失败和重打

- 幺等键使用“租户 + 卡片类型 + 来源版本 + 执行时点 + 分组键 + 介质方案”；
- 失败后只重试失败项，不重打已成功项；
- 物理设备有回执时，区分“已生成、已入队、已发送、设备确认、失败”；没有回执的浏览器打印只能记为“已发起”，不冒充出纸成功；
- 补打必须选原因，保留原卡片、原批次、操作人和时间链，并按机构策略显示“补打”或序号。

## 7. 数据和服务设计

### 7.1 复用现有底座

现有结构已具备可复用的核心：

- `RHN_META_PRINT_TMPL` 保存模板标识、文档类型、租户范围和当前版本；
- `RHN_META_PRINT_TMPL_VER` 保存不可变布局配置、内容摘要和发布人；
- `RHN_SYS_PRINT_OUTPUT` 已保存来源版本、数据快照、输出内容、SHA-256 和生成人；
- `RHN_SYS_PRINT_JOB` 已保存原打/重打关系、份数、操作人和关联号。

但当前渲染器固定为 A4，且只识别 `OUTPATIENT_NOTE` 和 `OUTPATIENT_PRESCRIPTION`；模板表中的布局配置还没有被通用解析。因此本次应替换硬编码分支，不是只再增加几个 `if (documentType)`。

### 7.2 建议新增的持久化概念

| 概念 | 职责 |
|---|---|
| `print_template_draft` | 可编辑草稿、修订号和校验结果，与不可变发布版分离 |
| `print_template_binding` | 卡片类型、场景、租户/机构/科室、介质方案、生效时间和优先级 |
| `print_media_profile` | 纸张/标签的毫米尺寸、方向、边距、间隙、行列、DPI 和起始格 |
| `print_device` | 设备身份、作用域、驱动/网络名称、输出语言、能力和状态 |
| `print_device_binding` | 工作站/科室 + 卡片类型 + 介质方案到默认设备的映射 |
| `print_batch` | 查询条件快照、组版策略、数量对账、状态和操作人 |
| `print_batch_item` | 批次内每张逻辑卡片的来源键、来源版本、分组键、执行时点、快照、状态和错误 |
| `print_batch_output` | 最终 PDF/设备指令包、页号/标签格映射、摘要和不可变内容 |
| `print_device_delivery` | 入队、发送、设备回执、失败码、重试次数和时间 |

建议扩展现有打印作业状态，但不覆盖历史记录：`GENERATED -> QUEUED -> SENT -> DEVICE_CONFIRMED`，任一通道可进入 `FAILED` 或 `CANCELLED`。浏览器通道止于 `SENT`。

### 7.3 数据提供器协议

每个卡片类型实现统一协议：

1. 定义可选条件和权限范围；
2. 返回候选卡片及稳定分组键；
3. 校验来源状态、版本、停止/作废状态和业务门禁；
4. 一次性生成不可变快照，渲染过程不再查实时业务表；
5. 输出字段字典、样例值、必填级别和隐私级别，供模板设计器使用。

首期数据应直接复用现有治疗执行任务和住院医嘱执行任务。药品名称、规格、剂量、途径、频次、皮试和抗菌药标识使用医嘱已固化的快照，避免后续修改药品基础数据改变已生成卡片。

## 8. 业务规则

1. 卡片仅能从已签署并达到对应业务门禁的医嘱/执行任务生成。
2. 口服药卡和输液卡默认按“计划执行时点”生成，不按开嘱时间。
3. 医嘱变更后，未打卡片失效并重建；已打卡片保留为历史且标记 `SUPERSEDED`，新卡显示变更版本。
4. 医嘱停止/作废后禁止再打原卡；确需追溯时只能下载历史输出，不能进入常规打印队列。
5. 过敏、皮试、抗菌药和高警示标记取自医嘱快照与有效临床事实；模板只决定展示，不自行推断。
6. 打印行为不改变执行任务状态；床旁扫码或人工签名后才能记录实际执行。
7. 纸质巡视卡可作为现场记录载体，但如系统要形成可计算的闭环，巡视结果仍需以结构化电子事实回录；不从打印历史反推临床执行。

## 9. 分期实施

### 第一期：可用的临床卡片闭环

- 建立卡片类型、数据提供器和介质方案模型；
- 将当前硬编码 A4 渲染器改为可解析发布布局的通用 PDF 渲染器；
- 实现受控可视化设计器、草稿/审核/发布和真实数据预览；
- 交付输液瓶签/静滴卡、口服药卡、输液巡视卡三类模板；
- 支持 A4、A5、58/80 mm 连续纸和自定义标签 PDF，使用浏览器打印；
- 保存不可变卡片快照、模板版本、内容摘要和原打/补打链。

### 第二期：批量和设备化

- 交付批量打印工作台、数量对账、A4/A5/预切纸组版、部分失败重试；
- 实现本地打印桥、设备注册、工作站绑定、静默打印和可获得的设备回执；
- 根据试点设备增加 ZPL/TSPL/ESC-POS 适配，不在未确定机型前同时实现全部语言；
- 补充注射卡、雾化/治疗卡和护理执行单。

### 第三期：执行闭环与运营

- 对接移动护理/PDA，卡片条码扫描定位患者、执行任务和医嘱版本；
- 巡视、异常、执行与复核形成电子事实，纸张作为降级和现场载体；
- 建立按科室、设备、卡片类型统计的失败率、重打率、耗材和峰值队列监测。

## 10. 第一期验收标准

1. 管理员能在一个页面完成单卡设计、真实样例预览、校验和提交发布，无需编写 HTML 或请开发人员制作报表。
2. 同一张输液卡可在自定义标签和 A4/A5 多联两种介质上生成，内容版本一致。
3. 口服药卡、输液卡和巡视卡均能按病区、日期、班次、患者和状态筛选，且打印前后的卡片数、排除数和错误数可对账。
4. 药品长名、多药组、儿童小剂量、过敏/皮试/高警示和中英文混排均有专项样例，发布前可发现溢出和遮挡。
5. 经校准设备上的实物宽高、边距和标签间隙符合耗材方案，条码能被试点手持设备稳定识别。
6. 同一业务幺等键重复提交不生成重复卡片；医嘱变更后旧卡不被覆盖，新旧版本关系可追溯。
7. 补打必须记录原因，历史输出与 SHA-256 摘要一致，可追溯模板版本、来源版本、操作人、批次和打印通道。
8. 无本地打印桥时，A4/A5/热敏 PDF 仍可预览和人工打印；本地桥不可用时可降级，不阻塞基层业务。

## 11. 实施风险与试点前置

- **不要在未确定耗材时锁死标签尺寸**。试点前收集实物纸张、标签间隙、黑标方式、DPI 和打印机型号。
- **浏览器打印无法提供可信的出纸成功回执**。首期界面要如实显示“已生成/已发起”，需无人值守或大批量打印时再引入本地桥。
- **PDF 不能自动消除驱动缩放和走纸偏差**。每个设备/耗材组合需校准值和实物验收。
- **单据不等于临床事实**。打印、补打、扫码和实际执行必须保持独立状态，否则会产生“打过就算做过”的安全风险。
- **模板自由度必须有上限**。卡片是医疗安全载体，应先满足必填字段、可读性和可追溯性，再提供机构品牌化能力。

## 12. 试点建议

选择一个病区和一个门诊/基层输液区做两类试点：

1. 病区试点：A4/A5 口服药执行单 + 热转印输液瓶签 + A5 输液巡视卡；
2. 基层试点：A5 或 80 mm 输液卡 + A5 巡视卡，优先验证 USB 打印和断网后已生成文件的重打能力。

试点确认实际卡片样张、耗材和设备后，再冻结首批平台预设；这样既能快速上线，也不会把一家机构的细节写进通用领域模型。
