# 库房月结与调价价值账设计

## 1. 设计结论

库房账务分为三类不可混用的事实：

1. `inventory_transaction_lines` 记录数量变动，数量必须非零。
2. `inventory_valuation_entries` 记录数量不变时的价值变动，主要包括售价调价、成本重估、舍入调整和冲销。
3. `inventory_period_balance_snapshots` 固化月结时每个库存维度的期初、本期变动、期末和实时数量。
4. `inventory_period_balance_values` 按成本价、零售价等价值口径分别固化月结金额，严禁将不同口径相加。

数量账的标准恒等式为：

```text
期初数量 + 本期数量净变动 = 期末账面数量 = 月结时实时库存数量
```

其中出库、发药等已以负数记录，因此统一使用“加净变动”，不再分别书写加减公式。

价值账的标准恒等式为：

```text
期初价值 + 数量业务金额净变动 + 价值调整 + 舍入调整
= 期末账面价值 = 月结时库存价值
```

## 2. 表职责

### 2.1 `inventory_periods`

继续作为库房期间主表。新增：

- `previous_period_id`：指向上一期，防止同一库房出现两条期间分支。
- `closing_run_id`：指向最终成功的月结批次。

期间仍使用 `OPEN -> CLOSING -> CLOSED` 状态。`CLOSED` 后不允许再写入数量流水或价值流水。
期间链和月结批次均使用“租户 + 库房 + 期间”复合外键，数据库层禁止跨库房串期。期间日期不重叠且前后连续由建期服务在锁定库房后校验。

### 2.2 `inventory_period_close_runs`

记录每次月结尝试，保留请求编码、请求摘要、对账批次、差异数和失败原因。各价值口径的金额汇总单独存入 `inventory_period_close_totals`。

状态为：

```text
RUNNING -> VALIDATED -> POSTED
                    -> FAILED
                    -> VOID
```

只有差异数为零、价值差为零并完成记账时才能成为 `POSTED`。

### 2.3 `inventory_period_balance_snapshots`

月结的最小核算维度与库存余额一致：

```text
租户 + 库房 + 库位 + 经营项目 + 批次 + 库存状态
```

每条数量快照保存：

- 期初数量、本期数量净变动和期末账面数量；
- 月结时实时数量及差异；
- 库存余额修订号；
- `opening_source_snapshot_id`，用于证明本期期初来自哪一条上期期末。

每条数量快照在 `inventory_period_balance_values` 中按 `COST` 和 `RETAIL` 分别保存期初价值、业务金额、价值调整、舍入差额、期末价值与实时价值。这两类表共同构成“期末=库存”的直接证据，不能只保存药品级汇总。

### 2.4 月结价值明细与汇总

- `inventory_period_balance_values`：按库存维度和价值口径保存期初、变动、调整、期末及差异。
- `inventory_period_close_totals`：按月结批次、价值口径和币种汇总金额。

当前支持 `COST` 和 `RETAIL` 两种口径。增加新口径时只增加明细与汇总记录，不需要重复生成数量快照。

### 2.5 `inventory_valuation_entries`

独立价值流水，不改变数量。支持：

- `PRICE_ADJUSTMENT`：销售价调价产生的库存零售价差；
- `COST_REVALUE`：库存成本重估；
- `ROUNDING`：包装换算和金额精度产生的显式舍入差；
- `REVERSAL`：对原价值流水的反向冲销。

价值流水必须归属一个开放库存期间，并保存数量快照、调整前后单价、价值及冲销关系。

### 2.6 调价单据表

- `inventory_price_adjustments`：调价单头、审批与记账状态。
- `inventory_price_adjustment_lines`：药品级原价、新价、价格版本和汇总调价金额。
- `inventory_price_adjustment_details`：库存维度级数量快照、余额修订号和价值流水关联。

调价类型分为：

- `SALE_PRICE`：只建立新的 `catalog_prices` 销售价版本，并记录库存零售价差。
- `COST_REVALUE`：只改变库存成本价值，不改变目录销售价。
- 销售价与成本价禁止在同一调价单混调。当前明细表每个库存维度只关联一条价值流水，若后续确有组合审批需求，应先扩展为“一条调价明细关联多条价值流水”，不能复用单一关联字段强行记账。

## 3. 月结流程

1. 在期间保持 `OPEN` 的状态下运行 `PERIOD_CLOSE` 预检，日常库存作业不被长时间阻塞。
2. 从上期 `POSTED` 快照取期初，从本期数量流水和价值流水汇总净变动。
3. 生成带库存余额修订号和状态摘要的只读月结快照；任一维度数量或价值差不为零时仍保留 `VALIDATED` 批次，但不得正式月结。
4. 正式月结事务对期间加排他锁，并按固定维度顺序锁定本库房全部库存余额。
5. 重新计算状态摘要；只要预检后新增了库存流水或余额修订发生变化，就拒绝旧预检结果并要求重新预检。
6. 全部一致后，在同一事务内完成期间 `OPEN -> CLOSING -> CLOSED`，并将月结批次置为 `POSTED`。
7. 自动建立下一连续期间，通过 `previous_period_id` 引用已关闭期间，其期初必须来自上期最终快照。

## 4. 精度与对账规则

- 数量继续使用 `decimal/number(28,8)`。
- 单价继续使用 `decimal/number(24,6)`。
- 金额流水和月结快照使用 `decimal/number(30,6)`，避免“大数量 × 高精度单价”溢出原 `24,6` 金额范围。
- 包装换算全程使用基本单位数量，只在展示层还原包装数。
- 舍入差不得隐藏在平均价中，必须形成 `ROUNDING` 价值流水。
- 月结头不汇总不同药品的数量，因为不同单位数量不可直接相加；只汇总统一币种的价值。

## 5. 并发与不可变要求

- 调价记账和月结快照都必须按“库位、药品、批次、库存状态”固定顺序锁定余额。
- `inventory_balance_revision` 与锁定后修订号不一致时，调价单必须重新计算，不得沿用旧快照。
- 数量流水、价值流水和已发布月结快照不允许物理修改或删除，错账只能通过反向冲销更正。
- 请求编码与请求摘要共同保障月结和调价的幂等性。

## 6. 迁移范围

本轮迁移为：

- PostgreSQL/H2：`V83__inventory_period_close_and_valuation_ledger.sql`
- Oracle：`V83__inventory_period_close_and_valuation_ledger.sql`

该迁移只增加兼容结构，不改变现有库存数量记账语义。月结服务、价值记账服务和调价界面均在该兼容结构上实现。

## 7. 当前实施状态

截至 2026-08-30，已完成：

- 库存期间连续性、上一期间已关闭校验及业务记账期间读锁；
- 成本口径的月结预检、数量/金额快照、差异阻断、预检过期校验和正式月结；
- 正式月结后自动建立下一连续期间，已关闭期间拒绝补记流水；
- 库房管理中的期间时间轴、勾稽汇总、预检历史、差异明细及正式月结二次确认界面；
- 成本重估与销售调价分单管理，支持批量选择经营项目、草稿、预检、审核、正式记账和取消；
- 调价预检保存库存维度、数量和余额修订号，预检后库存发生变化时拒绝旧单记账；
- 成本重估仅更新现存库存平均单位成本并生成 `COST_REVALUE` 价值流水，库存数量流水保持不变；
- 销售调价生成新的目录价格版本并生成 `RETAIL` 价值流水，不覆盖历史价格；
- 库房管理中的宽屏调价工作区，集中展示调前/调后价值、差额、基本单位数量及批次库位影响范围；
- H2 集成测试覆盖“预检后发生业务变动则拒绝关账”和“关账后下期自动结转”。
- H2 集成测试覆盖“调价预检过期拒绝记账”“包装换算后数量不变”以及“成本调价差额进入月结勾稽”。

当前月结汇总先开放 `COST` 成本口径；销售调价已记录 `RETAIL` 价值流水，但零售价口径的月结期初结转和汇总仍作为下一阶段推进。组合型 `SALE_AND_COST` 调价暂不开放，待一对多价值流水关联结构明确后再实施。
