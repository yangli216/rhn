# 门诊单据信息管理

连续录入列表保留医嘱顺序。保存后的单据通过摘要条和行内归属标记进入右侧编辑面板；保存单据信息不清空医嘱录入草稿、不自动打开面板。宽屏并排，常规桌面宽度按需覆盖侧栏。

## 当前范围

- 处方按现有自动分方生成的处方 ID 管理，检验检查沿用现有一条请求一张申请单的边界。
- 关联诊断从本次已保存的就诊诊断选择，支持多选和一个主要诊断；服务端校验归属并保存名称快照。
- 外配处方标记作用于整张处方。门诊特病病种为医生确认后的文字记录，目前没有接入医保待遇目录。
- 外配、特病仅作为单据属性记录与打印展示，不自动变更院内收费、发药、库存冻结或医保结算流程。部分药品外配、待遇校验及跨流程联动不在本次范围。
- 检查目的独立于原有部位、标本和临床说明；新增字段同时进入医技外发请求快照和申请单打印内容。

## 编辑与状态

两类单据分别提供 `PUT /api/encounters/{encounterId}/prescriptions/{id}/document-info` 和 `PUT /api/encounters/{encounterId}/service-requests/{id}/document-info`。

请求包含 `expectedRevision` 和 `documentInfo`；关联诊断、主要诊断、外配标记、特病病种及检查目的一次保存。校验租户、就诊、活动状态、版本，记录修改前后审计事件。

处方仅草稿可修改。检验检查仅有效、未采集、未开始执行的申请可修改，修改时锁定医技执行任务并再次检查状态。诊断尚未选择和检查目的未填写是提示项，不新增机构未配置的强制阻断规则。

切换单据、关闭面板时若存在修改，提供保存并继续、放弃修改和继续编辑；版本冲突保留用户输入。患者工作区已有忙碌保护覆盖侧栏未保存状态，浏览器退出也会提示。

## 分单与提交

当前主路径每次批量保存根据分单规则建立新处方，不重新分配既有单据 ID。兼容保存路径跳过已经设置单据属性的处方，避免自动追加到外配、特病或已关联诊断的处方。

审核开立界面显示已保存单据的缺项入口。尚未保存的医嘱提供“保存分单并完善”，完成后可再次审核开立；原连续输入及直接确认开立路径保留。

## 数据库

V1_57_0 为处方头和诊疗请求分别新增 `JSON_DOC_INFO`，既有单据按空属性读取。PostgreSQL、Oracle 分别使用 TEXT 和 CLOB；H2 测试使用 V1_57_1 兼容迁移。无需回填或修改旧单据。

## 手工验收

1. 连续输入多种药品及检验检查，保存后确认输入顺序和分单结果不变。
2. 点击“方1”或摘要，确认所属医嘱高亮、侧栏成员与实际单据一致。
3. 设置诊断、主要诊断、外配或特病，保存并刷新，确认信息保留。
4. 修改后切换单据或关闭，分别验证继续编辑、放弃、保存并继续。
5. 继续录入并保存新医嘱，确认旧单据属性不被覆盖。
6. 检查目的与原说明分别保存，检查打印和医技外发数据；采集后侧栏只读。
7. 双窗口修改同一单据，旧版本保存应报冲突且保留输入。
