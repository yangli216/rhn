# 门诊结构化病历表单规范

## 1. 能力边界

门诊病历保留两种并行书写方式：

- **基础门诊病历（简易）**：主诉、现病史、既往史、生命体征、查体、诊疗计划和诊断，默认启用，适用于大多数基层门诊。
- **科室结构化病历**：在基础病历之上追加科室定义字段，由医生按本次就诊场景主动选择；不能替代基础病历和诊断，也不能自动签署。

“病历段落模板”和“结构化病历表单”是两类能力。前者复用医生常写文字，后者定义字段结构与校验规则，编码、版本和生命周期不得混用。

## 2. 标识与版本

- 表单编码：大写字母开头，只允许大写字母、数字和下划线，例如 `HYPERTENSION_FOLLOW_UP`。
- 专科编码遵循相同格式；当前基层全科使用 `GENERAL_PRACTICE`。
- 分区和字段编码使用 lowerCamelCase，例如 `bloodPressureReview`、`homeSystolic`。
- 每次发布形成递增的不可变版本。发布 V2 时 V1 转为 `RETIRED`；新病历不得再引用 V1。
- 已保存的临床文书不只记录表单版本 ID，还必须固化完整定义快照，保证历史还原不依赖在线配置。

## 3. 字段类型

当前支持：

| 类型 | 用途 | 可配置规则 |
|---|---|---|
| `TEXT` | 短文本 | 必填、最大长度、提示语 |
| `TEXTAREA` | 长文本 | 必填、最大长度、提示语 |
| `NUMBER` | 数值 | 必填、最小值、最大值、单位 |
| `SELECT` | 单选 | 必填、受控选项 |
| `BOOLEAN` | 是/否 | 必填 |
| `DATE` | 日期 | 必填、ISO 日期格式 |

单表单最多 8 个分区、40 个字段；字段编码在整张表单内唯一。暂不支持脚本表达式、任意 HTML、嵌套对象和跨字段动态计算，避免把普通基层病历配置成难以维护的低代码系统。

## 4. 文书快照

选择结构表单保存后，门诊病历使用 `RHN.OUTPATIENT_NOTE.V3`，新增：

- `structuredForm`：版本 ID、表单编码、版本号、名称、专科编码、定义 Schema、发布时间和完整分区字段定义；
- `structuredData`：经服务端校验、清理后的本次填写值。

未选择结构表单时继续使用简易病历，不发送空结构数据。签署、完整性保护、不可否认证据和受控打印均针对包含快照的完整文书版本。

## 5. 使用原则

- 默认简易、按需增强，不能强迫所有基层门诊使用专业表单。
- 结构表单只补充专科事实，不重复患者身份、生命体征、诊断、医嘱等已有强类型字段。
- 前端切换表单或编辑结构字段必须进入未保存状态，切换患者与签署前受统一草稿保护。
- 打印和历史回显按照文书内快照解释选项名称和单位，不读取当前发布版本。
