# M4 医防一体化契约

## 1. 目标与边界

M4 以高血压为首个医防纵向切片，证明“诊疗事实 → 候选识别 → 照护计划 → 随访执行 → 异常回流 → 公卫上报”能够使用同一居民、同一术语、同一证据链闭环。首切片不以单次异常自动生成确诊，不把门户待办当作连续照护权威数据，也不以本地保存代替外部上报成功。

模型权威来源为 `nextgen-core.dbml` 中的 `vis.observation`、`vis.condition`、`hpl.care_plan`、`hpl.care_goal`、`hpl.care_task`、`hpl.care_task_event`、`hpl.followup_task_detail` 与 `hpl.public_health_report`。`work_tasks` 仅为岗位工作台投影，`hpl.care_task` 才是连续照护任务权威。

业务依据：

- 国家卫生健康委 [WS/T 872—2025《基层医疗卫生机构高血压防治管理标准》](https://www.nhc.gov.cn/fzs/c100048/202509/2f3f7cce449145f8b361e70b3ed4ae9a/files/WS%20T%20872%E2%80%942025-20250930105429913.pdf)，2026-03-01 实施；
- LOINC [85354-9 Blood pressure panel](https://loinc.org/85354-9/)，收缩压 `8480-6`、舒张压 `8462-4`，单位 `mm[Hg]`；
- 高血压诊断确认仍遵循非同日多次规范测量和临床确认，本系统首切片只创建疑诊候选与复测任务。

## 2. 分段实施

| 切片 | 交付闭环 | 完成口径 |
|---|---|---|
| M4.1 候选识别 | 结构化血压、疑诊病情、权威复测任务、规则证据、工作台投影 | 单次异常只进入候选；普通和显著升高分流；重复计算幂等 |
| M4.2 照护计划 | 照护计划、目标、临床确认、任务编排 | 计划经医务人员确认后生效；变更保留版本与原因 |
| M4.3 随访执行 | 随访表单、结构化事实、完成判定、异常回流 | 随访结果进入时间轴；红旗异常回到诊疗闭环 |
| M4.4 公卫协同 | 上报事件、提交、回执、失败重试、撤回/更正 | 以对方业务回执作为完成依据，本地保存不算上报完成 |

## 3. M4.1 候选识别契约

### 3.1 输入事实

诊室接诊记录的血压为临床人员确认后的最终规范读数。系统同时写入两条 `FINAL NUMBER` 观察结果：

- LOINC `8480-6`：收缩压；
- LOINC `8462-4`：舒张压；
- 单位统一为 `mm[Hg]`；
- 观察结果关联租户、居民、接诊、记录时间和操作者。

后续若需要保存同次测量的原始多次读数和平均过程，应扩展观察结果组，不覆盖本切片已经形成的最终读数和证据。

### 3.2 识别与安全边界

首切片规则编码为 `WS_T_872_2025.SUSPECTED_HYPERTENSION`，规则版本为 `2025-09-19`：

1. 仅评估测量时已满 18 周岁的居民；
2. 收缩压大于等于 140 mmHg，或舒张压大于等于 90 mmHg，进入疑诊候选；
3. 首次进入候选时创建 `SUSPECTED + ACTIVE` 的 I10 病情事实，并创建非同日复测任务；
4. 收缩压大于等于 180 mmHg，或舒张压大于等于 110 mmHg，创建立即复测并评估转诊的 `URGENT` 任务；
5. 显著升高也不得由系统自动确诊或自动判定转诊；
6. 普通候选复测期限为 28 天，临床确认流程在 M4.2 实现。

同一居民的候选写入以居民主记录悲观锁串行化；同一病情只保留一个开放复测任务。重复计算可以追加新的测量证据，但不能重复生成病情或任务。

### 3.3 证据与投影

每次有效识别事件保存：规则编码和版本、判断结果、年龄、接诊号、测量时间、两条观察结果标识和值、阈值、复测期限、证据规范化 JSON 与 SHA-256。证据声明 `CANDIDATE_NOT_DIAGNOSIS`，避免门户展示把候选误解为确诊。

新建的 `care_task` 通过领域事件投影成 `CONTINUOUS_CARE` 岗位待办，并携带返回连续照护工作台的路由。投影可重建，不能反向覆盖病情、照护任务或证据事件。

### 3.4 数据范围与权限

- 自动识别必须在受信机构、科室上下文内执行，且账号已绑定医务人员身份；临床记录未选择工作上下文时仍保存结构化血压，但安全跳过候选副作用，待受信上下文中的补偿筛查处理；
- 候选队列只返回当前租户及当前有效机构、科室授权范围的数据；
- 居民合并后按主索引规范标识查询；
- 术语快照固化系统 URI、版本、编码与显示名，历史事实不随当前术语显示变化而重解释。

## 4. M4.2—M4.4 后续契约

M4.2 将使用 `care_plan` 表达计划主体、状态、生效区间和负责人，使用 `care_goal` 保存可测量目标，以 `care_task` 编排复测、随访、转诊评估等动作。候选只能由有权限的临床人员确认、排除或转为其他处置，系统规则不能直接签署诊断。

M4.3 将把随访表单定义与结构化事实分离：表单负责采集，观察结果、用药、生活方式和处置建议进入对应权威领域；`followup_task_detail` 记录本次随访执行上下文。危险症状、持续显著升高、依从性或不良反应等红旗规则创建临床评估任务，不能只留在表单 JSON 中。

M4.4 使用 `public_health_report` 保存待提交、已提交、业务接收、业务拒绝、更正和撤回轨迹；Outbox 负责可靠投递，外部业务回执负责最终状态。接口失败允许幂等重试，内容改变必须生成新版本或更正事件，不得覆盖已提交报文。

## 5. 基础数据扩展属性边界

`item-attribute-configuration-model.md` 已列为本轮横切底座，但它服务于药品、检验、检查和诊疗项目等基础项目的差异化配置。高血压阈值、确诊条件、转诊红旗、随访频次、计费、库存和医疗安全规则不得配置成任意动态属性；需要可配置时应进入版本化规则模型，或先升级为强类型字段/受控 `PROJECTED` 投影。

M4 可以读取业务发生时已经固化的项目扩展属性快照作为辅助证据，但不得在历史回放时按当前属性配置重算，也不得扫描 JSON/EAV 值驱动候选识别。

## 6. 首切片验收

1. 成年居民正常血压只生成两条结构化观察结果，不生成候选；
2. 成年居民首次异常生成疑诊病情、复测任务、证据事件和岗位投影；
3. 重复测量不重复生成病情和任务，但保留新的证据事件；
4. 显著升高生成立即复测与转诊评估提示，状态仍为疑诊；
5. 未成年人不进入成人高血压筛查；
6. 无当前科室上下文时不创建候选，显式越权上下文或无医务人员绑定时失败关闭；
7. 规则证据可追溯到两条 LOINC 观察结果且哈希稳定；
8. OpenAPI、前端类型、H2 全迁移、后端自动化测试、UI 规范检查和生产构建通过。
