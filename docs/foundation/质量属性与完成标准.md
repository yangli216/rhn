# 基础底座质量属性与完成定义

## 质量属性场景

当前阶段不实施监控、备份、发布和安全工程，但业务基础必须满足以下可测试属性：

- 一致性：强事务状态、事件 Outbox 和同步投影在同一事务成功或回滚。
- 幂等性：重复事件不会生成重复健康时间轴记录。
- 可追溯：主数据、配置、MPI 和临床文档的历史版本不被覆盖。
- 可演进：API 和事件有显式版本；参数维护带乐观修订号的当前状态和追加式变更记录；新增可选字段保持兼容。
- 隔离性：查询和修改始终带租户条件；跨租户相同外部编码互不冲突。
- 可移植：数据库迁移至少在 PostgreSQL 与自动化测试数据库验证。
- 可测试：每个基础模块提供领域规则测试和持久化集成测试。
- 可理解：状态、错误码、术语和模块边界有集中目录，禁止散落魔法字符串。

## 基础能力 Definition of Done

一个 Foundation 用例完成必须具备：

1. 领域术语和状态定义；
2. 所属模块和数据表归属；
3. 输入校验、唯一性和并发规则；
4. 租户隔离；
5. 数据库迁移；
6. 公开 API 或模块契约；
7. 稳定错误码；
8. 领域事件及其版本（若产生跨模块事实）；
9. 单元或集成测试；
10. 对现有纵向切片的回归验证。
11. 涉及关键数据时，登记密码保护目录，定义精确受保护原文并验证完整性/不可否认证据；禁止业务自建密码实现。
12. 涉及枚举选项时，完成系统枚举、普通字典、术语、主数据或领域状态判定；保存稳定编码、复用统一选项加载和响应文本翻译，禁止硬编码中文映射或直接查询字典表。
13. 涉及可配置行为时，定义参数分类、作用域、缺值、继承、缓存、安全和历史重放策略；只通过 `ConfigurationDirectory` 解析，并覆盖默认值、覆盖、继承、禁止继承和缺值测试。

监控指标、备份策略、发布流水线和正式安全控制不计入当前 Foundation 用例完成条件。
