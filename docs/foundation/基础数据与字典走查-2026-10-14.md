- `MED_SAFETY_OVERRIDE_POLICY`：用药安全提醒处置要求。原前端映射的键写成 `NOT_APPLICABLE`，与后端 `NOT_ALLOWED` 不一致，且该映射无人使用，已删除。

**响应绑定**（自动附 `xxxText`）：挂号队列、就诊查询与就诊响应、收费挂号意向的来源/就诊类型/候诊状态；居民证件类型（`PI_RESIDENT_IDENTIFIER_SYSTEM`）；供应商状态（`BD_MASTER_STATUS`，与厂家一致）；字典属性、基础数据属性定义与用药规则的上述枚举字段。

**前端**：删除挂号来源、就诊类型、候诊状态（两份且“已取消/已退号”不一致）、支付方式、重复开立规则、储藏方式、药品类型（两处）、科室类型（遗留 `CLIN_*` 码）、床位状态、居民证件类型（含过时别名，名称与字典不符）、供应商状态、字典属性四类名称等映射，改用响应 `xxxText`；选项列表通过新共享钩子 `useSystemEnum` 读取系统枚举。

### 第 4 步第二批：药房与收费

**模块自行登记系统枚举**：新增 `SystemEnumContribution`，各业务模块以 Spring 组件提供自己的系统枚举，平台目录统一汇总并校验编码全局唯一；`SystemEnumDefinition.of(...)` 有 Java 枚举时校验项与枚举常量完全一致。本批由收费（`BillingSystemEnums`，12 个）、药房（`PharmacySystemEnums`，27 个）、用药安全（`MedicationSafetySystemEnums`，2 个，自平台目录迁出并改为按 Java 枚举校验）提供，系统枚举共 88 个。

**处理中发现的不一致**（均以后端为准修正显示）：
- 支付类别前端只映射 10 项中的 5 项，医保统筹、预交金、医院减免、补助、舍入差额此前显示原始编码。

## 第 4 步 · 收费域收口

按“历史数据不保留、开发库重建”的前提，处理批次二遗留的收费域问题（迁移 `V1_129_8__billing_terminal_scene_and_tender_type`，两种方言）。

**收费入口统一为一套编码**：`PAY_USE_SCENE` 改名“收费入口”，项改为 `CASHIER`、`DOCTOR_STATION`（原 `CLINIC_SETTLE`）、`SELF_SERVICE`，新增 `MOBILE`、`ONLINE`，与结算单入口约束一致；撤销系统枚举 `BIL_TERMINAL_SCENE`。结算单入口、支付记录、支付订单场景和票据开具渠道统一由新组件 `BillingCodes` 按字典校验，删除 `CLINIC_SETTLE→DOCTOR_STATION` 的硬转换以及控制器上的取值正则。`SystemEnumConsistencyTest` 增加“系统维护字典与检查约束”的比对：结算单入口须与字典完全一致，票据渠道为其子集（医生站不开票）。

**住院预交金不再占用场景编码**：原先用 `INPATIENT_PREPAYMENT` 写入支付场景列来识别预交金，现预交金记为收费处收款，按“未关联账单的收款”识别（只有预交金如此）。

**支付方式 → 结算支付类别改为字典属性**：`PAY_METHOD` 新增 `TENDER_TYPE` 属性（现金、银行卡、移动支付、医保个人账户、其他），替换结算记账和票据财政分摊两处写死的判断。原写法把未识别的支付方式（含字典里的“其他”）计为“商业保险”，开票时再被拒绝；现“其他”计为新增的支付类别 `OTHER`（其他自付，计入患者自付），未配置类别的支付方式在收款、建支付订单和登记预交金时直接拒绝。

**新增系统枚举与约束**：收费来源 `BIL_CHARGE_SOURCE_TYPE`（12 项，原为开放文本，同时为收费事项表加检查约束）、收付类型 `BIL_PAYMENT_TYPE`、账务核对结果 `BIL_RECONCILIATION_LINE_STATUS`、票据类型 `BIL_RECEIPT_TYPE`、住院结算财务状态 `BIL_INPATIENT_FINANCIAL_STATUS`。系统枚举共 92 个。

**前端**：
- 收费员日结的支付方式原样显示编码（如 `WECHAT`），收付类型、账务核对的业务类型（原显示 `MEDICATION_DISPENSE` 等编码）和核对结果改用响应文字；补录类型选项改用系统枚举。
