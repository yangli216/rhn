# 参数管理设计

## 1. 能力边界

参数中心统一承载可运营、需要按上下文差异化的系统参数和业务参数。本轮实现与目标模型保持一致，只维护当前定义和当前值，不提供审批、发布、计划生效、业务版本或自动回滚。

普通枚举选项复用字典中心；标准术语和值域仍归术语服务；密码、私钥和第三方密钥明文不得进入参数库；强类型业务事实、权限规则和临床规则版本不能降格为参数。

## 2. 物理模型

项目采用扁平 schema 命名，将逻辑模型落为：

| 物理表 | 一行粒度 | 并发策略 |
|---|---|---|
| `parameter_categories` | 分类树中的一个节点 | `OPTIMISTIC_VERSION` |
| `parameter_definitions` | 一个参数定义的当前状态 | `OPTIMISTIC_VERSION` |
| `parameter_values` | 一个参数在一个规范作用域中的当前值 | `OPTIMISTIC_VERSION` |
| `parameter_changes` | 一次定义或值变更 | `APPEND_ONLY` |

V10 迁移创建上述权威表。V2/V7 曾建立的 `configuration_definitions`、`configuration_revisions` 属于早期原型遗留结构，新代码不再映射或读写；已有部署升级时需先制定旧数据迁移和核对方案，再单独执行退役迁移，不能在通用升级脚本中直接丢弃潜在数据。

## 3. 定义规则

参数分类、参数键和定义字段的登记与评审要求统一遵循[参数分类与参数定义规范](参数分类与参数定义规范.md)。

- 参数键使用小写点分段，例如 `outpatient.registration.timeout`，创建后不可修改或复用；
- 值类型为 `STRING`、`NUMBER`、`BOOLEAN` 或 `JSON`；
- 控件与值类型必须兼容，`SELECT` 必须绑定系统枚举或普通字典；
- 默认值、示例值和覆盖值统一使用 JSON 表达，并接受 JSON Schema 子集校验；
- 定义区分 `SYSTEM` 与 `BUSINESS`，支持启停、允许继承、解析缓存和显式空值开关；
- 已有当前值后禁止修改值类型，避免已存 JSON 失去解释方式；
- 参数级别支持多选并完整保留已有允许作用域，编辑其他资料不得只保留第一个作用域；已有定义缺少作用域时要求明确选择，不能自动补成租户级；
- `SENSITIVE` 必须使用掩码或隐藏展示策略；`SECRET` 必须使用 `SECRET_REFERENCE` 控件和非明文展示策略，定义及日志快照均不保存密钥明文。

编辑定义时保留已有计量单位和示例值，只有用户明确编辑或清空普通字段才更新或移除。空字符串默认值使用显式选项维护，区别于未配置和 JSON `null`；已有空白字符串也不得因改名被清除。明文响应声明有默认值或示例值却未返回内容时，阻止保存并提供重新确认入口，刷新后未编辑字段使用已确认原值，其他草稿保留。受保护的默认值和示例值未返回明文时明确提示“留空保留、填写替换”；密钥参数同样保留未修改的受保护示例，但不保留默认明文。

分类是管理界面树，不参与业务解析。分类支持父级、排序、启停、循环检测和 64 层深度限制。

分类目录读取必须确认标识、编码、名称、修订、排序和明确状态，以及标识/编码唯一、父级齐全且无循环；无效目录显示加载失败，不能把缺少状态当成启用或丢弃孤立分类后展示正常树。创建、更新和排序须逐项核对响应目标、提交内容和修订后才提示成功；排序不提前把本地计划写入缓存，完整响应必须包含原目录并保持未提交分类的内容。发布已确认响应时保留并发刷新取得的更新修订和新增分类，同一修订内容矛盾应提示未确认。

分类编辑草稿绑定打开编辑器时的修订；刷新和失败不能重置草稿或静默提高提交版本。刷新失败禁用提交并提供重新确认入口；写入期间锁定表单和关闭按钮，工作上下文变化后的迟到响应不发布成功或覆盖缓存。分类接口目前没有请求编码幂等协议，响应丢失不代表写入失败，也不能靠客户端生成请求编码或匹配分类编码声称已确认；应重新加载核实服务端事实，冲突由原修订或唯一编码保护。

编辑定义时，未修改的 JSON Schema 原样保留，修改单项约束只更新对应字段；不得因编辑名称等资料补上默认结构、删除其他关键字或重写枚举和正则。JSON 类型未声明 `type` 时允许对象或数组。无法解析或字段类型不合法的规则必须明确展示原始内容并阻止提交，用户可通过原始 JSON 修复或明确清空；服务端负责最终校验。含分隔符或首尾空格的枚举值、必填字段名以原始数组展示并通过原始规则编辑，不能经逗号分隔输入框静默拆分。

参数编辑器按原始 JSON 数值文本维护当前值、默认值和校验规则，不经 JavaScript `Number` 或普通 `JSON.parse` / `JSON.stringify` 往返生成提交内容。大整数、高精度小数、科学计数法及负零不会因编辑或保存被舍入、下溢为零或改成 `null`；数值范围使用精确十进制比较。编辑一个规则字段时，其他字段（包括嵌套附加规则）的数值文本继续保留。数值输入只接受 JSON 十进制格式，不把十六进制等格式自动转换成另一个数值。JSON 参数按服务端契约只接受对象或数组，发现重复属性名时保留输入并阻止提交，不静默覆盖同名属性。此处约束编辑和提交内容，业务范围与运行时解析仍由服务端校验。

服务端通过共享 `JsonCodec.readExactTree` 解析参数默认值、当前值、约束及历史快照：保留精确十进制数，拒绝重复键和尾随 JSON；业务层不直接构建 `JsonMapper`。`ParameterContentIntegrityTest` 覆盖精度、极大／极小数值、范围与枚举约束及失败不落审计，`ArchitectureTest` 校验共享封装边界。

## 4. 当前值与解析

编辑已有科室参数时，必须先取得该科室的真实所属机构；查询失败、响应缺失或科室标识不匹配时保留编辑草稿并阻止保存，允许重新核实。不得使用当前登录机构替代，刷新期间及刷新失败后也不得沿用缓存归属提交。

机构与科室配置目标共用按租户隔离的核实逻辑。列表加载失败、目标缺失或科室不属于所选机构时，不得自动选择列表第一项；保留目标标识并要求用户明确选择或重试。保存必须等待目标核实成功，刷新期间和失败后不得沿用缓存目标提交。

`(definition_id, scope_code)` 唯一，保证每个规范作用域只有一条当前记录。`scope_code` 只能由服务端根据已校验上下文生成：

```text
PLATFORM
TENANT:<tenantId>
ORGANIZATION:<organizationId>
DEPARTMENT:<departmentId>
USER:<userId>
PRODUCT:<tenantId>:<code>
MODULE:<tenantId>:<code>
ENVIRONMENT:<tenantId>:<code>
```

当前值支持 `OVERRIDE`、`INHERIT`、`RESET_DEFAULT`、`EXPLICIT_NULL`。启用继承时按用户、科室父链、机构父链、租户、模块、产品、环境、平台、定义默认值解析；关闭继承时只查询定义允许的最具体上下文。完整语义见 [ADR-004](../architecture/架构决策-004-分层参数配置.md)。

依赖解析失败必须传播原始错误，不得转换为“条件未满足”并缓存成 `SUPPRESSED`。管理详情可在依赖预览失败时保留定义资料，`dependencySatisfied` 为空表示未知；目录未返回该字段时同样不得标为已抑制。预览使用请求中的租户、用户、机构和科室，实际业务按完整调用上下文解析。

服务端参数 JSON 使用专用严格解析器：小数按 `BigDecimal` 解析，拒绝重复属性、多个顶层值和空文档；定义校验、覆盖值校验、运行时解析、依赖期望值和历史快照读取使用相同规则。数值范围和枚举不经浮点舍入比较，字符串长度约束按非负任意精度整数校验及比较，不经 32 位整数截断。保存当前值前重新校验已有 Schema，防止历史无效规则被类型转换当成零等默认值。解析失败直接报错且不写入成功解析缓存；失败写入不修改当前值或追加成功变更记录。

依赖期望值在保存与运行时均按前置参数类型校验：布尔值只接受 `true`/`false`，数值按十进制比较，JSON 对象/数组按结构比较并拒绝重复键及多段输入。保留已有字符串不区分大小写的匹配方式；无效期望值或与声明类型不符的实际值必须报错，不能隐式转换成 `false` 或字符串比较结果。

## 5. 写入与审计

定义和值的更新、启停及人工回退均遵循同一命令协议：

1. 提交非负 `expectedRevision` 和唯一 `requestCode`；
2. 校验租户、上下文标识、类型、Schema、字典值和安全策略；
3. 以乐观锁更新当前状态；
4. 在同一事务追加前后快照、原因、操作者和时间；
5. 事务提交后失效参数解析缓存。

当前值编辑器只有在返回定义、作用域、当前值标识、递增修订号、模式、状态和内容与提交一致后才提示保存成功。明文 JSON 按服务端存储文本核对，不经 JavaScript 数值转换；敏感或密钥内容按既有隐藏策略，仅核对服务端返回的目标、修订和内容状态，不要求接口泄露明文。响应缺失、旧修订或结果不符时保留草稿并持续提示“保存未确认”。同一页面内同一份未确认命令重试复用请求编码，参数服务按既有幂等协议返回当前详情后仍需核对；修改内容或作用域视为新命令。提交期间暂时锁定编辑，切换上下文后的迟到响应不得覆盖新上下文。

定义创建和更新同样核对返回的参数键、分类、名称、类型、控件、作用域、策略、依赖及默认值/示例值；更新还要求修订号大于打开编辑器时的源修订号。启停只在目标状态、新修订及其他定义内容一致时确认成功，失败保持确认弹窗。编辑草稿绑定原始修订，后台刷新不能悄悄提高提交版本；同一未确认命令重试复用请求编码和原修订，修改草稿使用新编码但仍受原修订保护。提交期间锁定表单和关闭操作；跨上下文或已关闭会话的迟到结果不发布成功提示、不覆盖当前缓存。受保护的默认值和示例值按服务端保留/替换规则核对存在状态，接口不返回明文时不声称已比对隐藏正文。

变更日志不提供更新或删除接口。人工恢复历史值会写出新的 `ROLLBACK` 记录。密钥参数快照仅保留密钥引用。

历史恢复前必须确认内部 `after` 快照为完整对象：启用状态必须是真实布尔值，值模式必须是已知枚举，正文和密钥引用只能是字符串或明确的 `null`；缺少字段不得推断为停用、空内容或默认模式。审计记录的租户和快照的作用域类型、标识、引用、编码必须与被恢复的当前记录一致。快照中的 Long 标识允许整数和十进制字符串两种既有序列化形式，不接受浮点数或布尔值转换。无效快照返回 `PARAMETER_ROLLBACK_SNAPSHOT_INVALID`，不修改当前值、不追加成功变更记录，也不改变已有缓存解析结果；有效快照仍受当前定义校验、修订锁和幂等协议约束。

前端当前值启停须核对原目标、递增修订、目标状态及未改变的内容；历史恢复须核对所选历史的模式、启用状态和明文内容，保护内容按服务端隐藏协议核对状态。失败持续提示“操作未确认”，重试保留原操作、原当前值修订和请求编码，不能因刷新后状态已变化而把停用重试变成启用。历史查询缓存按参数、租户和工作上下文隔离，记录的目标和操作信息未确认时不展示为有效列表；缺失快照标注“未返回”，不补成 `null`。快照字段、可见目标或作用域不完整时禁用对应恢复入口并显示原因。恢复提交期间禁止关闭弹窗，切换上下文后的迟到响应不写入当前缓存或发布成功提示。

## 6. 接口与前端

管理接口位于 `/api/platform/configuration`，包含：

- 分类目录的查询、创建和更新；
- 参数定义的筛选、详情、创建、更新和启停；
- 作用域当前值的新增、更新和启停；
- 定义和值的追加式变更记录查询及值快照人工恢复；
- 按当前租户、用户、机构、科室和附加上下文解析最终值。

前端 `/settings/parameters` 提供参数目录、定义策略、当前值、分类和变更记录的一体化管理。页面选项从系统枚举目录读取；返回字段使用 `sdParam...` 命名，由 JSON 序列化层自动补充 `Text` 字段，避免前端重复维护中文枚举映射。

详情读取及写入响应进入缓存前必须核对参数标识、修订号、类型与控件、安全策略、布尔开关、作用域集合和当前值事实。缺失字段不得套用新建参数的默认选项；跨参数或跨租户内容、重复作用域、内容与模式不一致以及无效 JSON 均作为未确认数据处理。明文内容保留原始 JSON 文本，保护内容遵循服务端遮蔽协议。失败时隐藏详情操作，刷新失败保留已有编辑草稿并禁用提交，重新确认后恢复操作。明确返回的空作用域集合、未知依赖预览和历史 Schema 的人工修复入口继续保留；明文默认值或示例值标记为存在但正文缺失时，由编辑器要求重新确认或明确替换，不能静默清空。这些读取校验不替代具体写入命令的结果核对。

参数相关系统枚举包括 `PARAM_SCOPE_TYPE`、`PARAM_VALUE_TYPE`、`PARAM_CONTROL_TYPE`、`PARAM_CONFIG_TYPE`、`PARAM_SENSITIVITY`、`PARAM_DISPLAY_POLICY`、`PARAM_STATUS`、`PARAM_VALUE_MODE`、`PARAM_CHANGE_TYPE` 和 `PARAM_CHANGE_TARGET_TYPE`。以上 10 组枚举均作为平台级系统托管字典持久化，管理页可统一查看，但只能随代码和 Flyway 迁移调整。

## 7. 业务接入要求

- 业务模块只注入 `ConfigurationDirectory`，不得访问参数 Repository 或自行缓存；
- 每个新参数必须登记分类、配置属性、值类型、缺值行为、允许作用域、继承、缓存、敏感与展示策略；
- 业务调用应传递真实上下文，不得用常量伪造机构、科室或用户；
- 关键业务决定需要在业务事实中留存最终值或来源修订；
- 集群部署前完成跨节点缓存失效；接入真实数据前完成参数管理权限与平台级值管理的 IAM 策略。
