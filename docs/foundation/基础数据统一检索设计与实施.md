# 基础数据统一检索设计与实施

## 1. 目标与边界

本方案统一诊断、通用药品、药品产品和诊疗项目的中文名称及简码检索，解决各模块分别维护拼音字段、前端本地过滤和短查询结果不一致的问题。

统一的是检索投影、简码生成、个人检索偏好和远程查询协议，不统一不同业务场景的准入规则：

- `MasterDataSearchDirectory` 负责从名称或简码得到基础数据目标标识。
- 临床开立继续校验机构采用、可开立、可执行、有效期等临床条件。
- `ProcurementCatalogDirectory` 继续校验供应商协议、可采购、库存站点和业务日期等采购条件。
- 搜索投影不能绕过业务目录直接返回可操作对象。

## 2. 物理模型

检索投影表使用 `RHN_BD_SEARCH_ENTRY`。一行代表一个可独立命中的名称，不代表一个简码词项。

主键和来源定位：

- `ID_SEARCH_ENTRY`：检索条目主键。
- `SD_SCOPE_TYPE + ID_SCOPE`：产品、租户或机构作用域。
- `SD_TARGET_TYPE + ID_TARGET`：概念、通用药品或目录项目。
- `CD_SOURCE_KEY`：来源字段稳定键，用于幂等覆盖和删除旧投影。
- 唯一约束为作用域、目标和来源键组合。

名称与简码：

- `NA_SEARCH`：标准化后的中文或原始检索名称。
- `CD_PINYIN`：拼音首字母简码，不保存完整拼音。
- `CD_WUBI`：五笔 86 首码。
- `CD_MNEMONIC`：人工维护或外部导入的助记码。
- `SD_NAME_TYPE`：标准名、简称、别名、商品名或机构本地名。
- `FG_PRIMARY`：是否主名称，用于同等匹配条件下排序。
- `CD_GEN_VER`：简码生成器版本，用于字典升级后的可控重建。

该模型是半宽表：同一个名称的拼音、五笔和助记码存放在同一行；别名、商品名和机构本地名因为是 1:N 关系，分别成行。

不采用以下结构：

- 不按拼音、五笔、助记码分别成行，避免按简码类型放大数据量。
- 不把多个别名放入 `ALIAS_1...ALIAS_N` 或 JSON，避免无法独立索引和无限扩列。
- 不将临床准入、供应商协议或库存状态冗余进公共检索表。

## 3. 数据量控制

投影行数按“当前可检索名称数”计算，而不是按简码类型计算：

```text
总行数约等于：标准名 + 有效简称 + 有效别名 + 有效商品名 + 当前机构本地名
```

控制规则：

- 只保留当前有效且可检索的名称，停用和过期记录不进入在线投影。
- 机构目录历史保留在 `RHN_BD_ORG_CATALOG_ITEM`，检索投影只保留每个“机构 + 目录项目”的当前解析结果。
- 机构本地名使用稳定来源键 `ORG_CATALOG_ITEM:CURRENT`，版本替代时覆盖同一条投影。
- 全量重建按批次读取和刷新，不一次性加载全部源表及投影表。
- 全量重建默认不随应用启动执行，只能通过显式配置在初始化或维护窗口启用。
- 每日只刷新当天生效和昨日失效的数据，不执行每日全量重建。
- 重建结束后清理已删除源数据对应的孤儿投影。

当单租户或全库进入千万级投影时，再根据真实执行计划评估租户分区、索引压缩或独立搜索服务；当前模型不预先引入搜索中间件。

## 4. 简码生成规则

- 中文名称标准化后生成大写拼音首字母，例如“黄芪”生成 `HQ`。
- 使用随版本发布的五笔 86 字典生成大写首码，例如“黄芪”生成 `AA`。
- 非中文字符按统一标准化规则保留，不生成完整拼音字段。
- 自定义助记码优先使用基础数据来源字段，写入前执行同一标准化规则。
- 生成规则变化必须同步提升 `CD_GEN_VER`，并通过受控重建更新存量投影。

## 5. 个人检索偏好

统一参数：

- `master-data.search.input-mode`：`PINYIN`、`WUBI`、`ALL`。
- `master-data.search.match-mode`：`PREFIX`、`CONTAINS`、`SIMILARITY`。
- `master-data.search.similarity-threshold`：相似度最低阈值。
- `master-data.search.result-limit`：一次检索返回的目标数量上限。

参数按照平台、租户、机构、科室、用户层级解析。非中文输入根据个人输入模式匹配简码；中文输入匹配标准化名称。编码、条码等明确业务标识仍由业务仓储采用精确或左匹配，不走相似度规则。

短查询受结果上限约束，`h` 的第一页不是所有 `hq` 结果的超集；前端必须使用当前完整输入重新发起远程查询，不能在上一页结果上二次过滤。

## 6. 查询与业务目录

查询分两阶段执行：

1. 场景服务先确定业务候选集，或允许检索服务产生目标标识集合。
2. 业务仓储使用目标标识集合、状态、有效期和场景条件完成分页查询。

临床与采购的差异必须保留：

- 临床开立关注机构采用、可开立、可执行、处方或医嘱规则。
- 药房发药关注可发药产品、库存站点、处方明细和库存路由。
- 采购入库关注供应商供货关系、协议有效期、可采购标志和采购订单剩余量。

因此不使用一个 `ClinicalResourceSearchDirectory` 承担全部场景。公共检索目录只负责文本召回，`ProcurementCatalogDirectory` 等场景目录负责业务准入。

## 7. 同步与运维

基础数据新增、修改、状态变更和别名变更后，在同一业务事务内增量同步对应目标。机构目录新增、替代、停用后重新解析该机构目录项目的当前版本。

配置项：

- `RHN_SEARCH_PROJECTION_REBUILD_ON_STARTUP`：默认 `false`；仅初始化或维护窗口显式开启。
- `RHN_SEARCH_PROJECTION_REBUILD_BATCH_SIZE`：默认 `500`，允许范围由服务限制在 50 到 2000。
- `RHN_SEARCH_PROJECTION_EFFECTIVE_REFRESH_ENABLED`：默认 `true`。
- `RHN_SEARCH_PROJECTION_EFFECTIVE_REFRESH_CRON`：默认每天 `00:05`。
- `RHN_SEARCH_PROJECTION_EFFECTIVE_REFRESH_ZONE`：默认 `Asia/Shanghai`。

全量重建日志输出期望条目、创建、更新和删除数量。发生生成器版本升级、首次上线或投影完整性异常时执行受控重建；日常运行依靠事务内增量同步和有效期边界任务。

## 8. 验收口径

- “黄芪”能够通过 `hq` 拼音首字母检索，通过 `aa` 五笔首码检索。
- 同一名称的拼音、五笔和助记码位于同一投影行。
- 停用、未生效、已过期名称不出现在在线投影。
- 同一机构目录项目存在多个历史版本时，投影中最多只有一个当前本地名称。
- 版本生效日切换后，稳定来源键不变且名称被覆盖，不新增历史行。
- 诊断、药品和诊疗项目使用统一远程检索规则。
- 临床和采购使用各自业务目录校验，不能因为文本匹配而绕过准入条件。
- 前端查询由回车或查询按钮触发，不依赖本地列表二次过滤。
