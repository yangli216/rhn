# 门诊接诊归属与挂号复用规则

## 目标

统一门诊医生站的患者可见范围、实际接诊归属与挂号复用判断。该规则适用于普通门诊和专家门诊；急诊应使用独立流程，不直接套用本规则。

## 医生站数据视角

| 视角 | 待诊归属 | 已接诊归属 | 用途 |
| --- | --- | --- | --- |
| 本人 | 未开始就诊时按排班医生 ID；已开始后按实际接诊账号 | 按实际接诊账号 | 医生日常接诊，默认视角 |
| 本科室 | 当前工作上下文中的科室 | 当前工作上下文中的科室 | 科内代诊、护士分诊和科主任协同 |
| 本院 | 当前工作上下文中的机构 | 当前工作上下文中的机构 | 医务管理、门诊部全局协调 |

归属判断不得依赖医生姓名。姓名会重名、变更，也无法表达代诊事实。就诊开始后应以 Encounter 的实际接诊账号为准；开始前只能使用挂号排班上的执业人员 ID。

“本院”是数据权限边界，不是普通业务参数。是否允许使用本院视角应由角色的数据范围（机构级或租户级）控制，并在服务端校验；界面隐藏或禁用只能改善体验，不能代替鉴权。

已接诊记录为只读历史入口，只提供查看病历，不允许重新叫号、过号、恢复接诊或再次接诊。已诊毕就诊如需继续诊疗，应创建新的就诊；唯一例外是“取消诊毕”（`POST /api/encounters/{id}/cancel-completion`），用于诊毕后更正诊断、病历或医嘱：

- 仅限原接诊医生，必须填写原因；就诊状态由 `COMPLETED` 回到 `IN_PROGRESS`，排队号票由已结束回到服务中，并写入 `COMPLETED → IN_PROGRESS` 状态事件、新的工作会话和 `ENCOUNTER_COMPLETION_CANCELLED` 事件，原诊毕检查、状态事件和已签署病历版本不删除。
- 同一居民在同科室已有进行中的就诊时拒绝取消（`ENCOUNTER_ACTIVE_DUPLICATE`），避免两次就诊并存。
- 已签署病历仍不可直接覆盖，诊断变更须先发起病历更正再保存，重新签署后走完整的诊毕准入。
- 取消诊毕不撤销已发生的收费、发药或检验检查；调整已履约医嘱须走退费、退药或医技流程，不能靠本功能绕过。

## 对截图描述的评估

截图提出的“同科可协调其他医生、专家号换专家更严格、已诊毕后重新挂号”方向合理，但“隔天必重新挂号”和“跨科一律重新挂号”不应写成固定规则。挂号是否可复用应同时判断：

1. 挂号是否仍在有效期内。系统已有 `outpatient.registration.validity.days` 和 `outpatient.registration.validity.cutoff-mode`。
2. 当前就诊是否已经诊毕、取消或终止。已诊毕必须创建新就诊。
3. 目标医生是否同科，是否属于同一服务或号别。
4. 是否从普通号更换为专家号，或从一位专家更换为另一位专家。
5. 本次处理是正式转科、同科代诊，还是仅查看报告。

推荐决策基线：

| 场景 | 默认处理 | 可配置点 |
| --- | --- | --- |
| 有效期内、未诊毕、同科普通号换医生 | 允许授权人员代诊，记录原排班医生和实际接诊医生 | 同科代诊策略 |
| 有效期内、未诊毕、专家临时由普通医生代诊 | 默认禁止；确需代诊时应确认患者并留痕 | 专家号替诊策略 |
| 有效期内、未诊毕、更换另一位专家 | 默认重新挂目标专家号 | 专家号改挂策略 |
| 有效期内、未诊毕、跨科 | 默认走转科；无有效转科关系时重新挂号 | 跨科处理策略 |
| 超过挂号有效期 | 重新挂号 | 现有有效期参数 |
| 已诊毕后再次就诊或复查 | 创建新挂号和新就诊 | 不允许重开已完成就诊 |
| 仅由同科医生协助查看已出报告，不形成新诊疗 | 可只读查看，不改变接诊归属 | 病历访问权限 |

## 参数与权限边界

建议在业务服务真正消费规则时再建立参数定义，避免产生只展示、不生效的“空参数”。推荐参数模型如下：

| 建议参数 | 值域示例 | 缺省值 | 作用层级 |
| --- | --- | --- | --- |
| `outpatient.reception.same-department-substitution-policy` | `ALLOW_WITH_AUDIT` / `REQUIRE_APPROVAL` / `DENY` | `ALLOW_WITH_AUDIT` | 机构，可被科室覆盖 |
| `outpatient.reception.specialist-substitution-policy` | `PATIENT_CONFIRM_AND_AUDIT` / `REBOOK` / `DENY` | `REBOOK` | 机构 |
| `outpatient.reception.cross-department-policy` | `REFERRAL_ONLY` / `REBOOK` | `REFERRAL_ONLY` | 机构 |
| `outpatient.reception.completed-follow-up-policy` | `NEW_ENCOUNTER_REQUIRED` | `NEW_ENCOUNTER_REQUIRED` | 系统固定或机构只读 |

以下内容不应参数化：

- 本人、本科室、本院的数据访问权，必须走角色和数据范围授权。
- 已完成病历是否可被任意修改，必须受病历签署、修订和审计规则约束。
- 操作日志是否记录，代诊、改挂、转科等关键动作必须强制审计。

## 审计要求

发生代诊、改挂或转科时，至少记录患者、原挂号、原排班医生、实际接诊医生、原科室、目标科室、操作人、原因、患者确认方式和时间。历史记录中同时展示“挂号医生”和“实际接诊医生”，避免归属混淆。
