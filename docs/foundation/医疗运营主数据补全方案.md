# 医疗运营主数据补全方案

## 1. 建设目标

本轮在既有药品、诊疗项目、字典、术语和扩展属性能力上，补齐医疗机构日常运营需要的四类基础数据：检验/检查执行配置、项目组套、医用耗材与器械、统一计量单位与换算。

设计原则如下：

- 目录主档与业务扩展分层，统一复用 `catalog_items` 的编码、状态、生效期、开立/收费/库存属性。
- 字典承载稳定枚举，业务表承载有生命周期、关联关系、约束和审计要求的数据。
- 组织级差异使用组织范围配置，不复制租户主档。
- 标准术语映射可渐进完善，不阻塞本地业务编码先落地。
- 所有修改保留版本号和审计字段，更新接口执行乐观锁校验。

## 2. 能力范围

### 2.1 检验标本与检查部位

- 检验项目维护检验方法、报告时长、空腹要求、POCT 属性和采集说明。
- 一个检验项目可配置多个标本、采集容器、最小采集量、默认/必需规则和排序。
- 同一检验项目只能有一个有效默认标本；标本、排序号不能重复。
- 检查项目维护检查类型、检查前准备、是否必须选部位、是否允许多部位及上限。
- 检查项目可维护本地部位/方式变体、互认编码和排序，后续可关联标准术语概念。
- 多部位计价支持主项只计一次、主项按部位计费、基础部位加固定金额、基础部位加收费项目四种模式，并可限制最大计费部位数。
- 检查附件项目支持始终带出、按需选择、多部位触发，以及固定数量、每部位、每超出部位三种数量依据。

检查计价规则只生成收费行和数量，不复制机构价格；实际金额继续由目录采纳与有效价表解析。

检验标本配置进一步承担采集分管规则：

- `SEPARATE`：项目独立分管。
- `SHARE`：相同分管编码、标本和容器的项目共用试管。
- `BY_TEST_COUNT`：在共管基础上按每管最大项目数自动拆管。
- 试管加收支持每管加收或超过包含管数后加收，加收项目引用统一诊疗目录。

标本和容器引用统一字典项 ID，避免字典名称调整后业务配置失联；接口返回时同时解析编码和名称。

### 2.2 LIS/PACS 组套与组合项目

`item_groups` 保存组套主档，`item_group_members` 保存成员及数量、排序、必选属性。

支持以下类型：

- `LIS`：成员只能是检验项目。
- `PACS`：成员只能是检查项目。
- `ORDER_SET`：常用组合开立项目。
- `PACKAGE`：业务项目包。

组套可为租户通用或限定组织，开立时按成员引用展开，不复制项目主档。成员状态、适用期和组织可用性仍需由开立业务二次校验。

### 2.3 医用耗材与器械

耗材/器械作为统一目录项的业务扩展，新增 `SUPPLY.CONSUMABLE` 和 `SUPPLY.DEVICE` 两个项目类型，并由 `supply_items` 保存医疗物资专属字段：

- UDI-DI、通用编码/名称、型号、规格、材质类型。
- 医疗器械 I/II/III 分类。
- 注册证号、注册名称、注册人、注册有效期。
- 厂商、结构描述、适用范围和使用说明。
- 高值、植入、介入、无菌、一次性使用属性。

耗材可进入既有目录启停、机构采纳、定价、包装和库存链路。植入类必须同时标记为高值；UDI-DI、注册证号和目录编码执行租户内唯一性校验。

### 2.4 统一计量与换算

`unit_definitions` 按计数、质量、体积、时间、长度、面积、活度、温度等维度维护单位、显示符号和小数精度。

`unit_conversions` 同时支持：

- 全局换算，例如 L→mL、g→mg、h→min。
- 项目专属换算，例如某耗材 1 BOX→50 EA。
- 生效期管理和状态管理。
- 同维度校验、重叠生效期校验。
- 多跳换算和反向换算；同一单位对存在项目专属规则时优先于全局规则。
- 偏移换算，满足温度等仿射换算场景。

业务交易应保存“原始数量+原始单位”，换算结果用于库存扣减、收费数量或展示，避免重复换算造成精度损失。

## 3. 数据库变更

本轮迁移为 `V46__medical_operations_master_data.sql`，H2 与 Oracle 脚本同步维护，主要新增：

- `supply_items`
- `item_groups`
- `item_group_members`
- `unit_definitions`
- `unit_conversions`

并为既有 `laboratory_services`、`laboratory_service_specimens`、`examination_services`、`service_variants` 补充版本和审计字段。

增量迁移 `V47__diagnostic_collection_and_charge_rules.sql` 新增检查附件表，并扩展检查计价和检验分管/试管加收字段；H2 与 Oracle 脚本保持同步。

## 4. 接口契约

统一前缀：`/api/platform/master-data/operations`

| 资源 | 主要能力 |
| --- | --- |
| `/services/{id}/clinical-configuration` | 查询检验/检查执行配置 |
| `/services/{id}/laboratory-profile` | 修改检验配置 |
| `/services/{id}/specimens` | 新增、修改、启停标本配置 |
| `/services/{id}/examination-profile` | 修改检查配置 |
| `/services/{id}/variants` | 新增、修改检查部位/方式 |
| `/services/{id}/examination-attachments` | 新增、修改检查附件项目 |
| `/services/{id}/examination-charge-plan` | 按部位与附件选择解析检查收费行 |
| `/laboratory-tube-plan` | 按检验申请解析分管、试管数量及加收行 |
| `/supplies` | 查询、新增、修改耗材/器械 |
| `/item-groups` | 查询、新增、修改项目组套 |
| `/units` | 查询、新增、修改单位 |
| `/unit-conversions` | 查询、新增、修改换算规则 |
| `/unit-conversions/convert` | 按日期和可选项目执行换算试算 |

接口版本已提升至 `1.23.0`。

## 5. 管理端交互

基础数据管理新增“运营主数据”入口，采用 PC 端工作区布局，包含四个二级区域：

- 标本与部位：先检索诊疗项目，再维护执行配置。
- 项目组套：按组套类型筛选合法成员。
- 耗材与器械：维护主档、UDI、注册证和经营属性。
- 计量与换算：并列查看单位与规则，支持全局/项目专属规则和在线试算。

所有检索型下拉框沿用系统统一组件，选项左侧显示名称、右侧浅色显示编码，并支持名称、编码和拼音检索。

## 6. 业务接入约定

后续业务功能不应自行维护标本、组套、耗材或单位副本，应按以下方式消费：

1. 开立检验/检查申请时读取有效执行配置，并保存当时选择的标本或部位变体标识。
2. 展开组套时记录组套 ID、版本及展开后的项目明细，便于追溯历史规则。
3. 耗材申领、入库、收费和使用登记统一引用目录项 ID；UDI 实例追溯属于库存批次/序列层，不回写主档。
4. 数量换算统一调用换算服务，传入业务日期和目录项 ID；不得在各业务模块硬编码包装倍率。
5. 对外交换优先使用标准术语映射和统一单位编码，本地编码作为机构内稳定键保留。

## 7. 后续完善方向

建议按运营价值继续推进：

1. 将标本/容器、检查部位与 SNOMED CT、LOINC 等标准体系映射，并增加映射完整度看板。
2. 增加组套版本发布、复制、批量调价及科室常用组套授权。
3. 接入国家药监局器械数据，支持注册证/UDI 导入、到期预警和变更比对。
4. 将项目专属单位换算接入包装、库存、收费和采购模块，建立端到端数量一致性测试。
5. 增加主数据审批、批量导入校验、变更影响分析和下游同步事件。
6. 为停用、过期、孤立映射、重复编码及规则冲突建立日常数据质量任务。

本轮完成后，系统已具备基层医疗机构日常建档和运营所需的核心主数据底座；高等级医院或集团化场景仍需在标准术语覆盖、器械监管数据、组套版本治理和跨机构分发方面继续深化。
