# 字典字段自动翻译设计

## 1. 目标

列表、详情和嵌套对象中的字典代码统一在 HTTP JSON 序列化阶段补充显示文本，业务查询不再逐字段关联字典表，业务服务也不再重复编写代码到名称的转换逻辑。

该能力只补充展示字段，不改变领域对象保存的稳定代码，也不参与业务判断、数据校验或字典选项加载。

## 2. 响应字段约定

需要自动翻译的出参字段使用 `sd<字典编码的大驼峰形式>`：

| 字典编码 | 代码字段 | 自动生成字段 |
|---|---|---|
| `DICT_STATUS` | `sdDictStatus` | `sdDictStatusText` |
| `APPOINTMENT_SOURCE` | `sdAppointmentSource` | `sdAppointmentSourceText` |
| `CONTACT_RELATION_TYPE` | `sdContactRelationType` | `sdContactRelationTypeText` |

底座使用 Hutool 命名转换从 `sdXxx` 推导大写下划线字典编码。无法通过名称准确推导时，在 Java record component、字段或 getter 上使用 `@DictionaryBinding("实际字典编码")` 显式绑定。

规则如下：

- 约定只用于响应 DTO；请求命令字段继续使用清晰的业务名称，不要求增加 `sd` 前缀；
- `sdXxxText` 是只读派生字段，业务 DTO 不得自行重复声明；启动或序列化发现冲突时立即失败；
- 原值为 `null` 时文本也为 `null`；原值为数组或集合时生成顺序一致的文本数组；
- 找不到字典或字典项时，文本回退为原代码，保证前端仍可识别异常数据而不是显示空白；
- 业务判断必须使用代码字段，不得使用 `Text` 字段。

## 3. 处理流程

控制器返回 JSON 对象后，底座先遍历响应对象图，按字典编码归并本次响应实际使用的代码；随后一次性解析各字典，并在 Jackson 写出属性时紧邻原字段补充 `Text` 字段。DTO 本身不会被修改，也不要求继承公共父类。

系统枚举直接从只读内存目录解析。普通字典按“租户覆盖优先、平台字典回退”的规则解析，并以 `租户 ID + 字典编码` 为键缓存完整的代码文本映射；同一响应内无逐行或逐字段数据库查询。

普通字典翻译目录包含已停用字典项，以保证历史数据仍能正确显示；表单和筛选项仍必须调用 `resolveActiveItems`，只提供当前启用项。

## 4. 缓存与一致性

缓存参数位于 `rhn.dictionary.translation.cache`：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `maximum-size` | `10000` | 最大租户字典缓存条目数 |
| `maximum-ttl` | `PT5M` | 最长写入后过期时间 |

字典定义或字典项事务提交成功后主动失效缓存：租户字典只失效当前租户和编码，平台字典失效该编码的所有租户副本。主动失效保证正常维护后立即生效，TTL 负责兜底处理非标准写入或跨进程通知暂未覆盖的场景。

当前为单体部署，使用进程内 Caffeine 缓存。演进为多实例后，应在保留本地缓存的同时通过事务后事件或消息广播缓存失效，不能单纯增大 TTL。

## 5. 接口契约和前端使用

OpenAPI 生成阶段同步增加 `sdXxxText`，标记为 `readOnly`、可空字符串，并写明对应字典编码；前端契约由 OpenAPI 自动生成，不手写重复类型。

前端展示直接读取 `sdXxxText`，筛选值、提交值和状态判断读取 `sdXxx`。系统枚举和普通字典的选项接口仍用于下拉框，不能用响应翻译能力替代可选值校验。

示例响应：

```json
{
  "id": "362387869790210",
  "sdDictScopeType": "TENANT",
  "sdDictScopeTypeText": "租户私有",
  "sdDictStatus": "ACTIVE",
  "sdDictStatusText": "已启用"
}
```

## 6. 安全和适用边界

自动翻译仅处理 `com.rhn` 应用响应对象中的字符串、枚举及其集合，并只在兼容 JSON 的 HTTP 响应中启用。原始 `JsonNode`、文件、字节流和非 JSON 响应不参与遍历。

签名原文、验签报文、密码证据、审计快照和对外交换合同必须保持确定的原始结构：不得在这类 DTO 中使用保留的 `sdXxx` 命名，签名与证据持久化继续使用底层 `JsonCodec`，该离线序列化路径不会注入文本字段。若对外协议本身需要显示文本，应在适配层显式映射，不能依赖内部展示约定。

## 7. 开发门禁

新增字典字段时依次确认：

1. 该值确实属于系统枚举或普通字典，不是主数据、参数或版本化术语；
2. 字典编码已按命名规范登记，响应字段能准确推导或已添加 `@DictionaryBinding`；
3. OpenAPI 中已生成对应只读 `Text` 字段，前端未保留中文硬编码；
4. 集成测试同时断言代码和文本，并至少覆盖未知值或历史停用值策略；
5. 涉及签名、证据或外部交换时，确认该响应明确排除自动注入。
