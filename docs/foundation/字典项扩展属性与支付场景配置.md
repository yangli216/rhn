# 字典项扩展属性与支付场景配置

## 建设结论

本轮在普通字典之上增加“属性定义 + 分层属性值”能力，不为支付方式单独增加业务配置表。支付方式、支付使用场景仍是普通字典，适用关系由字典项扩展属性表达，后续渠道能力、终端支持、打印方式等同类需求可复用。

核心表：

- `dictionary_attribute_definitions`：定义属性编码、数据类型、单/多值、引用字典、必填性、是否可检索及允许自定义的最深层级。
- `dictionary_item_attribute_values`：按字典项和作用域保存实际值；多值采用多行存储；显式空集采用 `EXPLICIT_EMPTY` 标记行。

## 分层与覆盖规则

解析顺序固定为：科室 → 机构 → 租户 → 全局。找到第一组有效配置即停止继续向上解析；显式空集同样会停止继承。

属性只定义一个“可配置最深层级”：

- `PLATFORM`：仅全局。
- `TENANT`：全局、租户。
- `ORGANIZATION`：全局、租户、机构。
- `DEPARTMENT`：全局、租户、机构、科室。

覆盖策略仅保留：

- `ANY`：下级可自由覆盖，可增加、删除或完全替换上级值。
- `NO_OVERRIDE`：只允许全局配置。

不再提供“下级只能收窄上级范围”的策略，也不执行子集校验。

## 支付方式示例

基础字典：

- `PAY_METHOD`：现金、银行卡、微信、支付宝、其他。
- `PAY_USE_SCENE`：诊间结算、收费处、自助终端。

医保不属于支付方式。自费、医保等属于结算责任类型；医保基金、个人账户属于结算资金来源，
医保结算完成后的个人自付部分仍须从 `PAY_METHOD` 选择现金、银行卡或数字支付方式。

属性定义：

- 编码：`AVAILABLE_SCENE`
- 类型：`DICT_REF`
- 基数：`MULTIPLE`
- 引用字典：`PAY_USE_SCENE`
- 可配置最深层级：`ORGANIZATION`
- 覆盖策略：`ANY`
- 必填、可检索

机构可以将现金的全局配置从“诊间结算、收费处”自由覆盖为“诊间结算、收费处、自助终端”，也可以配置为空集，或删除本层配置恢复继承。

## 业务接入

通用筛选接口：

`GET /api/platform/dictionaries/resolve/{dictionaryCode}/applicable?attributeCode={attributeCode}&referenceCode={referenceCode}`

收费工作台通过 `PAY_METHOD / AVAILABLE_SCENE / CASHIER` 取得当前工作上下文可用的支付方式。收款提交携带 `paymentSceneCode`，后端使用同一解析器再次校验；缺省场景按 `CASHIER` 兼容既有调用。

管理端在字典详情提供：

- 扩展属性新增、编辑、启停。
- 属性类型、基数、引用值域、最深自定义层级及覆盖策略配置。
- 按字典项维护当前作用域值、显式空集及恢复继承。
- 属性定义和属性值变化写入字典追加式审计日志，并纳入字典修订号并发控制。

接口契约版本：`1.24.0`。
