# 字典与参数底座接入指南

## 1. 目的

本指南是后续业务模块使用字典和参数能力的统一入口。门诊、药事、收费、公共卫生、家医、接口等模块不得复制字典表、参数表、中文映射、继承算法或本地缓存。业务模块只依赖底座公开 API，并继续拥有自己的业务规则和事实数据。

## 2. 先判断数据属于哪类能力

| 需求特征 | 应使用 | 示例 | 不应使用 |
|---|---|---|---|
| 代码分支、数据库约束依赖，集合封闭且运行期不可修改 | 系统枚举 | 就诊状态、底座状态、并发策略 | 可在线维护的普通字典 |
| 平台或租户可维护的扁平选项，只解释当前可选值 | 普通字典 | 预约来源、联系人关系、非标准展示分类 | Java 枚举、参数、主数据 |
| 有标准来源、版本、有效期、值域或映射 | 术语服务 | 诊断、药品标准编码、标准值域 | 普通字典 |
| 同一行为需要按租户、机构、科室、用户或产品上下文取不同值 | 参数中心 | 超时时间、默认打印模板、开关、阈值 | 业务表中的事实或状态 |
| 有独立属性、关系、状态迁移和生命周期 | 领域模型或主数据 | 药品、科室、收费项目、处方状态 | 字典或参数 |
| 需要发布版本、历史时点解释或严格规则计算 | 规则/流程/版本化配置领域 | 医保规则、临床规则、审批流程 | 当前值参数 |

拿不准时先回答三个问题：业务人员是否需要不停机维护选项；值是否随执行上下文变化；历史业务是否必须按当时版本重新解释。不能因为建模方便就把领域对象降格为字典或参数。

## 3. 普通字典接入

### 3.1 后端读取和校验

业务模块只注入 `platform.dictionary.api.DictionaryDirectory`：

```java
List<DictionaryValue> sources = dictionaryDirectory.resolveActiveItems(
        context.tenantId(), "APPOINTMENT_SOURCE");

boolean allowed = sources.stream()
        .anyMatch(item -> item.code().equals(command.sourceCode()));
```

- 新增或修改业务数据时，使用 `resolveActiveItems` 校验并提供当前可选项；它只返回启用项，并按“租户同编码字典优先、平台字典回退”解析。
- 展示历史数据时通常使用统一 JSON 字典翻译；确有非 HTTP 投影需求时，才使用 `resolveItemTexts`，它包含已停用项。
- 系统枚举通过 `platform.dictionary.api.SystemEnumDirectory` 读取。只有封闭、与代码约束完全一致的集合才能登记为系统枚举。
- 业务表只保存稳定的字典项编码，不保存名称，不以字典记录 ID 作为业务值。
- 业务模块不得访问字典 Repository、字典表或管理接口，也不得自行实现租户回退和缓存。
- 字典分类只服务管理端组织与治理。业务模块按稳定字典编码解析，不依赖分类 ID、分类路径或分类名称进行业务判断。

### 3.2 响应文本翻译

需要显示字典名称的响应字段优先命名为 `sd<字典编码大驼峰>`：

```java
public record AppointmentResponse(
        Long id,
        String sdAppointmentSource
) {
}
```

JSON 序列化会自动增加只读的 `sdAppointmentSourceText`。DTO 不得手写同名 `Text` 字段，业务服务也不得逐条查询字典或拼装名称。字段名无法准确表达字典编码时使用显式绑定：

```java
public record AppointmentResponse(
        Long id,
        @DictionaryBinding("APPOINTMENT_SOURCE") String source
) {
}
```

此时序列化结果增加 `sourceText`。绑定字段进入 OpenAPI 后，生成的前端类型也会包含只读文本字段。

### 3.3 前端选项和展示

表单统一使用共享 `DictionarySelect`，提交字典项编码：

```tsx
<DictionarySelect
  api={api.dictionaries}
  dictionaryCode="APPOINTMENT_SOURCE"
  value={sourceCode}
  onChange={setSourceCode}
/>
```

- 下拉选项使用 `DictionarySelect` 或 `api.dictionaries.resolve(code)`，不得写死中文数组。
- 列表和详情展示服务端返回的 `sdXxxText`，筛选、提交和业务判断使用 `sdXxx`。
- 历史停用项仍可显示，但不能继续出现在新增数据的可选项中。
- 字典管理 API 只供管理页面使用，业务页面不得通过管理列表拼装选项。

## 4. 参数中心接入

### 4.1 定义参数

新增参数前必须登记并评审以下内容：

完整的分类目录、命名、定义字段和评审规则见[参数分类与参数定义规范](参数分类与参数定义规范.md)。

1. 使用小写点分段稳定键，例如 `outpatient.registration.timeout`；
2. 分类及 `SYSTEM`/`BUSINESS` 配置属性；
3. 值类型、控件、JSON Schema、默认值和单位；
4. 允许作用域，以及是否允许继承、缓存和显式空值；
5. 没有任何有效值时是必须报错，还是由定义默认值兜底；
6. 敏感级别和展示策略；`SECRET` 只能保存外部密钥引用；
7. 若控件为 `SELECT`，绑定的系统枚举或普通字典编码。

参数键创建后不得修改或复用。参数只表达可运营差异，不能控制授权边界、替代状态机、承载临床规则版本或保存业务事实。

### 4.2 后端解析

业务模块只注入 `platform.configuration.api.ConfigurationDirectory`，传入真实执行上下文：

```java
ConfigurationValue timeout = configurationDirectory.resolveCurrent(
        context.tenantId(),
        context.subjectId(),
        organizationId,
        departmentId,
        "RHN",
        "OUTPATIENT",
        environmentCode,
        "outpatient.registration.timeout");

long seconds = timeout.value().asLong();
```

- 没有产品、模块、环境上下文时使用五参数重载，不用空字符串或虚构 ID 占位。
- 业务只消费已经解析出的 `value` 或 `secretReference`，不得根据 `valueMode` 再实现一遍继承。
- 定义没有默认值且当前上下文无有效值时，底座返回 `PARAMETER_VALUE_NOT_FOUND`；业务不得在代码里偷偷加入第二套默认值。
- 参数值必须按返回的 `valueType` 和已登记契约读取。对业务关键参数，建议在模块内封装成有明确单位和类型的适配器，避免调用点散落 JSON 取值。
- `SECRET` 的 `secretReference` 只能交给密钥/凭据适配器解析，禁止返回前端、写日志或转换成普通参数值。
- 业务模块不得访问参数 Repository、参数表、管理接口或自行缓存；继承顺序、租户隔离和缓存失效全部由参数底座负责。

### 4.3 业务事实与前端

- 参数适合决定“现在应怎样执行”，不等于历史事实。收费、签署、处方、消息发送等需要审计或重放的关键动作，应把最终采用的值、参数键及必要的来源修订写入业务事实或证据原文。
- 关键业务判断应在后端完成，前端接收后端计算后的业务结果，不得仅靠页面参数控制安全、收费或临床行为。
- 纯展示或非关键交互确需读取参数时，应先在 `frontend/src/shared/api/configurationApi.ts` 增加有 OpenAPI 类型约束的解析方法，再通过 React Query 使用；不得在页面直接拼管理接口或复制参数解析逻辑。
- 参数管理页面 `/settings/parameters` 只负责维护定义、当前值和变更记录，不是业务模块的运行时数据源。

## 5. 新模块实施顺序

1. 在需求和表结构评审时，按第 2 节完成字典、参数、术语、主数据和业务事实分类。
2. 在[字典与术语命名规范](字典与术语命名规范.md)中登记新编码；复用已有编码时确认语义完全相同。
3. 新建普通字典时选择同作用域分类；分类仅作管理治理，不进入业务数据模型和运行时解析逻辑。
4. 为参数建立定义清单，明确缺值、作用域、继承、缓存和安全策略。
5. 后端只依赖 `platform.dictionary.api`、`platform.configuration.api`，把读取封装在本模块 application 层。
6. 响应按 `sdXxx` 规则声明字典字段；前端复用 `DictionarySelect` 和生成契约。
7. 补充字典有效/停用/租户回退测试，以及参数默认值/覆盖/父级继承/禁止继承/缺值测试。
8. 对跨租户读取、敏感参数泄露、本地重复缓存和历史业务重放进行专项检查。

## 6. 合并前检查

- 没有新增 `Map.of(code, 中文名)`、页面选项常量或重复字典表；
- 没有从业务模块导入字典、参数的 `domain`、`application`、`infrastructure` 或 `web` 包；
- 没有直接查询 `dictionary_*`、`parameter_*` 表；
- 没有把字典名称、参数当前值当作不可变历史事实；
- 没有把权限、业务状态机、临床规则或密钥明文做成参数；
- OpenAPI、前端生成类型、跨租户测试和架构边界测试已经更新。

更完整的实现语义见[普通字典管理设计](普通字典管理设计.md)、[字典字段自动翻译设计](字典字段自动翻译设计.md)、[参数管理设计](参数管理设计.md)和[架构决策-004](../architecture/架构决策-004-分层参数配置.md)。
