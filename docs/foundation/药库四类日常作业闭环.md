# 药库四类日常作业闭环

## 1. 目标与完成口径

本设计覆盖医疗机构药库最常用的四类日常业务：

1. 采购到货 → 收货登记 → 验收 → 批量入库；
2. 科室请领 → 审核 → 拣货 → 出库；
3. 库间调拨 → 调出确认 → 在途 → 调入确认；
4. 盘点建单 → 实盘录入 → 差异审核 → 盈亏调整。

只有同时具备领域状态机、责任人、数据范围、幂等与并发门禁、不可变库存分录、异常分支、接口、界面和自动化验收，才算完成。表中预留状态或页面演示数据不算业务完成。

## 2. 共同约束

- 库房沿用机构科室主数据，业务单据引用科室对应的库存配置，不单独维护库房主数据。
- 所有主单均具有租户、机构、业务科室/库存站点、单号、外部请求码、版本号和创建责任人。
- 单号用于业务检索，`request_code` 用于接口幂等；同一请求码不能用于不同载荷。
- 提交后业务关键字段不可直接覆盖，后续变化通过状态迁移和追加式事件表达。
- 审核人与制单人原则上分离；高风险差异和受控药品必须进入独立复核门禁。
- `inventory_transactions` 是库存数量事实源；申请、审批、验收、拣货和在途本身不改变库存余额。
- 最终过账必须在同一数据库事务内锁定余额、写不可变分录、更新投影并推进单据状态。
- 业务日期必须落在开放库存期间；已关闭期间不得补写或覆盖。
- 失败重试必须返回原结果或明确的幂等冲突，不得重复入账、重复出库或重复调整。
- 每次状态变化写入 `inventory_document_events`，保存前后状态、操作者、发生时间、原因和关联号。

## 3. 采购到货与验收入库

### 3.1 单据

- `suppliers`：供应商主体、许可证和有效期。
- `supplier_supply_items`：供应商可供产品、包装、协议价与供货有效期。
- `purchase_orders` / `purchase_order_lines`：采购订单及行。
- `goods_receipts` / `goods_receipt_lines`：到货验收单及批次行。

### 3.2 状态

- 采购订单：`DRAFT → SUBMITTED → APPROVED → PARTIALLY_RECEIVED → COMPLETED`。
- 到货验收：`RECEIVED → INSPECTING → ACCEPTED/PARTIALLY_ACCEPTED/REJECTED → POSTED`。

### 3.3 过账规则

- 到货数量必须大于零；验收合格量与拒收量之和必须等于实收量。
- 供应商、供应品项、包装和资质必须在业务日期有效。
- 同一采购行累计实收不能超过允许的订单数量和容差。
- 合格数量按批号、效期和收货库位批量入账；拒收数量不进入可用库存。
- 任意一行失败时整张验收单不部分过账。

## 4. 科室请领与出库

### 4.1 单据

- `stock_requisitions` / `stock_requisition_lines`：请领单及申请行。
- `stock_requisition_allocations`：按批次和库位形成的拣货分配。

### 4.2 状态

`DRAFT → SUBMITTED → APPROVED → PICKING → ISSUED`，并允许 `REJECTED/CANCELLED` 终止。

### 4.3 过账规则

- 申请科室必须在当前机构数据范围内，来源库存站点必须为有效药库或药房。
- 审核可调整批准量但不能超过申请量，拒绝必须填写原因。
- 拣货使用 FEFO/FIFO 或明确人工批次，在事务内锁定余额并生成分配。
- 库存不足时整单不进入拣货，不允许默默缩量。
- 出库按分配行扣减库存并消费预留，形成不可变 `ISSUE` 分录。

## 5. 库间调拨

### 5.1 单据

- `stock_transfers` / `stock_transfer_lines`：调拨主单与品项。
- `stock_transfer_allocations`：调出批次、库位、在途量和调入库位。

### 5.2 状态

`DRAFT → SUBMITTED → APPROVED → PICKING → IN_TRANSIT → COMPLETED`，并允许 `REJECTED/CANCELLED` 终止。

### 5.3 过账规则

- 来源和目标库存站点必须不同且属于当前可访问机构范围。
- 调出确认按分配批次扣减来源库存，同时将数量记录为在途，不直接增加目标库存。
- 调入确认必须逐行填写实收量、差异和目标库位；超收不允许直接过账。
- 调入过账保留原批号和效期，在目标站点形成 `TRANSFER` 入账分录。
- 短少、破损等差异必须记录原因，不能通过修改原调出分录抹平。

## 6. 盘点与盈亏调整

### 6.1 单据

- `stock_counts`：盘点范围、快照时间和状态。
- `stock_count_lines`：库位、经营项目、批次、账面量、实盘量与差异。

### 6.2 状态

`DRAFT → COUNTING → SUBMITTED → APPROVED → POSTED`，并允许 `REJECTED/CANCELLED` 终止。

### 6.3 过账规则

- 建单时冻结盘点范围的账面快照；同一站点和范围不能存在重叠的进行中盘点。
- 实盘量必须由盘点人员录入，未盘行不能提交。
- 差异审核人不得与盘点人相同；零差异可以直接确认，高风险差异要求原因和复核证据。
- 过账前再次锁定余额并验证账面版本；盘点期间发生库存变化时必须提示重盘或按政策重算。
- 盈亏只通过 `COUNT` 类型库存分录调整，不直接修改余额字段。

## 7. 验收场景

- 采购：一张订单包含多药品、多批号、部分拒收，合格行一次性过账且重复请求不重复入账。
- 请领：多品项请领审核后按两批次 FEFO 拣货，库存不足整单失败，成功出库只产生一次分录。
- 调拨：调出后来源库存减少、目标库存不变；调入确认后目标库存增加，批次追溯保持连续。
- 盘点：建单后录入盘盈和盘亏，非本人审核，过账生成正负调整；并发库存变化触发版本冲突。
- 数据范围：其他科室或机构不能读取、审核或过账不属于其范围的单据。
- 库存期间：关闭期间内四类过账全部失败且不改变余额。
