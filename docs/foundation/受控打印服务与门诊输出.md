# 受控打印服务与门诊输出

## 1. 能力边界

受控打印不是前端直接调用 `window.print()`。业务模块先确认来源对象已达到可正式输出的终态，再向 `platform.printing.api` 提交规范快照；平台解析已发布模板，生成不可变 PDF，保存内容摘要并建立打印任务。当前支持：

- 已签署当前版本的门诊病历；
- 已提交、未撤销且药品明细全部生效的门诊处方；
- 原始生成和基于同一不可变输出的重打审计；
- 平台模板基线，以及同文档类型的租户模板优先覆盖解析。

“生成成功”只证明服务端 PDF 已形成并通过摘要校验，不等同于实体打印机已经出纸。打印机发现、队列状态、缺纸和卡纸回执属于设备/操作系统适配边界，后续按试点设备方案接入。

## 2. 数据模型

| 表 | 职责 |
|---|---|
| `print_templates` | 模板身份、文档类型、平台/租户作用域、当前发布版本 |
| `print_template_versions` | 不可变模板配置、布局模式、发布摘要与发布信息 |
| `print_outputs` | 来源版本、业务快照、PDF 内容、SHA-256 摘要、用途和生成主体 |
| `print_jobs` | 原始/重打请求、份数、状态、操作者、关联号和原始任务关系 |

模板选择顺序为“当前租户有效模板 > 平台有效模板”。输出保存模板 ID 与模板版本 ID，后续模板升级不会改变历史文件。重打复用原输出字节并新增 `REPRINT` 任务，不覆盖原任务或重新读取可能已变化的业务对象。

## 3. 业务门禁

1. 必须具备受信机构、科室工作上下文和已识别操作人。
2. 来源机构/科室必须位于当前数据范围内。
3. 病历只有 `SIGNED` 当前版本且存在签署证据时可打印；草稿和修订中状态失败关闭。
4. 处方只有 `ACTIVE` 且所有药品明细均为 `ACTIVE` 时可打印；草稿、撤销及部分未生效状态失败关闭。
5. 下载前重新计算 PDF SHA-256；与持久化摘要不一致时禁止返回文件。
6. 文件名会移除路径和控制字符，避免响应头注入与非预期路径语义。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `POST /api/clinical-documents/{documentId}/print-jobs` | 生成已签署门诊病历 PDF |
| `POST /api/encounters/{encounterId}/prescriptions/{prescriptionId}/print-jobs` | 生成已提交处方 PDF |
| `GET /api/platform/printing/templates` | 查询当前可解析的模板及版本 |
| `POST /api/platform/printing/jobs/{jobId}/reprints` | 针对原不可变输出登记重打任务 |
| `GET /api/platform/printing/outputs/{outputId}/content` | 摘要校验后下载 PDF |

生成响应返回 `jobId`、`outputId`、模板代码/版本、摘要、文件名和受控下载地址。PC 端在生成前再次展示对象、版本、用途和输出格式；当前默认生成一份“患者副本”。

## 5. PDF 基线

- A4 纵向，采用统一页边距、标题层级、表格边框和页脚；
- 嵌入 Noto Sans SC 字体，输出不依赖客户端或打印机预装中文字体；
- 病历包含居民/就诊信息、主诉、生命体征、诊断、诊疗意见、签署信息和来源版本；
- 处方包含居民/处方信息、药品名称、规格数量、剂量用法、备注、提交信息和来源版本；
- 页脚显示“RHN 受控打印文件”和页码。

- 脱敏副本、水印策略、批量打印及基于权限的打印用途控制。
