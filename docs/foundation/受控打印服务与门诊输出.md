# 受控打印服务与门诊输出

## 1. 能力边界

受控打印不是前端直接调用 `window.print()`。业务模块先确认来源对象已达到可正式输出的终态，再向 `platform.printing.api` 提交规范快照；平台解析已发布模板，生成不可变 PDF，保存内容摘要并建立打印任务。当前支持：

- 已签署当前版本的门诊病历；
- 已提交、未撤销且药品明细全部生效的门诊处方；
- 原始生成和基于同一不可变输出的重打审计；
- 按就诊查询正式输出及全部原打/重打任务，支持历史文书下载和补打；
- 平台模板基线，以及同文档类型的租户模板优先覆盖解析。

“生成成功”只证明服务端 PDF 已形成并通过摘要校验，不等同于实体打印机已经出纸。打印机发现、队列状态、缺纸和卡纸回执属于设备/操作系统适配边界，后续按试点设备方案接入。

## 2. 数据模型

| 表 | 职责 |
|---|---|
| `print_templates` | 模板身份、文档类型、平台/租户作用域、当前发布版本 |
| `print_template_versions` | 不可变模板配置、布局模式、发布摘要与发布信息 |
| `print_outputs` | 来源版本、业务快照、PDF 内容、SHA-256 摘要、用途和生成主体 |
| `print_jobs` | 原始/重打请求、份数、状态、操作者、关联号和原始任务关系 |

模板选择顺序为“当前租户有效模板 > 平台有效模板”。输出保存模板 ID 与模板版本 ID，后续模板升级不会改变历史文件。重打复用原输出字节并新增 `REPRINT` 任务，不覆盖原任务或重新读取可能已变化的业务对象。

## 3. 业务门禁

1. 必须具备受信机构、科室工作上下文和已识别操作人。
2. 来源机构/科室必须位于当前数据范围内。
3. 病历只有 `SIGNED` 当前版本且存在签署证据时可打印；草稿和修订中状态失败关闭。
4. 处方只有 `ACTIVE` 且所有药品明细均为 `ACTIVE` 时可打印；草稿、撤销及部分未生效状态失败关闭。
5. 下载前重新计算 PDF SHA-256；与持久化摘要不一致时禁止返回文件。
6. 文件名会移除路径和控制字符，避免响应头注入与非预期路径语义。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `POST /api/clinical-documents/{documentId}/print-jobs` | 生成已签署门诊病历 PDF |
| `POST /api/encounters/{encounterId}/prescriptions/{prescriptionId}/print-jobs` | 生成已提交处方 PDF |
| `GET /api/platform/printing/templates` | 查询当前可解析的模板及版本 |
| `GET /api/platform/printing/records?encounterId={encounterId}` | 查询本次就诊全部正式输出、摘要、模板版本及打印任务 |
| `POST /api/platform/printing/jobs/{jobId}/reprints` | 针对原不可变输出登记重打任务 |
| `GET /api/platform/printing/outputs/{outputId}/content` | 摘要校验后下载 PDF |
| `POST /api/platform/printing/deliveries/{deliveryId}/desktop-dispatches` | 工作站打印：先持久保存 RHN Link 持久调用操作编码，返回打印机、份数、作业名与小写摘要 |
| `POST /api/platform/printing/deliveries/{deliveryId}/desktop-results` | 工作站打印：回写已提交 / 未执行 / 结果不确定 |
| `POST /api/platform/printing/deliveries/{deliveryId}/reconciliations` | 工作站打印：人工核对确认出纸，或说明后判定未出纸 |
| `POST /api/platform/printing/deliveries/{deliveryId}/browser-fallbacks` | 工作站打印设备但页面不在 RHN Link 中：投递改记浏览器打印 |

生成响应返回 `jobId`、`outputId`、模板代码/版本、摘要、文件名和受控下载地址。PC 端在生成前再次展示对象、版本、用途和输出格式；当前默认生成一份“患者副本”。医生站的“就诊历史”按文书版本展示既往输出：当前签署版本没有正式输出时允许首次生成，已有输出时只能下载原文件或登记补打，不能把补打伪装成新的原始输出。

## 4.1 RHN Link 工作站打印

打印设备通道 `DESKTOP_LINK` 表示由 [RHN Link（健域端联）](https://github.com/yangli216/rhn-link) 工作站的 `rhn.printing` 插件把同一份 PDF 提交到 Windows 系统打印队列，`NA_QUEUE` 保存工作站系统打印机名称，输出语言只能为 PDF。路由仍按“单据 + 介质 → 设备”绑定，不同纸张应配置为不同系统打印机。

- 生成输出后投递为 `QUEUED`；页面在 RHN Link 中且持久调用可用时，先调用 `desktop-dispatches` 保存操作编码（`DISPATCHED`），再以同一编码调用插件，最后回写结果。
- 插件返回已提交时投递为 `SENT`，只表示进入系统打印队列，不代表已出纸；进入队列前失败（打印机不存在、摘要不符等）为 `FAILED`，可修正后用新编码重新下发。
- 作业中途中止、插件内部异常、宿主超时或进程中断等无法确定是否已入队的情况为 `UNCERTAIN`：禁止直接重新下发，必须人工核对纸面结果，确认出纸为 `DEVICE_CONFIRMED`，说明后判定未出纸为 `FAILED`。
- 页面不在 RHN Link 中（普通浏览器、客户端版本不兼容或持久调用不可用）时登记 `browser-fallbacks`，投递通道如实改记 `BROWSER_PDF` 后调起浏览器打印预览。
- 已提交或已确认的投递不能再次下发；再次打印须登记重打（新任务、新投递）。
- 前端编排位于 `frontend/src/shared/desktop/`，插件契约与状态码以 rhn-link `docs/rhn-printing.md` 为准。真实出纸、纸张与缩放须在 Windows 工作站实机验收。

## 5. PDF 基线

- 门诊病历默认 A4 纵向、处方默认 A5 纵向、检查/检验/治疗申请单默认 A5 横向；纸张为产品默认值，机构可按本地要求配置；
- 嵌入 Noto Sans SC 字体，输出不依赖客户端或打印机预装中文字体；
- 采用黑白纸质文书排版。病历以连续段落呈现主诉、病史、体检、辅助检查、诊断、处理意见和签署信息，保留结构化专科字段；
- 处方采用患者信息、临床诊断、Rp 正文、签署区结构；西药逐项列出规格、数量、剂量和用法，饮片采用三列排列并保留特殊煎服嘱托；
- 申请单区分开单科室与执行科室，呈现诊断、病情摘要、申请目的、项目、数量和签署区；
- 页脚显示患者、业务单号、用途和页码；长内容自动续页，续页带文书类型和患者标识；
- 来源版本、内部对象 ID 和摘要仍保存在受控输出及审计数据中，不占据纸面正文；缺失临床信息不以默认剂量、用法或阴性结论补齐；
- `V1_99_0` 仅为平台 V1 默认模板发布 `RHN_OUTPATIENT_DOCUMENT_V2` 新版本，保留旧版本及已生成 PDF。旧纸型设备绑定不自动改写，新纸型需匹配介质绑定，否则使用浏览器 PDF 回退。

调研依据、样张及验收说明见[医生站打印版式调研与验收](../归档文档索引.md)。
