# 普通字典管理设计

## 1. 定位与边界

普通字典用于平台或单一租户范围内、只需要解释“当前可选值”的轻量枚举。它不承载标准临床术语、外部大型目录、有效期版本、层级关系、多语言、映射、参数继承、业务状态迁移规则或底座自身的封闭枚举。

需要版本发布、历史版本解释和值域复用的对象进入 `platform.terminology`；具有独立属性和生命周期的数据进入相应主数据或业务聚合；全局/租户/机构/科室/用户差异进入 `platform.configuration`。

字典底座自身依赖的作用域、状态、日志操作和日志目标属于 `SYSTEM_ENUM`。这些值同时参与代码分支和数据库约束，必须保持封闭、不可在线修改；由代码目录集中提供中文名称和说明。组织与参数模块的系统枚举同时在字典表形成平台级只读投影，便于数据库查询、管理端统一展示和基础数据交付，但代码目录仍是语义权威。

## 2. 数据模型

表结构契约 1.1.0 将逻辑模型固化为 `HI_BD_DICT_CAT`、`HI_BD_DICT_DEF`、`HI_BD_DICT_ITEM`、`HI_BD_DICT_CHANGE`。本项目延续已有的扁平 schema 与描述性表名，对应落为：

| 物理表 | 并发策略 | 责任 |
|---|---|---|
| `dictionary_categories` | `OPTIMISTIC_VERSION` | 平台/租户作用域内的分类树、稳定编码、排序、状态和审计字段 |
| `dictionary_definitions` | `OPTIMISTIC_VERSION` | 当前字典定义、所属分类、平台/租户作用域、稳定编码、系统托管标记、状态和审计字段 |
| `dictionary_items` | `INHERIT_PARENT` | 当前字典项；自身不持有并发令牌，任一变化推进父字典修订号 |
| `dictionary_changes` | `APPEND_ONLY` | 分类、字典和字典项命令的前后 JSON 快照、原因、请求编码、操作者和时间 |

数据库约束固化以下规则：

- 分类和定义分别在 `(scope_code, code)` 内唯一，字典项在 `(dictionary_id, code)` 内唯一；
- 平台分类/定义的 `scope_code` 固定为 `PLATFORM` 且 `tenant_id` 为空；租户数据由应用生成 `TENANT:<tenantId>`；
- 每个字典必须关联同作用域分类；分类父子节点也必须处于相同作用域，并禁止形成环；
- 分类、字典和字典项仅允许 `ACTIVE`、`INACTIVE`，不提供物理删除接口；
- `system_managed=true` 的定义固定为平台作用域，创建/更新人员为空，由 Flyway 迁移维护；普通定义必须保留创建/更新人员；
- 变更日志至少存在一个前后快照；`CATEGORY`、`DICT`、`ITEM` 三类目标分别约束分类、字典和字典项 ID；
- `request_code` 建普通索引而非唯一索引，允许一个业务请求扩展为多条审计记录；同一资源重放同一请求直接返回已有结果。

## 3. 写入规则

所有更新、启停和字典项命令都必须提交 `expectedRevision`。服务端先验证当前修订号，再修改当前数据、推进父字典修订号并在同一事务追加变更日志；并发请求只能有一个成功，失败方得到 `DICTIONARY_REVISION_CONFLICT` 或统一乐观锁冲突。

分类及定义的作用域和编码、字典项编码创建后不可修改。分类允许调整父节点与排序，字典允许调整所属分类；两者只能在原作用域内移动。名称、说明、排序和启停状态允许调整。停用分类前必须先迁移或停用其启用子分类及启用字典。历史业务数据继续保存原字典项编码，停用只阻止其进入新的可选值集合。

系统托管字典不进入普通写入规则：定义和字典项只能随代码及数据库迁移调整，所有普通字典写接口统一返回 `SYSTEM_DICTIONARY_READ_ONLY`。启动校验会逐项比较数据库投影与代码目录，缺失、增删、名称、说明、排序或状态不一致都会阻止应用启动。初始投影以 Flyway 迁移作为变更依据，不写入面向人工维护的 `dictionary_changes`。

## 4. 租户和读取规则

管理查询只返回平台分类/字典与当前租户分类/字典；租户分类、字典详情、字典项和变更记录都通过同一可见性门禁，跨租户按“未找到”处理，避免泄露资源是否存在。按分类筛选时包含其全部后代分类。

分类树只用于管理端导航、检索和治理，不参与运行时字典解析，不改变“租户同编码优先、平台字典回退”的行为。

业务模块通过 `DictionaryDirectory.resolveActiveItems(tenantId, code)` 读取当前有效选项。存在同编码租户字典时优先使用租户定义，否则回退到平台定义；停用的字典或字典项不会进入解析结果。业务模块不得直接访问字典表。

## 5. 管理接口

管理接口统一位于 `/api/platform/dictionaries`，包含目录查询、详情、创建、定义更新、分类调整、定义启停、字典项新增/更新/启停和变更记录查询；分类树通过 `/categories`、`/categories/{id}` 及其启停、变更记录子资源维护；另提供 `/resolve/{code}` 当前有效项解析接口。接口 ID 使用十进制字符串，修订号使用非负整数，所有写命令携带独立请求编码。

字典底座通过 `/api/platform/dictionaries/system-enums` 和 `/api/platform/dictionaries/system-enums/{code}` 发布只读系统枚举目录。首批固化如下：

| 系统枚举编码 | 用途 | 枚举项 |
|---|---|---|
| `DICT_SCOPE_TYPE` | 字典作用域 | `PLATFORM`、`TENANT` |
| `DICT_STATUS` | 字典定义状态 | `ACTIVE`、`INACTIVE` |
| `DICT_CATEGORY_STATUS` | 字典分类状态 | `ACTIVE`、`INACTIVE` |
| `DICT_ITEM_STATUS` | 字典项状态 | `ACTIVE`、`INACTIVE` |
| `DICT_CHANGE_TYPE` | 变更操作 | 分类创建/更新/移动/启停、字典创建/更新/移动/启停、字典项新增/更新/启停 |
| `DICT_CHANGE_TARGET_TYPE` | 变更目标 | `CATEGORY`、`DICT`、`ITEM` |
| `PARAM_SCOPE_TYPE` | 参数作用域 | `PLATFORM`、`TENANT`、`ORGANIZATION`、`DEPARTMENT`、`USER`、`PRODUCT`、`MODULE`、`ENVIRONMENT` |
| `PARAM_VALUE_TYPE` | 参数值类型 | `STRING`、`NUMBER`、`BOOLEAN`、`JSON` |
| `PARAM_CONTROL_TYPE` | 参数控件 | `TEXT`、`TEXTAREA`、`NUMBER`、`SWITCH`、`SELECT`、`JSON_EDITOR`、`SECRET_REFERENCE` |
| `PARAM_CONFIG_TYPE` | 参数配置属性 | `SYSTEM`、`BUSINESS` |
| `PARAM_SENSITIVITY` | 参数敏感级别 | `NORMAL`、`SENSITIVE`、`SECRET` |
| `PARAM_DISPLAY_POLICY` | 参数展示策略 | `PLAIN`、`MASKED`、`HIDDEN` |
| `PARAM_STATUS` | 参数状态 | `ACTIVE`、`INACTIVE` |
| `PARAM_VALUE_MODE` | 参数值模式 | `INHERIT`、`OVERRIDE`、`RESET_DEFAULT`、`EXPLICIT_NULL` |
| `PARAM_CHANGE_TYPE` | 参数变更类型 | `CREATE`、`UPDATE`、`ENABLE`、`DISABLE`、`RESET`、`ROLLBACK` |
| `PARAM_CHANGE_TARGET_TYPE` | 参数变更目标 | `DEFINITION`、`VALUE` |

目录启动时校验系统枚举项与 Java 枚举常量完全一致；组织与参数的 18 组系统枚举还会校验字典表只读投影。不完整、重复、多余或展示元数据不一致都会使应用启动失败。普通字典创建接口拒绝以上保留编码，从机制上避免同名和自举递归。

前端字典管理页同时呈现普通字典和系统托管投影；系统托管记录带明确标识且隐藏定义、字典项和启停操作。页面提供分类筛选和分类树维护，可新建、编辑、移动、排序和启停分类，并在创建/编辑字典时强制选择同作用域分类。页面不提供业务版本、草稿或发布入口；作用域、状态和变更记录的显示名称及选项全部读取系统枚举目录，不在页面重复维护中文映射。

## 6. 响应字段自动翻译

业务出参采用 `sd<字典编码大驼峰>` 命名时，JSON 序列化层自动补充同名 `Text` 字段。字典管理自身的作用域、定义状态、字典项状态、变更类型和变更目标已按此规则改造，作为后续业务模块的参考实现。

翻译使用系统枚举内存目录或按租户缓存的普通字典文本目录；普通字典的历史停用项仍可翻译，新增业务的下拉选项则继续只读取启用项。字段约定、缓存失效、OpenAPI 和安全边界详见[字典字段自动翻译设计](字典字段自动翻译设计.md)。
