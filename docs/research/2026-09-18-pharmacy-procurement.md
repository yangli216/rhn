# 采购验收入库：调研与第一轮改进

日期：2026-09-18。

## 当前问题

- 到货表药品列受挤压，规格、厂家难辨；采购表重复药名。
- 数量、货位逐行从空白录入；超量、缺批号等只表现为按钮不可用。
- 页面剩余数量是尚未入账数量，未扣除已登记待验收/待入库的占用数量；与服务端计算不一致。
- 采购表把不完整行过滤后提交，可能造成用户认为已录入的药品漏单。
- 不同包装单位混合汇总数量，难以解释。
- 保存采购单后还需找到草稿提交；登记到货后需重新查找验收单。

## 本轮实现

1. 默认展示待办，增加待提交/审核、待到货、待验收、待入库、全部记录；支持单号、供应商和药名搜索。
2. 桌面宽屏采购与收货弹窗，保留药品规格、厂家、包装单位、单价单位；收货表设定列宽，窄桌面使用表格横向滚动。
3. 采购默认“保存并提交审核”，可取消勾选只存草稿。保存成功、提交失败时明确提示已保存单号，通过列表继续办理，避免把两步都视作失败。
4. 可收数量 = 采购剩余数量 − 同采购单处于 RECEIVED/INSPECTING/ACCEPTED/PARTIALLY_ACCEPTED 的已登记到货数量。最终仍由服务端加锁验证，防止并发超收。
5. 到货默认带入可收数量；部分到货直接改数，0/空白跳过该药；单一收货货位自动带出，多货位可统一选择、逐行覆盖。
6. 药品行持续展示超量、缺批号/效期、缺货位、日期倒置原因。无可收货位明确提示，不擅自创建货位。
7. 登记成功直接进入质量验收；默认全部合格，输入不合格数自动扣减合格数，并保留不合格原因必填与数量守恒校验。验收后定位待入库列表。
8. 未完成药品行、重复药品包装禁止提交；不再跨包装单位累加显示数量。保留金额汇总与 Enter 连续录入。
9. 到货网络结果不确定时冻结原请求并复用请求号重试；不自动验收、不自动入账，现有权限、追溯码和入库事务校验保持有效。

## 验证

- 采购相关回归：3 个测试文件、11 个用例通过。覆盖待入库占用扣减、到货预填、超量/负数/日期校验、网络重试、不完整行、采购已保存但提交失败、验收不合格差异联动，以及原库房上下文行为。
- TypeScript 检查及生产构建通过。
- ego-browser 使用持久服务实际查看采购列表、采购弹窗、收货弹窗，并验证“可收 1 盒、填写 20”的错误提示；未在 Oracle 写入测试采购/库存数据。
- 全局 UI 检查仍存在既有颜色等规范问题；本轮新增样式使用语义令牌。

## 仍需独立建设的场景

本轮是现有采购链路的交互改进，不表示医院药事管理所有场景已完备。同药同单多批号当前仍需分次登记（服务端一张收货单禁止重复采购行）；供应商协议价格自动取价、采购草稿编辑/撤销、供应商送货单导入、发票与结算、冷链记录、特殊药品双人验收等需要后续结合医院制度完善。原采购建单会自动补供货目录的行为本轮未调整，若实行供应商准入/品种授权审批，应另行改为明确的受控维护流程。
