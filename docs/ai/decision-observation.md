# 决策运行观察契约

入口：AI 助理配置中心 → 决策运行观察。合理用药继续使用处方质量审查日志和候选的旁路部署与观察，不另建并行评价体系。

## 留痕与边界

- 四个决策场景（辅诊目录核查、智能建方目录核查、预检分诊、病历完整性与矛盾核查）在实际到达决策服务时追加 `RHN_AUD_AI_DCSN_RUN`。包括禁用、配置不完整、候选限制、模型成功、不确定及失败；业务没有触发该服务时不虚构运行记录。
- 记录当前租户、机构、科室，模型及规则版本、请求关联、供应商追踪、输入 SHA-256、有限输入和候选快照、有效判断/概率、阈值、总耗时、基线状态和异常类型。独立密钥、供应商异常正文不进入快照和日志。
- 快照由受限目录请求生成，分诊只保留既有评估请求的临床字段，不增加身份字段。自由文本可能包含敏感内容；列表不返回输入/答案，详情按需读取，必须有当前机构科室及 AI 配置权限。分诊详情与研判还需既有分诊、接诊、挂号访问权限之一或管理员身份；病历核查详情与研判还需门诊接诊权限或管理员身份。
- 写入使用独立事务，调用方之后回滚不抹除旁路证据；写入故障不改变临床处置，在服务日志输出 `decision_observation_not_persisted` 告警。无持久化记录不保证业务从未触发，需结合部署版本、配置和写入告警核对。
- `RHN_AUD_AI_DCSN_REVIEW` 追加人工研判及原因、操作者和时间，历史保留。统计每个运行只按最新意见计一次，不将重复研判累加为样本；研判不修改处方、分诊或开关。

## 统计与基线

- Jev 与 LingDT 共用现有观察流程，当前模型由 `decision-provider` 选择；连接及密钥分别保存，留痕记录实际返回的模型版本。变更供应商后旧记录保留，历史置信度和一致性不能直接作为新供应商的医学准确率证明。

- 查询固定当前机构科室，支持场景、模式、结果、日期和分页，默认最近七天，单次最多九十天。统计覆盖全部筛选样本，非当前页或最近50条。
- 区分总尝试、实际发起模型调用、有效判断、不确定/无匹配、结果分布、人工研判、平均总耗时和P95总耗时。配置检查和失败不是有效判断；低于阈值或 `NONE` 属于不确定/无匹配。
- 分诊将可确认的科室与规则首选科室比较；缺少规则选择或执行失败不假造比较。目录决策只处理原流程尚未解决的意图，原基线为人工核对，记为 `MANUAL_REVIEW`，一致性为空。不得用空集合冒充确定性基线计算“不一致”。
- 可比较一致性、概率集中程度、人工研判数都不是临床准确率；重复请求是不同运行，不是不同患者。
- 场景状态读取实际服务配置与当前工作范围最近留痕，显示总开关关闭、场景未启用、配置不完整、尚无持久化触发记录或已有记录。最近历史可能属于旧模式；筛选可核对当前模式。观察接口版本证明该能力已在服务端提供，不证明模型已启用。

## 合理用药日志

`/api/quality/medication-workbench/evaluation-records` 按当前机构科室分页，支持日期、模式、结论及处方标识；详情返回当时不可变输入、命中证据、规则执行与失败结果。旧 `/evaluations` 最近50条契约保留兼容，页面使用新分页入口，不用“零命中”表达“无风险”。

## 验证与运行

`./scripts/verify-scope.sh decision-observation` 包含范围、统计、快照、人工意见和消费者检查；迁移/契约变更扩大完整验证并从临时 test 服务生成 OpenAPI，测试不连接人工 Oracle。

页面沿用列表模板的 WorkspacePane/TableShell 分区和共享筛选、分页、Dialog，根容器不叠加页面边距。人工验收仍需核对1280/1440/1920px、标准/大字、长快照滚动、无权限、失败重试与不同工作上下文。

本轮不自动启用模型或采纳业务操作。病历核查已支持提示到医生采纳、忽略及真实保存版本的关联；目录/分诊的最终业务采纳关联、自动回放、日志集中采集和留存归档策略仍待建设。历史普通日志不自动转换为持久化运行记录。


## 病历完整性与矛盾反馈

- 配置中心增加 `decision-scene-record-quality-enabled`，默认关闭；复用 Jev/LingDT 选择、独立凭据、总开关、置信度和现有灰度范围。医生站病历区域的“核查当前病历”按需触发，不在每次输入时调用。
- 仅核查九个现有文字段落。七项资料覆盖问题（起病、演变、伴随症状、既往史、近期用药、过敏、随访）以及三项文字矛盾问题（过敏、用药、症状），均为有限选项，含 `UNKNOWN`；不输出替代病历，不决定诊断、剂量、紧急程度或医嘱。不同时间、主观症状与客观查体差异不自动认定矛盾。
- 总开关关闭、场景关闭、配置不全不调用模型，输入快照为空；旁路只供观察，不返回可采纳提示。辅助模式按每题门槛筛选，低置信度/UNKNOWN 不展示为确定提示。超限不截断输入；超时、非法响应或留痕失败保留既有录入及保存。
- `RHN_AUD_AI_REC_DCSN` 将可采纳运行绑定到原就诊、当前机构科室、医生/执业人员、评估时间、病历版本及九段文字指纹。请求供应商的 state 不含患者/就诊身份；自由文本仍可能含敏感资料，详情按原临床权限保护。
- `RHN_AUD_AI_REC_FB` 追加 `ADOPTED`（采纳并定位）、`DISMISSED`（忽略）、`MODIFIED`（相关段落改变且已保存）、`UNCHANGED`（已保存但相关段落未改变）。医生手工核实、编辑并沿用原草稿保存；点击采纳不补写阴性事实，也不等同保存。
- 保存反馈要求服务端当前门诊文档 ID/版本等于回执，版本高于核查基线、内容版本产生于核查和采纳之后且由同一医生保存。指纹复用统一文本清洗，前后空白整理不计为修改；字段变化由 health-core 的公开、按权限过滤的当前文档快照核对，不相信客户端声明的修改结果。仅保存变化字段的指纹和文档版本，不重复复制保存后原文。
- 一条反馈命令可重试，同一命令不同内容返回 `RECORD_QUALITY_COMMAND_CONFLICT`；行锁串行处理，唯一约束兜底。反馈失败不会撤销或重新写入病历。前端保留命令重试，重载后恢复上次待反馈记录，可核实已保存版本。患者/API/权限切换和评估期间编辑均拒绝迟到结果；未提交草稿不会被反馈覆盖。
- 观察详情展示完整追加反馈及医生/时间/文档版本；汇总按筛选范围内每条提示的最新状态计数，重复点击不累计样本。“已采纳”含修改/未修改的保存状态；修改不等于提示已解决，更不是医学正确率。尚未引入自动语义复核、真正问题解决率或所有临床场景的统一采纳率。
- 公开 API 位于 `/api/ai/clinical-assistant/encounters/{encounterId}/record-quality`（POST 核查、GET 恢复上次辅助结果）及 `/{runId}/feedback`。均校验当前接诊医生与机构科室；总开关改为关闭/旁路后禁止新的采纳，历史忽略和保存反馈仍可记录。
