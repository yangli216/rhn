# RHN 原生 AI 辅助诊疗实施路线图

## 1. 现状结论

医生站现有 AI 界面不是纯前端静态文案，但截至本次改造前只有 `LOCAL_ASSIST` 固定规则：病历缺项检查、生命体征阈值提醒、活动性过敏提示、已录入 ICD-10 校验和院内方案关键词匹配。病历补文案也由固定模板拼接。`MODEL` 当时没有适配器，因此不能视为真实 AI 辅助诊疗。

本次已经打通第一条原生模型闭环：

```text
医生站当前患者与草稿
  -> RHN 服务端最小必要上下文
  -> OpenAI-compatible 模型网关
  -> 结构化建议解析
  -> ICD-10 / 方案白名单 / 确定性风险二次校验
  -> 建议与审计留痕
  -> 医生明确采纳
  -> 当前页面草稿
  -> 原病历、诊断和医嘱校验/保存流程
```

模型密钥不进入浏览器；模型不能直接调用临床写服务；患者、就诊、机构、科室、医生、草稿和服务端临床锚点任一变化都会阻止旧建议采纳。

## 2. 与全医慧助能力对照

| 能力域 | 全医慧助现有能力 | RHN 当前状态 | RHN 原生落点 |
| --- | --- | --- | --- |
| 病历辅助 | 症状/语音生成，字段事实建议 | **本次可用**：模型病历草稿、缺项与补问 | 医生站病历编辑区与智医抽屉 |
| 诊断辅助 | 正式诊断、鉴别方向、目录匹配 | **本次可用**：模型候选/鉴别，院内 ICD-10 强校验 | AI suggestion + encounter diagnosis 草稿 |
| 风险与安全 | 接诊风险、L1 规则、L2 模型复核 | **部分可用**：生命体征/过敏规则与模型风险合并 | 独立 Safety Review，不允许模型覆盖规则 |
| 诊疗方案 | 药品、检查、检验、处置推荐与匹配 | **部分可用**：模型按院内方案的结构化条目推荐，采纳前逐项核对并执行用药预检 | 下一阶段拆分非模板 Order Recommendation API |
| 医生确认/回写 | 编辑、匹配、库存门禁、一键回写 | **已有闭环**：服务端预检后仅入页面草稿，再走原服务 | 保持 RHN 原生保存、审方和医嘱提交 |
| 报告解读 | LIS/PACS 原文、异常提炼、后续方案 | **部分可用**：当前就诊报告已作为服务端只读模型上下文 | diagnostics 模块只读 Report Interpretation |
| 慢病续方 | 90 天历史、库存、核查与处方建议 | **部分可用**：近 90 天已完成就诊、诊断和有效医嘱进入只读上下文 | outpatient + pharmacy 跨模块只读上下文 |
| 症状问诊 | 部位/系统/症状采集与追问 | **部分可用**：基于当前草稿生成医生补问清单 | Doctor Workstation 内嵌 Consultation Session |
| 语音问诊 | 录音、实时转写、结构化病历 | **部分可用**：浏览器录音、服务端文件转写、可编辑文本再分析 | 后续增加经评审的实时转写 |
| 医学知识 | PMPHAI/知识库检索 | **本次可用**：服务端托管检索，展示知识库、年份、位置和引用片段 | 可追溯 Knowledge Retrieval API |
| 事实核查 | 病历、诊断、治疗逐项核查 | **部分可用**：当前病历、过敏与报告的一致性核查 | 建议级 Evidence/Fact Check 子资源 |
| 对话助手 | 流式问答，可选联网搜索 | **部分可用**：支持同一稳定就诊上下文内连续追问 | 就诊上下文 Chat Session，联网默认关闭 |
| 反馈与追踪 | trace、采纳/拒绝、问题反馈 | **部分可用**：生成/查看/采纳/忽略/正负反馈 | 扩展 trace、延迟、token 和质量评估 |
| 诊断路径 | 可视化诊断推理路径 | **部分可用**：候选/鉴别依据与待确认项 | Diagnosis Reasoning Graph，只读展示 |

“基本覆盖”以临床工作能力为口径，不复制悬浮球、Tauri 本地桥、PHIS 私有 SDK、窗口管理和本地缓存。这些是独立桌面产品的宿主能力，在 RHN 内应由原生模块、权限和数据契约替代。

## 3. 分阶段实施

### M1 原生临床分析核心（已完成）

- `MODEL` 模式真实服务端调用，支持兼容 Chat Completions 的模型服务。
- 版本化提示词与结构化输出：摘要、病历草稿、诊断、鉴别、补问、安全提示、院内方案。
- 只发送最小必要患者信息，不发送姓名、电话、健康档案号；密钥只在服务端配置。
- 模型诊断必须命中当前院内 ICD-10；模型方案必须命中当前医生可见方案 ID。
- 本地确定性生命体征和过敏规则始终执行，不能被模型删掉。
- 建议采纳沿用双上下文指纹、有效期和审计事件；模型异常不影响医生站。

### M2 原生诊疗推荐

- **已完成**：院内方案的诊断、药品剂量用法及检查/检验/处置条目进入模型只读上下文和失效指纹，医生采纳前可逐项核对。
- **已完成**：方案采纳支持逐项选择诊断、药品、检查、检验和处置，未选项不进入草稿；采纳事件记录标准编码或目录 ID。
- **已完成**：AI 方案药品行使用稳定 ID；采纳前与确认时均由服务端重新读取当前可见方案，检查产品/包装、剂量、途径、频次、疗程、数量、精确过敏命中以及当前科室路由药房的指定包装库存，确定性失败阻断采纳。
- **明确边界**：药物相互作用和禁忌证在接入医院认可、可版本化的规则或知识源前返回 `NOT_EVALUATED`，不以模型判断伪装成确定性校验。
- 新增药品、检查、检验、处置四类结构化推荐，不复用自由文本 `treatmentPlan` 直接开嘱。
- 候选先由模型生成临床意图，再由 RHN 主数据解析为标准项目；未匹配项默认不选中。
- 药品最终仍必须经过过敏、库存、药房、剂量/频次/途径完整性和审方规则；相互作用、禁忌证待治理规则源接入后纳入阻断门禁。
- 检查检验必须解析执行科室、标本/部位和申请必填属性。
- 每项都支持采纳、拒绝、修改原因和证据追溯，最终仍走原医嘱提交接口。

### M3 报告助手与复诊

- **已完成**：当前就诊最近 10 份有效报告通过 diagnostics 公开只读目录进入模型上下文；报告版本变化会使旧建议失效。
- **已完成**：只发送报告类型、状态、名称、结论及结构化观察值，不发送报告作者、外部报告号、交换消息 ID 或内容摘要。
- **已完成**：医生站在模型能力可用时提供“解读检查报告”快捷入口，解读结果仍走原建议审计与医生采纳边界。
- diagnostics 提供结构化 LIS/PACS 原始报告上下文，原始结果始终先于 AI 解读。
- 异常项优先由数值、参考范围和上游标志确定，模型只负责解释和建议。
- 报告解读默认只读；“生成后续方案”作为医生主动触发的第二步。
- 当前报告或患者已切换时，迟到结果必须丢弃。

### M4 症状问诊与语音问诊

- **已完成**：医生可基于当前草稿生成动态补问清单；未知项保持问题形态，不补写为患者事实。
- **已完成**：支持基于上一轮结构化建议连续追问；患者、就诊、草稿或服务端临床上下文变化后必须重新分析。
- **已完成**：支持浏览器 `webm` 等录音上传到服务端 Speech Gateway，转写文本与 AI 病历建议分开展示并由医生编辑确认；音频不在 RHN 落盘。
- **配置**：`RHN_AI_SPEECH_ENDPOINT` 指向 OpenAI-compatible Audio Transcriptions 地址，`RHN_AI_SPEECH_MODEL` 默认 `gpt-transcribe`，`RHN_AI_MAX_AUDIO_BYTES` 默认且最大为 20 MB。
- 在医生站内嵌症状采集、动态追问和结构化问诊 session，不新增桌面悬浮窗。
- 浏览器录音只负责采集；转写密钥、模型和审计留在服务端。
- 转写文本、原始医生输入和 AI 生成内容分别标记，医生可逐字段修改。
- 音频留存、撤回、权限和保留周期上线前单独评审。

### M5 知识、事实核查与诊断路径

- **已完成**：提供绑定当前活动就诊和接诊医生的 PMPHAI-compatible 只读知识检索；浏览器不持有知识服务地址或密钥。
- **已完成**：结果缺少标题、来源或文档 ID 时不会展示；UI 明示知识库、年份、资源位置和检索片段，不把无来源模型内容伪装成权威依据。
- **已完成**：支持当前病历、活动性过敏和检查报告之间的一致性核查，矛盾与缺项分区展示。
- **已完成**：诊断候选与鉴别项可返回简要支持点、反对点和待确认项，并继续受 ICD-10 校验。
- 知识检索必须返回标题、来源、版本/日期和可定位片段；无来源内容不得显示为权威依据。
- 对病历、诊断和治疗建议分别执行事实核查，区分确定性冲突与模型柔性提醒。
- 诊断路径只展示证据、支持/反对项和下一步鉴别，不自动改变正式诊断。

### M6 慢病续方与持续治理

- **已完成**：同机构同科室近 90 天最多 5 次已完成就诊的诊断、有效药品与诊疗项目进入模型只读上下文；不发送历史医生、价格或支付信息。
- **已完成**：建议生成耗时/失败、供应商 token 用量、建议事件、方案预检结果和安全阻断已纳入 Actuator 指标；指标标签保持低基数，不含患者或就诊标识。
- **已完成**：支持机构、科室白名单和按执业人员稳定分桶的百分比灰度；不在灰度范围时能力接口明确返回不可用，直接调用同样被服务端拒绝。
- **已完成**：医生站支持当前建议与最近 50 条不可变历史记录切换，展示状态、时间、供应商/模型及连续追问父建议；历史结果没有采纳入口。
- 以明确时间窗读取历史诊断、处方、过敏、检验和当前库存；历史事实与本次建议分层。
- 续方先确认慢病范围，再生成候选；核心用法字段不完整时不得默认选中。
- prompt/model 版本、调用耗时、失败类型、采纳率和安全拦截率已有采集；“修改率”需在草稿编辑器增加字段级来源跟踪后再统计，不能用采纳事件替代。
- 建立离线金标准病例集、回归评测、灰度开关、供应商切换与院内数据留存策略。

## 4. 每阶段完成门禁

- AI 关闭、超时或返回畸形数据时，原医生站全流程仍可用。
- 任何模型输出都不能直接写核心临床表；写入必须由医生动作触发并经过原业务服务。
- 目录、库存、过敏、患者、就诊或文档版本变化后，旧建议不得采纳。
- 所有可回写诊断和医嘱都必须绑定院内标准 ID；自由文本只允许作为未选中的参考。
- 医生能看到生成来源、模型/提示词版本、有效期、依据和限制，并能反馈或拒绝。
- 测试同时覆盖正常、超时、非 2xx、空响应、非法 JSON、越权、串患者和迟到响应。

## 5. 上线顺序

先在 `LOCAL_ASSIST` 保持默认的前提下完成影子评测；再对试点科室开启 `MODEL` 只读建议；通过病例评审后开放病历/诊断草稿采纳；最后才逐类开放治疗推荐。药品推荐、慢病续方和语音留存不与 M1 同时放量。
