# V4：字段组合与门诊医嘱、收费分析

日期：2026-09-14。按用户本轮要求扩展现有体验版；不据此把 A07–A31 全部标为完成。

## 本轮行为

新建时仍先选择列表、排行、趋势、对比或综合看板，再描述业务需求。AI 现在可以选择业务来源、字段、聚合方式、筛选条件和分组，生成一个结构化分析计划，无需逐项开发专用指标接口。页面展示分析方案，查询本地 Oracle 数据，用户确认后保存；下次打开按最新数据及当前权限执行。

建议体验：

- 综合看板：“统计本月各科室有效药品医嘱条数、涉及患者去重人数及对应费用净发生额。”
- 排行分析：“本月门诊收费项目的费用净发生额排行，查看前10项。”
- 统计列表：“本月按医嘱类别统计医嘱条数，包含所有状态。”
- 趋势分析：“近30天有效药品医嘱涉及的患者去重人数，按日展示。”
- 统计列表：“分别统计本月各科室有效医嘱条数和全部门诊费用净发生额。”（费用不限定为这些医嘱对应费用。）

“实际收款收入”“医保到账”等没有接入的口径应说明缺少能力，不能用费用发生额替代。

## 数据目录与关联

| 来源 | 粒度与时间 | 可组合的字段/计算 | 已审核关联 |
| --- | --- | --- | --- |
| 门诊就诊 | 每次就诊，登记日期 | 就诊计数、患者去重、当前状态筛选 | RHN_VIS_ENC |
| 门诊确诊记录 | 本次就诊的有效确诊条目，首次记录日期 | 记录计数、就诊/患者去重、诊断名称/编码筛选 | RHN_VIS_ENC_DIAG → RHN_VIS_ENC，多对一 |
| 门诊医嘱 | 每条药品或服务医嘱，开立日期 | 条数、就诊/患者去重、状态/类别/项目筛选 | RHN_EX_CARE_REQ → RHN_VIS_ENC，多对一 |
| 门诊费用明细 | 每条已记账人民币费用，发生日期，含负数冲销行 | 费用行计数、金额求和/行平均、患者/就诊/关联医嘱去重、项目/金额/关联医嘱条件筛选 | RHN_BIL_CHARGE_ITEM → RHN_VIS_ENC，多对一；左关联 RHN_EX_CARE_REQ，多对一 |

所有关联带租户条件；费用到医嘱的关联还要求就诊一致。机构、科室归属均取自门诊就诊，不等于执行科室。普通医嘱需求默认有效状态 ACTIVE；所有状态需求保留草稿、有效、已完成和取消。

费用只包含已绑定门诊就诊的人民币已记账明细，包括未结算费用。正数与负数冲销按各自发生日期计入。未绑定就诊费用、其他币种不计入。“逐行平均”不是次均费用或人均费用。关联医嘱筛选只保留匹配的费用，未关联医嘱费用在没有医嘱筛选时保留。

## 实现约束

- `ReportSourceProvider` 由业务模块提供来源描述；`StructuredReportEngine` 用统一算法执行计数、去重、求和、平均。新增字段的组合无需再写专用指标分支。
- 首次使用来源时，通过零行 JDBC 投影读取真实列类型并校验数值聚合类型，检查来源及关联可执行；结果按进程缓存。它是已开放来源的结构校验，不是全库自动发现或自动批准任意表关联。
- 业务含义、粒度、默认状态、允许字段及多对一关联仍由服务端维护。AI 只接收目录、需求、日期和模板，不接收患者明细，也不能传入 SQL 或任意列名。
- 多个指标分别读取并汇总后按分组键对齐，不把诊断、医嘱和费用的多个一对多明细展开后聚合。总体去重/平均重新计算，不累加各组结果。
- 查询强制租户、机构、授权科室和日期边界，筛选值参数化；仅开放目录中的运算符，包含匹配转义通配符。单项最多五万条明细、查询超时15秒、1–100个授权科室、连续最多366天、最多4个指标。超限拒绝，不返回截断统计。
- 当前采用受限明细读取后在服务端汇总，不是生产级数据库聚合、专用分析库或全库 Text-to-SQL。未验证高并发与大数据容量。
- 新结构化定义保存为 `pageVersion=2`，携带字段来源版本、筛选条件、模板及相对日期规则；继续读取 `pageVersion=1` 和旧 `pilotVersion=1`。没有新增数据库迁移。
- 费用图表支持零线及负数柱形；结果底部标为“整体统计”，避免把去重和平均误认为列合计。

## 验证

后端 `StructuredAnalysisPageTest`、`AnalysisPageTest`、`AnalyticsPilotTest` 共13项通过（test profile，随机 H2，无 Oracle 测试写入）。新增验证覆盖：

- 同一医嘱三笔费用100、50、-100，费用净额50；两条有效医嘱不被收费关联放大。
- 同一患者跨日期出现，分组分别计1，总体仍为1；费用行平均为50/3。
- 医嘱类别/状态关联筛选、金额筛选；排行截取一项仍保留全部分组总量。
- 日期起止边界、外科室、外租户、住院、未绑定就诊、其他币种排除。
- 非法来源/字段/版本/聚合和筛选拒绝；SQL片段及通配符作为文字处理。
- 模型输入包含结构目录；生成、固化及读回保留来源、筛选和相对日期。
- 非排行模板缺少展示条数时确定性补10，不额外调用模型；完整业务字段仍严格校验。
- 模型格式错误最多自动修正一次，修正后仍校验字段及权限契约；失败原因在页面说明区显示，不保留“正在分析”的误导状态。

前端分析模块21项通过，包含字段方案展示、固化读回、生成失败反馈和负数柱形验证；构建通过，仍有既有大包提示。全仓 UI 规范检查仍有其他既有页面问题；本轮修改的 DynamicAnalysisLibrary 及其样式没有新增违规。实际 Oracle、真实模型与浏览器证据见 `V4-验证资产/`。

## 本地 Oracle 与真实模型结果

真实模型 qwen3.8-27b 生成三指标计划，查询当前机构12个可访问科室：有效药品医嘱10条，涉及患者去重5人，关联费用净发生额101.40元。当前科室全部费用项目排行为266.40元、6个项目分组。这些是验证时的本地业务数据，后续会随业务操作变化。

已在个人功能库保存“本月门诊药品医嘱与费用分析”和“本月门诊收费项目排行”，并验证后端重启后读回及再次执行。1440px及1920px截图见验证资产。真实模型的实收收入需求返回 UNSUPPORTED，未替换为费用发生额。

浏览器验证曾发现非排行页面的 limit 被模型输出为 null；已增加确定性默认值和回归用例。其他格式问题仍可进行一次带具体字段错误的模型修正；若仍失败，说明区明确反馈，不能保证模型服务每次输出都有效。

## 尚未开放

- 任意表发现后自动加入可执行范围；新来源仍需维护和校验语义及权限边界。
- 未定义的跨来源交叉筛选（如按诊断限定患者再计算其医嘱费用）；可下一轮用受控 EXISTS 关系计划扩展。
- 实收/退款支付流水、医保到账及跨结算行收款分摊；不能直接把结算或支付头金额连接到多行明细后求和。
- 动态比率、次均/人均、同比环比、患者明细导出及自动刷新任务。
