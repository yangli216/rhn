日期：2026-09-14。分支：`codex/analytics-a01`。状态：**开发验证通过·准入待验**。

本轮完成基础实现及合成环境验证。新增 analytics 模块自身分层无循环，存取及跨租户引用拒绝通过；仓库全局架构检查仍有既有循环，不能标记为全仓验收完成。真实 Oracle / PostgreSQL 迁移执行尚未验证，不据此开放真实数据。可以继续 A07 合成目录开发。

## 1. 实现范围

后端新增 `backend/src/main/java/com/rhn/analytics/`，包含 `api / application / domain / infrastructure / web`。不引用临床业务内部包，不扫描临床表、不生成 SQL、不调用模型。

| 对象 / 表 | 本轮内容 | 约束 |
| --- | --- | --- |
| AnalyticsCatalogVersion / RHN_AN_CATALOG_VER | 目录代码、版本、定义 JSON、CANDIDATE 初始状态 | `(tenant, code, version)` 唯一；当前版本对象不可变，无审批入口 |
| AnalysisDraftVersion / RHN_AN_DRAFT_VER | 逻辑草稿 ID、版本、所有者、固定目录版本、定义 JSON | `(tenant, draftId, version)` 唯一；不可变快照 |
| AnalysisRun / RHN_AN_RUN | 固定草稿版本行、所有者、修订号、运行与交付状态 | 初始 QUEUED / UNAVAILABLE；乐观锁；合法状态 CHECK |
| AnalysisAuditEvent / RHN_AN_AUDIT_EVT | 运行引用、操作者、事件代码与时间 | 追加式实体；没有问题原文或结果载荷字段 |

所有主键使用现有 `GlobalIds` Snowflake。数据库使用有符号 64 位数值；接口继续使用项目现有 boxed Long → 十进制字符串策略，版本号仍为整数。测试验证大于 JavaScript 安全整数范围的 ID 以字符串往返。新接口只返回能力开关，没有对外对象读取/写入接口。

每张表有 `(ID_TNT, 主键)` 唯一约束，目录版本→草稿版本→运行→审计的三个引用均由**租户复合外键**保护。Repository 只暴露保存与带租户的按 ID 查找，不提供全表读取、裸 ID 查找或删除。保存仅供内部基础实现使用，不是已授权的客户端命令。

`ID_DRAFT_VER` 是快照行的技术 ID；对外逻辑草稿标识为 `ID_DRAFT` 加 `NO_VERSION`。运行引用具体快照行，不会随新版本产生而改指向。此轮不实现会话指针、递增分配/CAS、确认回执、恢复、撤销或状态迁移命令；分别按 A09 / A12 / A17 接入。

目录定义与草稿正文目前是内部存储内容，不因成功保存就代表通过 A04 Schema、口径审核或执行授权。目录语义校验归 A07，计划校验归 A09。单个目录版本目前承载一个数据集的完整目录快照，后续指标拆分由 A07 演进。当前审计仅存与运行关联的基础事件；运行前拒绝、策略指纹、必要审计事务由 A12 扩展。

## 2. 双数据库迁移

- PostgreSQL：`backend/src/main/resources/db/migration/V1_42_0__analytics_foundation.sql`。
- Oracle：`backend/src/main/resources/db/oracle/V1_42_0__analytics_foundation.sql`。
- H2 测试适配：`backend/src/main/resources/db/h2/V1_42_1__analytics_h2_clob_types.sql`。

PostgreSQL 使用 bigint / integer / text；Oracle 使用 number(19) / number(10) / clob；时间均为 timestamp with time zone。表、索引、约束名均不超过 30 字符。双脚本经类型归一化后的定义完全一致。

JSON 字段沿用工程 `LONG32VARCHAR` 映射。H2 单独转 CLOB，以满足 Hibernate `ddl-auto: validate`；未通过禁用验证或修改既有迁移绕过类型检查。隔离 test 数据库从空库执行 42 个迁移并通过对象映射校验。

**H2 和文本结构一致性不等于真实 Oracle/PostgreSQL 方言通过。** 本轮没有连接手工 Oracle schema，没有执行真实数据库迁移；真实双数据库迁移、回滚/备份流程、账号资源限制须在专用测试环境补证，不使用 8080 手工库代替。

## 3. 入口与 OpenAPI

- 后端唯一新增接口：`GET /api/analytics/capabilities`，需要已有登录、租户、工作上下文及 `PORTAL.ACCESS`。该权限只允许读取非敏感能力状态，不代表统计授权。
- 后端 `rhn.analytics.enabled` 对应 `RHN_ANALYTICS_ENABLED`，默认 false。
- `queryExecutionEnabled` 在 A06 始终 false，即便入口开关为 true。
- 前端 `VITE_ANALYTICS_ENABLED=true` 才注册菜单、标签页和 `/analytics` 路由；默认不注册。已打开旧标签也不会绕过默认关闭条件。
- 页面根据后端能力显示“尚未开放”或“准备中”，失败时不开放操作。没有查询、运行、导出、语音或模型操作。
- UI 使用已有 PageHeader / Panel / PanelHead / Alert，未引入手机布局。A14 才建设多栏工作台。

OpenAPI 来源必须是 Springdoc 运行时输出，不能凭 A04 文档手写正式接口。先显式导出，再比对并同步当前改动，最后运行 `npm run api:generate`；前端能力类型引用生成的 `components.schemas.AnalyticsCapabilities`，不手写另一套响应字段。

本轮发现已有快照与运行时之间存在其他模块差异，因此仅同步新增 capabilities 路径和 schema；其余既有差异保持原状并记录为全仓契约校验遗留。统计接口局部契约匹配，不等于全仓 OpenAPI 已同步。
