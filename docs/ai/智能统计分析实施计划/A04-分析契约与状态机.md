## 2. 版本、标识与候选目录

- `schemaVersion`：结构版本，v1 不接受未知字段。增加新结构或改变字段含义时明确迁移，不能静默解释 v2。
- `datasetRef / metricRefs`：`业务名称@正整数版本`，不是物理表或 SQL；`@1` 是待实现目录候选版本，不能以存在此引用为理由绕过审核。
- `draftVersion / assetVersion / baseAssetRevision`：正整数，彼此不同。draftVersion 标识不可变草稿；assetVersion 标识不可变资产内容；assetRevision 是资产指针/生命周期/ACL 元数据的乐观锁修订号。
- 对象 ID：正的有符号 Long 范围内十进制字符串，禁止 JSON 数字、前导零及超出 `9223372036854775807`。A02/A03 的符号 ID 不直接作为 API 样例。
- `componentId`：草稿内稳定的 `c_...` 标识，删除后不复用给另一对象；不得采用数组位置定位标注。
- 上下文、授权指纹、实际范围、时区、数据水位、审核状态和 SQL 均由服务端生成，不是 AnalysisSpec 的客户端可写字段。

## 3. AnalysisSpec、QuerySpec、ViewSpec、ParameterSchema

完整 JSON 见样例文件，下面是各部分的冻结职责。

| 部分 / 字段 | v1 规则 |
| --- | --- |
| 根 | 必须且仅有 schemaVersion、querySpec、viewSpec、parameterSchema |
| querySpec.datasetRef | 一个版本化候选数据集，不接受 joins、table、SQL 或脚本 |
| querySpec.metricRefs | 1–4 个不重复、同数据集指标；目录/授权可进一步收紧 |
| querySpec.dimensions | 0–3 个唯一值：department、calendar_day、calendar_month、registration_source、visit_type；不开放患者/医生维度 |
| querySpec.filters | 最多两项；只允许来源/就诊类型的 IN 枚举筛选；同字段不得重复；两字段之间 AND，各字段 values 内 OR；空 values 拒绝 |
| querySpec.timeParameter / scopeParameter | v1 固定绑定 period / scope，不能任意引用其他字段或表达式 |
| querySpec.comparison | NONE 或 PREVIOUS_CALENDAR_MONTH；比较期与主期同权限和口径，计入同一预算 |
| querySpec.asOfPolicy | 固定 LATEST_COMPARABLE_WATERMARK；客户端不设置任意历史 asOf 来假装可复现 |
| parameterSchema.period | type=TIME_WINDOW，defaultValue 为固定日期窗或 PREVIOUS_CALENDAR_MONTH 相对周期 |
| parameterSchema.scope | type=SCOPE_INTENT，defaultValue 为四种受限范围意图之一；默认值不是授权 |
| viewSpec | gridColumns=12，1–8 个组件；没有 HTML、JS、URL、回调、动态 CSS 或网络数据源 |
| 组件 | 唯一 componentId；KPI/TABLE/BAR/LINE；纯文本 title 1–120 字符；metricRefs 为查询指标子集；dimensions 必须与查询分组集合相同，避免隐式再聚合 |
| 组件布局/格式 | columnSpan 3–12，decimals 0–4；只控制显示。计数、分母保护与真实精度仍由目录/结果类型决定 |

KPI 只允许无分组且单指标；BAR 恰有一个分组维度；LINE 恰有一个日/月时间维度；TABLE 可以显示全部已查询维度。一个分组查询不能再放一个隐式跨科室总计 KPI，需要明确的受控总计能力后再扩展。比例和去重人数尤其不能在前端求平均/相加。

Schema 的字段长度、数组大小是结构上限，不是查询预算保证。真实最大日期范围、行数、资源并发与 10 秒等试点建议仍由 A11 的服务端策略限制，客户端不能通过 ParameterSchema 提高它们。

标题、批注、维度显示名始终视作不可信纯文本并安全渲染。Schema 不尝试用 SQL/HTML 关键字黑名单判断自由文本安全；即使文本中出现“执行 SQL”也没有执行能力。可写的图表结构本身没有脚本字段。

### 3.1 参数默认值、解析和覆盖

RunRequest.parameters 只允许可选 period、scope；缺省使用资产/草稿的 ParameterSchema 默认值。v1 固定两个参数槽，不支持任意参数名、SQL 变量、临床对象字段引用或动态表单脚本。A02 的合成患者 ID 不能成为参数。

替换参数后重新执行同一结构和语义校验，包括日期顺序、完整自然月比较、范围意图、指标/目录权限及成本准入；不能只验证保存时的默认值。参数表单允许的类型和语法不代表实际每个值都可执行，未授权科室或超预算范围仍拒绝。

### 3.2 时间窗与比较期

固定周期输入为 `{kind: FIXED, startDate: YYYY-MM-DD, endDateExclusive: YYYY-MM-DD}`，左含右不含，必须 startDate < endDateExclusive。机构 IANA 时区从服务端读取；缺失/非法时区返回配置错误，不照抄门户的静默时区回退。

相对周期 v1 只支持 `{kind: RELATIVE, preset: PREVIOUS_CALENDAR_MONTH}`，每次运行按服务端当前时间在机构时区重新解析，展示实际日期后执行。半年汇总、滚动 N 天与多查询时间窗留待后续版本，不通过放大原始扫描实现。

PREVIOUS_CALENDAR_MONTH 比较只接受一个完整自然月（相对上月或固定月首至下月月首）。比较期为该月前一完整自然月，不是固定减去 30 天。例如 2026-01-01 至 02-01 对比 2025-12-01 至 2026-01-01。

v1 比较仅按非时间维度分组；按日/月维度的同期对齐尚未冻结，返回 COMPARISON_DIMENSION_UNSUPPORTED。普通无比较查询仍可按日/月画趋势。

所有组件使用同一受控结果/水位；当前期与比较期必须可比较。W 指数据可用截止/快照，不等于用户时间窗终点。队列 M04/M08 等会因 W 推进发生变化，定义本身不保证历史数值复现；完全复现要额外保留获批快照。

### 3.3 范围意图与确认

| scope.kind | 服务端解释 |
| --- | --- |
| CURRENT_DEPARTMENT | 当前可信工作科室，且必须在统计授权内 |
| CURRENT_AUTHORIZED | 当前机构内实际批准的统计科室集合，标明部分/全部范围 |
| FULL_CURRENT_ORGANIZATION | 明确请求当前一家医院全量；授权不完整则拒绝，不静默缩小 |
| EXPLICIT_DEPARTMENTS | departmentIds 只是请求意图；全部必须属于当前机构且获授权，混合越权整体拒绝 |

没有客户端 tenantId、organizationId、authorizedDepartmentIds 或执行授权 token 字段。更换机构先切换可信工作上下文，再重新校验/确认。确认回执 confirmationId 仅是“某人已确认某份口径”的引用，不是数据访问凭证。

## 4. 会话、标注、版本与确认回执

会话只持有最新草稿指针和交互状态，READY 表示已有可解释的有效草稿，不代表已获执行权或已完成用户确认。

- 初始输入 `OPEN`；有影响结果的歧义进入 `CLARIFICATION_REQUIRED`；解决歧义生成有效草稿后 `READY`；新需求或关键修改回到 OPEN/澄清；归档后只读，继续使用创建新会话。
- DraftVersion 内容不可变；应用完整受限 proposedSpec 时携带 baseDraftVersion 和 proposalId。后端计算差异，不能相信模型声明“仅改样式”。v1 不接受通用 JSON Patch 路径和可执行补丁。
- 变更提案状态 PROPOSED→ACCEPTED/REJECTED/CONFLICTED。引用基础版本已过期、对象删除或并发写入冲突时不静默覆盖，返回冲突并重新生成提案。
- AnnotationRequest 必须有 baseDraftVersion、componentId、text；可有 fieldRef 和 dimensionValue。数据点值出现时必须标出所属字段，后端核对该版本内对象、字段和值的合法性；物理字段/不可见值不能被批注注入。
- 撤销/重做通过复制选定历史内容产生全新递增草稿版本，保留原始版本和 provenance；不是覆写旧行或减少版本号。
- QuerySpec、参数默认值或当前参数变化需要重新解释和确认；纯 ViewSpec 变化立即预览并可撤销。复用结果前仍核验查询指纹、当前权限、策略/目录版本、水位与有效期。

确认流程：校验草稿和参数→服务端生成 interpretationId 及理解卡（实际周期、指标/版本、实际范围和口径）→用户确认该 interpretationId→生成短时 confirmationId。回执绑定主体、工作上下文、draftVersion、QuerySpec/有效参数/范围指纹及过期时间。客户端只能回传 ID，不能自填指纹充当确认。

运行时重新解析和鉴权。跨月导致实际日期变化、范围变化、查询修改、回执过期均返回 ANALYTICS_CONFIRMATION_STALE；重新展示后再确认。水位推进本身按 LATEST_COMPARABLE_WATERMARK 规则展示最新截至时间，不因此反复要求确认，除非实际口径/范围发生变化。

已发布资产的正常参数化复用按其已审核定义运行，不重新调用 AI，不要求草稿确认回执；用户修改查询口径则产生新草稿并重新确认，不能把修改伪装为参数覆盖。

## 5. 运行、结果交付与发布状态机

机器可读边和守卫见 state-machines.json；下表是实施必须保留的含义。状态边只是必要条件，所有迁移仍需相应事件、动作、对象、版本和事务守卫。

| 对象 | 状态与核心规则 |
| --- | --- |
| Session | OPEN / CLARIFICATION_REQUIRED / READY / ARCHIVED；归档不可继续原地写入 |
| ChangeProposal | PROPOSED / ACCEPTED / REJECTED / CONFLICTED；后三者终态 |
| QueryRun | QUEUED / RUNNING / CANCEL_REQUESTED / SUCCEEDED / FAILED / REJECTED / CANCELLED；后四者终态 |
| ResultDelivery | UNAVAILABLE / AVAILABLE / REVOKED / EXPIRED / PURGED；与运行执行状态分离 |
| AssetVersion | DRAFT / IN_REVIEW / PUBLISHED / SUSPENDED / RETIRED；退休版本不可恢复 |
| AssetLifecycle | ACTIVE / SUSPENDED / RETIRED；整体停用阻断所有版本，指定旧版本不能绕过 |

### 5.1 运行与结果

同步结构/对象校验失败直接返回 4xx，不创建可运行任务；通过准入后 POST runs 返回 202 与 QUEUED 对象。真正开始前重新鉴权，若期间授权/目录/策略变化则 QUEUED→REJECTED。

RUNNING 只有在受保护结果和必要审计就绪、执行资源释放后才能 SUCCEEDED；真实执行错误且资源已释放才 FAILED。超时、撤权或取消触发 CANCEL_REQUESTED；数据库未确认停止时维持该状态并告警，交付关闭。取消失败不假装 CANCELLED，也不能释放配额后让隐形 SQL 无限继续运行。

完成与取消通过同一运行修订号/CAS 竞争：若取消先提交，完成回调不得再标成功或交付；若成功先提交，取消请求返回终态，不伪造一次已停止的执行。撤权仍独立将交付变为 REVOKED。

SUCCEEDED 是历史执行事实，撤权后不改写它；读取旧结果时由 delivery 状态和当前权限拒绝。REVOKED 不因后来重新授权自动恢复，需新运行；EXPIRED/PURGED 不可当作可下载结果。

### 5.2 个人保存与共享发布

私人保存可 DRAFT→PUBLISHED，严格要求 owner_saves_private_asset 事件、作者身份且 PRIVATE ACL；它表示可复用的私有版本，不是共享批准。升级为科室/全院共享必须新建版本并 DRAFT→IN_REVIEW→PUBLISHED，不能改 PRIVATE 标志绕过审核。

共享审核驳回/撤回回到 DRAFT；审核请求固定到版本内容哈希与 reviewId。审核中继续编辑会产生新草稿，不改变正在审核的快照。发布版本内容永远不可变；允许变更的是独立生命周期状态和元数据，不是 QuerySpec 本身。

版本例子：v1 已发布，v2 审核中时资产 publishedVersion 指针仍为 v1；v2 审核通过后原子切换指针，v1 内容不变。回滚只将指针指向仍为 PUBLISHED、目录/策略/ACL/依赖仍有效的旧版，必须持当前发布范围权限、使用 baseAssetRevision 并追加审计；不能回滚到 RETIRED/SUSPENDED 版本。

## 6. API 草案（尚不存在的目标接口）

路由统一前缀 `/api/analytics`。v1 只冻结个人闭环必要输入，科室/全院发布提前冻结状态与命令边界，按 A21 实现；导出/语音/明细不开启。下面未纳入 JSON Schema 的小型 envelope 仍遵循列明字段、拒绝未知字段和项目统一校验规范。

| --- | --- | --- |

| GET /assets/{id} | URL 引用 | 200 ACL 允许的定义及版本；READ；模板无权不能暴露作者数据 |
| POST /assets/{id}/reviews | assetVersion、baseAssetRevision、targetScope；必需幂等键 | 201 reviewId/IN_REVIEW；对应 PUBLISH_DEPARTMENT/ORGANIZATION+范围；targetScope 只为当前机构或获准目标科室 |
| POST /assets/{id}/reviews/{reviewId}/decision | ReviewDecisionRequest；body reviewId 必须与 URL 一致；必需幂等键 | 200 版本/修订号/发布指针；APPROVE+审核范围、非自审、依赖与CAS |
| POST /assets/{id}/rollback | targetAssetVersion、baseAssetRevision、reason；必需幂等键 | 200 更新指针；对应发布权限+范围/依赖，私有资产限 owner |
| POST /assets/{id}/lifecycle | baseAssetRevision、action=SUSPEND/RESUME/RETIRE、reason；必需幂等键 | 200 新状态/修订号；MANAGE_ASSETS+管理范围；私有资产 owner 可自行停用/退休 |
| POST /assets/{id}/transfer-owner | baseAssetRevision、targetOwnerId、reason；必需幂等键 | 200 新所有者/修订号；MANAGE_ASSETS，目标同租户并具备维护资格，不扩大共享范围 |

targetScope 固定为 `{kind: DEPARTMENT, departmentId}` 或 `{kind: ORGANIZATION}`，机构只取当前可信上下文；reason 均为 1–1000 字符纯文本。interpretations/validations 的 parameters 只允许 period/scope 并应用同一 schema；缺省为空。

所有对象 ID 输入用字符串、版本用正整数；默认值不接受缺失后扩大授权的推断。每个接口在实现时都必须同步 OpenAPI 和前端生成类型。本轮 schema 和草案存于计划目录，现有 `docs/api/openapi.json` 保持真实已实现接口，不把计划伪装成可调用服务。

### 6.1 补齐 A03 留给 A04 的管理动作

在原九项候选动作基础上，新增拟议 `ANALYTICS.MANAGE_ASSETS`（资产停用/恢复/退休/移交的作用域管理）、`ANALYTICS.MANAGE_EXECUTION`（取消他人任务/场景停用的限定运维权）、`ANALYTICS.AUDIT_READ`（受控审计查阅）。这些都不是数据访问权或管理员全局绕过；需单独迁移和授权，不修改 A03 历史合成身份默认权限。

受信有效主体取消同租户本人任务时，即使 RUN 数据授权已撤销也允许发出停止指令；响应只含最小状态，不读取结果。取消他人任务需 MANAGE_EXECUTION 和目标范围。完全失效/停用身份不能继续登录调用，由治理服务完成取消。审计查阅接口只保留 READ 动作边界，正式查询字段和部署能力到 A25 再实现，不用 MANAGE_CATALOG 承担所有运维操作。

## 7. 幂等、并发与结果绑定

### 7.1 幂等键与生命周期

运行、取消、保存、发布审核决策、回滚和管理命令使用 Idempotency-Key；键为 8–128 字符的 ASCII 字母/数字/下划线/连字符，客户端为一个逻辑命令生成一次，重试不换键。新的逻辑命令必须新键。

命名空间至少 `(tenantId, subjectId, trustedWorkContext, operation, key)`；规范化请求哈希包含目标对象、基础版本、源版本、有效参数和命令内容，不包含客户端自填的权限。结构校验/当前身份及对象检查在重放前执行，不能从旧响应直接交付敏感数据。

[现有 IdempotencyService](../../../backend/rhn-platform/src/main/java/com/rhn/platform/idempotency/IdempotencyService.java) 只按 tenantId/operationCode/key 查找，创建记录采用 24 小时时长。analytics 不直接原样复用用户 key：通过独立适配生成带主体/上下文命名空间的固定长度摘要键，并使用持久命令回执关联资源。现有 responseJson 也不能作为无需重新鉴权的结果缓存。

相同命名空间同内容：已受理返回同一资源 ID；处理中返回 IDEMPOTENCY_IN_PROGRESS 或同一已创建的任务，不重复执行。相同键不同内容返回 IDEMPOTENCY_KEY_REUSED。数据库唯一约束/事务处理并发首次提交，不能仅靠先查后插。

24 小时临时缓存过期不得导致长任务或发布命令重新执行。持久命令回执/已完成键的受控标记需覆盖资源生命周期及允许重试窗口；键已过期但仍可识别时返回 410 ANALYTICS_COMMAND_EXPIRED，引导读取原资源。正式回执/标记清理、旧键识别窗口按 A03 D09 确定前，不开放真实命令执行；禁止在没有可识别旧键的机制时先清理回执再接受无界重试。此项是必须满足的准入条件，不将底座 24h 当成已解决的长期幂等能力。

### 7.2 乐观并发

- 草稿变更、恢复检查 baseDraftVersion；会话检查 baseSessionRevision；资产元数据/指针检查 baseAssetRevision；审核固定 reviewId+assetVersion+内容指纹。
- 基础版本不匹配返回 409，不自动合并计算口径；普通格式编辑也不能静默覆盖别人删除的组件。
- 接受提案、创建新草稿及更新指针须同事务；发布版本、审批事件、资产指针也须原子提交。失败重试用原幂等键。
- 幂等重放检查须能识别“本人该命令已成功”再返回当时的资源，不因自己的首次成功已推进版本而误报冲突；但当前权限仍先检查。

### 7.3 ResultManifest 冻结字段与消费规则

服务端结果清单至少包括：runId、source（类型、对象ID、版本）、queryFingerprint、effectiveParameters（实际日期/参数）、effectiveScope（有权可见的机构与科室、coverage=DEPARTMENT/PARTIAL_ORGANIZATION/FULL_ORGANIZATION）、organizationTimeZone、catalogVersions、policyVersion、asOfWatermark、executionState、deliveryState、resultRevision、expiresAt、precisionStatus、privacyStatus 和受控数据页引用。授权指纹仅限服务端使用或不透明标记，不发授权谓词。

expiresAt 为服务端带时区到期瞬时；precisionStatus 为 EXACT/TRUNCATED/SAMPLED，privacyStatus 为 CLEAR/PROTECTED。未就绪/被拒绝时不给数据页；清单指纹不包含可读权限谓词。

数据页字段来自受控列目录：维度列返回授权业务键/显示值；整数计数用十进制字符串，比例/增长用精确十进制字符串或 null；保护后值带 status=VALUE/SUPPRESSED/ZERO_DENOMINATOR/NO_DATA。被抑制的原值/分子分母不出现在响应、tooltip 或摘要。返回 SAMPLED/TRUNCATED 时显著标注不精确；v1 不自动启用抽样，超预算优先拒绝，不能只加 LIMIT 就称全量统计。

客户端只能将匹配当前草稿/参数请求的结果放入当前预览。旧运行晚返回保留在历史列表，不能覆盖新版本。纯 ViewSpec 产生新草稿时可建立显式的结果复用关联，保持原 QueryRun 的源版本不变；复用仍重鉴权并核对查询与结果指纹，不篡改旧运行记录来“适配”新版本。

## 8. 错误类型与降级

复用现有 [ApiError](../../../backend/rhn-kernel/src/main/java/com/rhn/shared/api/ApiError.java)：`code / message / correlationId / timestamp / violations[{field,message}]`，不私自增加会泄露 SQL/患者原文的 debug 字段。字段路径使用客户端 JSON 路径；消息为安全业务描述，内部异常只进入受保护诊断通道。

| HTTP / 分类 | 稳定代码 | 处理 |
| --- | --- | --- |
| 400 结构错误 | ANALYTICS_SCHEMA_INVALID、ANALYTICS_IDENTIFIER_OUT_OF_RANGE | 未知字段、错误版本形状、脚本字段、数字 ID 或越界 ID；修正请求 |
| 401 身份 | 沿用现有认证错误契约 | 重新认证 |
| 403 权限 | ACCESS_DENIED、ANALYTICS_SCOPE_FORBIDDEN、ANALYTICS_PURPOSE_FORBIDDEN | 不缩小范围冒充原请求；可另行选择有权范围 |
| 404 对象 | ANALYTICS_OBJECT_NOT_FOUND | 不存在和不可访问统一，避免枚举对象 |
| 409 版本/状态 | ANALYTICS_DRAFT_VERSION_CONFLICT、ANALYTICS_ASSET_REVISION_CONFLICT、ANALYTICS_VERSION_IMMUTABLE、ANALYTICS_STATE_CONFLICT | 重新读取/生成提案，不静默覆盖 |
| 409 确认/结果 | ANALYTICS_CONFIRMATION_STALE、ANALYTICS_RESULT_NOT_READY | 重新展示确认或等待运行；不交付旧结果 |
| 409 幂等 | IDEMPOTENCY_KEY_REUSED、IDEMPOTENCY_IN_PROGRESS | 不同请求新建命令；同请求跟随原任务 |
| 410 生命周期 | ANALYTICS_RESULT_EXPIRED、ANALYTICS_COMMAND_EXPIRED | 读取原资源记录或重新发起新的明确命令 |
| 422 目录/口径 | ANALYTICS_CATALOG_REFERENCE_UNAVAILABLE、ANALYTICS_CATALOG_NOT_APPROVED、ANALYTICS_METRIC_DATASET_MISMATCH、ANALYTICS_CLARIFICATION_REQUIRED | 目录无权/未知引用同样不暴露细节；未批准不得执行 |
| 422 时间/展示 | ANALYTICS_TIME_RANGE_INVALID、ANALYTICS_COMPARISON_WINDOW_INVALID、ANALYTICS_COMPARISON_REQUIRED、ANALYTICS_COMPARISON_DIMENSION_UNSUPPORTED、ANALYTICS_VIEW_REFERENCE_INVALID、ANALYTICS_VIEW_SHAPE_INVALID、ANALYTICS_COMPONENT_ID_DUPLICATE、ANALYTICS_FILTER_DUPLICATE、ANALYTICS_ANNOTATION_TARGET_INCOMPLETE | 错误明确到字段，不能让模型兜底猜计算方式 |
| 422 质量/成本 | ANALYTICS_DATA_QUALITY_FAILED、ANALYTICS_BUDGET_EXCEEDED | 修复质量或缩小周期/采用已审核汇总；大查询不靠分页解决 |
| 429 配额 | ANALYTICS_QUOTA_EXCEEDED | 等待或缩小需求；不无限自动重试 |
| 503 故障 | ANALYTICS_POLICY_UNAVAILABLE、ANALYTICS_AUDIT_UNAVAILABLE、ANALYTICS_MODEL_UNAVAILABLE、ANALYTICS_TIMEZONE_UNAVAILABLE | 策略/必要审计/时区失败关闭；模型不可用可回表单和已批准报表 |

局部验证器的结果码省略 `ANALYTICS_` 前缀；后端须按本表映射。隐私抑制/零分母是保护后结果状态，通常返回 200 及明确标记；整个请求触发差分推断拒绝时返回 403 ANALYTICS_PRIVACY_RESTRICTED。不能把被抑制的值显示为 0，也不能把权限失败变成空表。
