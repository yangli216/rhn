### 2.1 时间、状态与组织归属的关键差异

1. **两份挂号时间分别赋值**：Encounter 构造与 PatientRegistration 构造各自调用 `Instant.now()` 写 `DT_REGISTERED`，不是强制同一时间。跨午夜时可能影响按日分组。A02 必须选定权威时间，不能在不同指标中无说明地切换。
2. **挂号状态没有自动变为 COMPLETED**：E04 的 `PatientRegistration.complete()` 只在 `REGISTERED` 且完成时间为空时写 `DT_COMPLETED`，不修改状态；`start()` 同样只写开始时间。用挂号 `SD_STATUS='COMPLETED'` 计诊毕不成立。
3. **挂号完成时间也不能单独判诊毕**：E05 的 `markCompleted`、`markTransferred`、`markTerminated` 均调用 `registration.complete()`。就诊实体的 `transfer()` 也会写 `DT_COMPLETED`。候选诊毕指标须同时明确就诊状态 `COMPLETED` 与权威完成时间，排除 `TRANSFERRED / TERMINATED / CANCELLED`。
4. **没有统一的挂号退号时间字段**：Encounter 与 PatientRegistration 的取消方法只改状态；预约虽有 `DT_CANCELLED`，但直接挂号可能无预约。按退号发生日期统计应优先评估 `RHN_VIS_ENC_STATUS_EVT` 的 `CANCELLED` 事件时间；不能使用挂号时间、完成时间或预约取消时间冒充。
5. **事件发生时间与实体时间不是完全相同的时间戳**：状态事件、实体完成和 Outbox 发布各自取当前时间。后续投影需要选定事实时间，并区分业务发生、投影到达、水位时间。
6. **时区行为不统一**：E10 门户使用机构 `CD_TIMEZONE`，缺失/错误时回退 Asia/Shanghai；E05 队列查询使用 `BUSINESS_ZONE`。统计相对日期应明确机构时区和半开区间，不照抄某个页面实现。
7. **转科产生新就诊与新挂号**：E11 接收转科会创建目标科室 Encounter、来源/类型均为 `TRANSFER` 的挂号；原就诊变为 `TRANSFERRED`。汇总挂号条数时可能把一次连续诊疗计作两条，必须确认是否按条次或连续诊疗链统计。
8. **医生维度需映射治理**：E03 通过 `context.actor()` 写 `ID_CLINICIAN`（字符串），恢复接诊会重新写该值；状态事件/工作会话保存 `ID_PRACT` 与 `ID_USER`。不能直接把 clinician 字符串当人员 Snowflake ID，排班医生、首诊医生、最后接诊医生和诊毕操作者也不是天然相同。
9. **组织有事实 ID，但未证明历史名称快照完整**：就诊/挂号保留机构与科室 ID，状态事件复制当时 ID；连接当前组织目录获得名称可能显示新名称。科室改名/合并和 MPI 合并拆分的历史统计政策仍待定。
10. **FOLLOW_UP 已存在但不等于复诊指标已治理**：E05 允许 `GENERAL / FOLLOW_UP / EMERGENCY / TRANSFER`，空值默认为 GENERAL。本轮未证明各入口是否按统一业务规则标注、历史漏标率或与“患者 N 天内再次就诊”的对应关系。

## 3. 三条完整来源链

### 3.1 挂号成功

**入口 → 业务 → 存储 → 状态事件/Outbox → 现有读取与验证线索**：

- E01：`POST /api/encounters` → `EncounterService.register`。E09 另有 `POST /api/billing/registration-intents` → 零费完成或支付完成处理 → `EncounterDirectory.completeRegistration` → 同一个 register；创建支付意向不意味着已经创建就诊。
- E03：幂等查询、居民可挂号校验、机构科室校验和有效期内重复就诊检查后创建 Encounter。
- E05：通过公开 `OutpatientRegistrationDirectory.register` 校验预约/班次、消耗号源或锁定记录，创建 PatientRegistration 并登记候诊票；直接挂号可以没有预约和班次。
- E03：绑定挂号信息，追加 `REGISTERED` 状态事件、flush，发布 `OUTPATIENT_REGISTERED`（事件版本 1）；E14 持久化 Outbox。事件 envelope 有租户/机构/聚合标识和版本，普通挂号 payload 含科室等信息。
- E10 门户读取就诊表按当前科室和当天挂号时间计数；E19 的现金/零费挂号、幂等和异步支付用例可作为后续基线素材。本轮仅检查源码。

**候选统计落点**：优先以挂号事实主键计挂号条数；和就诊对账，确认权威时间、排除退号及转科规则后登记。支付待处理、挂号失败和号源锁定不直接算挂号成功。

### 3.2 退号完成

- E08：`POST /api/encounters/{encounterId}/cancel` → coordination `OutpatientCancellationService.cancel`。
- outpatient `prepare` 先锁定并检查租户/上下文、未开始接诊以及候诊/预约可取消状态。
- billing `cancelBeforeService` 处理财务取消/退款。只有 `readyToClose=true` 才继续关闭门诊；`CANCELLATION_PENDING / CANCELLATION_FAILED` 返回未完成，不能作为退号完成事实。
- outpatient `cancelBeforeService` → registration 取消候诊、设置挂号 `CANCELLED`；有关联预约时取消预约、返还号源并记事件；Encounter 追加 `REGISTERED→CANCELLED` 状态事件并改为 `CANCELLED`。
- 同时发布 `OUTPATIENT_REGISTRATION_CANCELLED`（事件版本 1）；重复取消已取消 Encounter 不再产生新的取消事件。状态事件有科室和发生时间；Outbox payload 本身不是完整分析行。
- E19 包含 `unserved_paid_registration_is_atomically_refunded_cancelled_and_returns_the_slot`、`started_encounter_cannot_be_withdrawn`；测试断言涉及就诊/挂号/队列/预约/财务状态及返还号源。本轮未执行。

**候选统计落点**：按退号发生期评估取消状态事件，以就诊/挂号去重；按挂号队列回看退号比例则使用另一套时间归因。历史事件缺失时，只能核实当前已取消记录，不能臆造取消日期。预约取消、退款请求和接诊后终止分别建模。

### 3.3 完成接诊

- E01：`POST /api/encounters/{encounterId}/complete` → E03 `EncounterService.complete`。
- 锁定就诊、获取上下文、检查未结束会诊并保留幂等命令；核对签署病历、身份核验、主诊断等，由 E12 `EncounterCompletionService.evaluate` 按配置给出诊毕决策。
- 通过后追加 `IN_PROGRESS→COMPLETED` 状态事件、关闭活动工作会话，`Encounter.complete()` 设置状态与 `DT_COMPLETED`。
- `OutpatientRegistrationDirectory.markCompleted` 完成候诊并写挂号完成时间，关联预约记 VISITED；flush 后发布 `ENCOUNTER_COMPLETED`（事件版本 1），最后完成幂等响应。
- E10 门户使用就诊 `SD_STATUS='COMPLETED' AND DT_COMPLETED >= 当天开始`；E20 的诊毕检查/追加事实测试和 E21 事件重复投影测试可复用为后续素材，本轮未执行。

**候选统计落点**：按完成期计当前明确 COMPLETED 的就诊条数，状态事件用于追溯/对账；终止、转科单列。历史时点“当时完成数”与“当前状态回看历史”是否等价需单独确认。

## 5. 首批能力白名单（候选范围）

以下全部 **代码事实可追踪、真实数据待核实、业务口径待确认**。A02 只能先据此建立合成事实和候选指标；不能把本表注册成“已审核”生产目录。

| 候选能力 | 初步边界 | 进入真实目录前条件 |
| --- | --- | --- |
| 挂号条数 | 按挂号事实计数；明确挂号发生日期及是否含取消/转科 | 定权威时间、转科口径，核验就诊关联 |
| 有效挂号条数 | 从同一挂号队列排除已取消项 | 明确当前有效还是截止历史时点有效；跨月退号如何回看 |
| 退号完成条数 | 按 CANCELLED 状态事件统计，不把退款处理请求当完成 | 验证历史事件完整、去重规则、日期归因 |
| 已完成接诊人次 | 就诊 COMPLETED 加权威完成时间 | 明确排除终止/转科，验证主表与事件/挂号对账 |

| 科室/时间趋势、环比 | 同一已治理指标按事实科室和机构时区分日/月，当前期与比较期同授权 | 确认归属与日历区间；半年趋势待独立汇总策略，不放开原始扫描 |
| 挂号来源/就诊类型分组 | 来源和 GENERAL/FOLLOW_UP/EMERGENCY/TRANSFER 分类的分布 | 核实入口默认值、字典与历史完整率；不自动命名为初复诊率 |
| 医生分组（有条件候选） | 只在实际接诊人员映射与归属规则确定后开放 | 区分账号 actor、ID_PRACT、排班医生与恢复接诊后的变化；未完成映射先关闭 |

首批展示范围：聚合指标卡、表格、柱状/折线及明确口径的比较；机构/科室仅来自统计授权策略；默认不开放患者明细。这里定义的是范围建议，尚未设计指标 ID、接口或实现图表。
