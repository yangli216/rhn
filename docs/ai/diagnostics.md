# 医技作业边界与业务闭环

用户于 2026-10-13 同意检查检验完善方案，并要求简化审核：首期采用保存草稿、直接签发；机构可选第二签发人，不建立提交/驳回/撤回/多级审批状态机。

## 复用入口

- `rhn-clinical/com.rhn.diagnostics` 继续拥有统一执行任务、结构化报告、版本替代和危急值账本。
- 检验/检查分别进入 `/diagnostics/laboratory`、`/diagnostics/examination`；工作台复用 WorkbenchPage，录入表单按领域分开。
- 草稿仅是当前工作内容；正式报告不可原位修改。更正保留旧版并填写原因。外部 PRELIMINARY 不等于本地待审核。
- 配置经 ConfigurationDirectory 读取；打印经 PrintDataProvider 与现有平台模板/介质/制品体系接入；不能创建平行实现。
- 主数据负责组合指标、参考区间与词条定义；当前机构确认的规则进入报告快照。无适用规则不得自动记录正常。

## 简单签发规则

默认保留单人签发；检验/检查分别通过机构级 `diagnostics.laboratory.double-sign.required`、`diagnostics.examination.double-sign.required` 开关启用第二人签发。第二人直接打开保存的草稿签发；修改草稿后该修改人即录入人，不沿用旧内容的签名。签发身份由后端工作上下文确定，不接受前端传自由姓名。

保存草稿不完成任务；只有已持久化的有效正式报告才能完成执行。报告、结果和实际签发人通过同一事务与既有事件投影关联。并发草稿修改依 revision 拒绝覆盖，签发请求需稳定幂等键。

## 必须保持的事实

- 门诊结算放行和住院执行计费分别沿用现有路径，不能因多指标或双签重复记费。
- 采集或执行后即使尚未签发，也不能按未执行直接退费；写入退费时锁住任务并重新检查，不能仅依旧页面预检。
- 任务、草稿、报告、标本和附件必须属于同一租户及允许的机构/科室、患者与申请。
- 原始危急值、通知、确认和更正历史可追溯；临床确认与医技通报是不同动作。
- 条码对应实际标本；共管、多管、拒收和重采保留历史；不能把任务 ID 当标本号。
- 采血管/容器推荐与分管只来自后端主数据分管规则：`POST /api/diagnostics/specimens/plan` 与生成条码共用同一试算，只读且不占号；前端不按项目名称关键词猜管，试算失败要显示原因，已生成标本以其实际容器为准。
- 签发与打印冻结版本、图片和身份；旧版/撤销版不得冒充当前有效报告。

## 交付范围与验证

业务闭环交付包含两工作台、持久草稿/可选双签、多指标与检查所见、标本扫码/拒收/重采、规则模板、危急值通报、报告与条码打印、检查图片附件、临床报告消费及资金保护。仪器协议、完整 LIS 质控、PACS 归档、预约叫号和 CA 接入属于后续专项。

新增/调整 API、迁移、权限、资金或共享打印需完整外环与 CI，并另检 H2 增量迁移、Oracle 对等迁移、OpenAPI 和生成类型。内环只跑实际受影响的单文件测试/UI 检查。日志存任务工作区 `.runtime/verification/`；真实浏览器、实体打印机和临床验收需明确授权，不能用 DOM 或健康检查替代。

## 机构报告模板与结果规则

- `DiagnosticTemplateDirectory` 是主数据公开契约；机构/诊疗项目内直接发布不可变版本，记录生效日期、确认依据及实际发布人，不增加审批状态机。发布沿用 `MASTER_DATA.MANAGE`、既有目录身份和维护的单位代码。
- `DiagnosticTemplateResolver` 在保存时匹配机构、项目和业务日期；年龄/性别来自居民资料，仪器/生理状态从机构规则可选条件录入。已保存草稿可继续原版本，新模板不重算历史。正式报告和 Observation 保存模板/规则快照。
- 数值比较符 `EQ/LT/LE/GT/GE` 独立保存、显示及打印。机构模板限制必填、允许编码、精度和单位；无适用规则不推断正常；规则冲突或比较符可能涉及危急范围需核对，不静默舍入或放行。
- 模板维护复用项目“执行与收费”中的 xwide Dialog；工作台显式载入模板，检查词条显式插入，`{{...}}` 等未填写占位项禁止签发。检查执行前的核对和草稿危急值通报仍属于后续业务闭环工作包，不以模板/签发测试替代。

## 报告查询与作业队列

- `/diagnostics/laboratory/reports` 和 `/diagnostics/examination/reports` 是独立报告查询入口，使用 ListPage 和限宽报告弹窗查看不可变报告及更正记录；版本操作固定在顶部，正文由 WorkspacePane 独立滚动，切换版本复位滚动位置。复用 DiagnosticReportViewer、现有报告打印和原工作台更正流程，不在查询页编辑临床结果。
- `GET /api/diagnostics/reports` 按当前租户、机构、执行科室和类别权限进行数据库分页；可按患者姓名/档案号、申请/报告/标本号、项目、报告状态及签发日期查询。默认近30天，可清空日期查历史。每个结果为一份报告版本，最新标识不受查询条件或分页影响。
- `GET /api/diagnostics/reports/{reportId}/history` 先校验访问权及当前执行科室，再返回同患者、就诊、申请、机构、科室和类型的完整版本链。旧版/撤销版不得打印成有效报告；查看使用原冻结内容和参考区间，不按当前模板重算。
- 两工作台请求 `activeAndRecent=true` 时，在分页前保留全部未完成任务、完成证据异常任务及近7天完成/取消记录。显式申请日期筛选仍按操作者条件执行；既有API调用不传该参数时保持原有查询语义。
- 从历史查询进入更正时用 `taskId` 单独授权加载目标任务，不放宽整个队列的近期范围；更正仍需原有编辑/签发权限及草稿并发控制。只读查询不修改、搬迁或删除历史数据。
