# 模板优先辅诊实施记录

## 已确认目标

保存模板即确认，不增加审核/发布状态或逐项确认门槛。保留当前病历、诊断、医嘱及常见查体/默认阴性预设。默认正文与本次口述证据分开，标记只辅助快速核对；保存本次病历即确认当前内容。现有签署、开立和业务校验保持原职责。

参考 floating-ball 的 `clinicalRecordAnnotation.ts`、`ClinicalRecordAnnotatedText.vue`：标记片段必须来自实际字段正文，调整/移除直接写字段，不使用只在 DOM 中存在的文本，不将未核实预设循环作为临床证据。不搬入具体临床句子的兼容过滤规则。

## 完整范围与交付顺序

1. 行内来源、变量、重点预设和冲突标记；普通文本保持简洁。悬浮说明、点击调整/移除、隐藏标记。元数据独立于正文保存，复制/打印不包含标记。医生编辑后重定位可靠标记，过期标记失效；来源保留，保存即确认。模板和 AI 生成均产生结构化标记；本次事实替换同一语义变量，保护手工修改。
2. 保存后生成当前版本的摘要、适用条件和关键词，无额外确认。不阻塞临床保存，不使用旧版本索引冒充当前版本。检索权限内 ACTIVE 模板，轻量多路召回后比较本次适用性，相似方案去重，同等适用时考虑个人偏好；无匹配允许空。移除详情重复宣教随访和适用条件常驻卡片。
3. 连续口述增量更新：仅稳定片段触发，患者/输入版本隔离、取消与缓存；准确更新受影响变量，保护手工编辑和既有选择。模板优先，无合适模板使用现有流式病历和诊疗生成，统一目录匹配、草稿和开立。生成成果保存为模板即进入下一次复用。

## 实现边界

- 医生工作台保留既有 WorkbenchPage 分区原则、FormField、Button 和现有保存主操作；标记使用共享非模态浮层，不增加独立滚动面板。
- 来源与片段独立建模，临床文字不是解析协议。变量绑定由模型/模板元数据提供，不做全局天数字符串替换。
- 生成时提供结构化标记；服务端只验证字段、锚点、来源与长度，不根据临床句式硬编码清洗。
- 未保存模板预设仍显示和随正文保存，但本次自动推理按来源识别，不当成患者明确表达。保存后确认当前版本，同时保留来源。
- 不复制手工生成的医疗阈值规则，不引入额外审核状态机，不自动提交 Git。

## 第二、三阶段实现（2026-10-02）

- 保存诊疗模板在同一事务内生成摘要、条件、关键词和临床内容摘要值；纯本地计算，不增加远程生成等待或新的审核状态。使用次数不改变内容摘要值。关联病历内容变化后拒绝旧索引，读取当前内容回退；重新保存方案生成新索引。没有对旧正文做硬编码清洗。
- 检索先限定租户、机构、个人/科室/全院可见范围及 ACTIVE 状态。诊断编码、名称、任务、索引关键词及中文二元词组参与召回；模型可扩展最多 8 个检索词，扩展词不变成患者事实。最多 20 个候选加载完整药品/项目后再比较适用性，最终最多 3 项，允许零项。模型推荐既有 ID，服务端校正名称、拒绝越权 ID。相同内容摘要值去重，个人偏好只在临床相关性排序之后参与。
- 常规生成也通过轻量索引召回并按候选加载详情，不把所有模板药品与项目送入模型。服务端上下文按 ID 稳定排序计算摘要值，使用次数或列表顺序变化不会让未改变的建议失效。
- 模板详情复用 MasterDetailPage、DataTable、Tooltip；宣教/随访只在病历段落呈现一次，适用条件通过图标悬浮展示。原始嘱托按保存值展示，去除了兼容旧句子的清洗函数。
- 连续语音只有 finalized 片段参与调度，900 ms 合并停顿，临时识别、重复 final 事件和普通键盘输入不自动生成。相同输入的方案结果使用 15 秒、最多 20 项的内存缓存；模板查询更新时清空。患者/机构/科室、输入与文书版本参与隔离，过期请求取消且迟到响应丢弃。
- 稳定口述先推荐模板；医生调入推荐模板后，用同一口述适配带语义绑定的变量。没有模板时走原有流式病历、诊断、目录匹配流程。自动带入只填空白病历或更新同一语义绑定，医生已编辑正文保留并标记冲突；没有可靠绑定的非空段落仍保留为对照建议，不能猜测替换范围。诊断与医嘱沿用原有草稿和开立入口，既有勾选、修改和已采纳医嘱保留。
- 语音结束与用户停止听写不等于新的审核操作。病历和模板仍以现有保存动作完成确认，来源元数据独立于正文。
