# 门诊辅诊提示词与默认院内候选核查

本次复核病历/诊断生成的提示词、Jev 目录判断投影与待匹配面板；沿用既有临床编排、院内目录和确认流程，不改 API 字段结构、库存/收费规则或 90% 阈值。

## 提示词问题与调整（V12）

- 原提示同时要求“必须推荐搜索意图”和“没有必要时不推荐”，容易诱导填满套餐。改为先判断本次必要性，没有依据时允许空列表；12 项是上限，不是目标。
- “不重复已有检查”缺少对口述检查结果的明确处理。现在先核对问诊、事实草稿和报告，已有有效结果能覆盖本次目的时复用；不能仅因缺少结构化报告就重新开检。确需复测时说明目的。
- 首选、替代、有条件追加和稳定期评估容易混合。现在只将当前有依据的执行方向纳入默认建议；后续触发条件用摘要或 INFO 提醒表达。联合检查须分别说明目的，不按相近名称混同部位、体位或协议。
- 原初次生成阶段禁止输出每项 rationale，医生难以核对患者事实依据。现在允许一句简短依据与目的（建议60字以内），沿用既有字段并在匹配面板展示；不编造事实、剂量、已执行状态或目录可开立性。后续目录选择阶段仍不重复生成病历或目录描述。

这些是模型输入约束；传输和解析测试不能证明每次实际模型输出的临床适宜性。继续由医生审阅，并使用已有检验结果、影像先后/替代关系等样例进行人工验收。

## Jev：原判断与默认候选分开

Jev 的 confidence 描述原 choice 的判断确定程度，choice 可能是 NONE；存在置信度不等于存在已确认等价项目。相关概念见 [TypeSafe confidence](https://docs.typesafe.ai/confidence)。

- choice/confidence 保留原值；不将 NONE 的高置信度显示为某个实际项目的置信度。
- suggestedItem 投影实际候选中概率唯一最高、且概率大于零的项目。NONE 占最高概率时，仍可提供实际候选中相对最高项作为备选，但明确“未确认等价项”。
- 只从当前院内候选白名单选择；并列最高、零概率、非有限概率、无候选或核查失败时不预选，不从候选顺序猜测。
- 默认预选与阈值分开：低于 90% 仍可预选供医生核对；不会自动变成已匹配、带入草稿或开立医嘱。
- 主行显示预选院内名称及 AI 原建议，浮动面板预填所选项。显式清空/修改优先于默认值；点击确认后按真实项目 ID 再校验可开立性。
- Jev 仍只核查目录语义，不提供临床适应证评分。肾绞痛样例的检查路径可参考 [EAU 2026 诊断评估](https://uroweb.org/guidelines/urolithiasis/chapter/guidelines)；不把特定病种规则硬编码到通用提示词。
