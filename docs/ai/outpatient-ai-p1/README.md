## 业务约束

- 模型只提取医生表达的临床意图；诊断、药品、产品、包装和服务项目身份由院内目录确定。
- 旧方案诊断缺少领域字段时只按既有兼容规则解释为西医 ICD-10。显式领域与编码体系不一致时直接拒绝，不跨域搜索。
- 药品目录、品规或包装存在多个候选时不选择首项。剂量、途径、频次或数量缺失时只保留待确认任务。
- 方案排序只处理 `visibleForCurrentContext()` 返回的权限内方案。模型引用候选集外方案 ID 时请求失败。
- 历史与标准方案差异是事实比较，不输出“符合指南”或“不符合指南”的自由判断。

## 验证

- 后端定向单元测试：诊断归一化、方案排序、药品解析、三层匹配、历史方案解析和方案差异。
- 后端集成测试：方案诊断双领域持久化、跨域拒绝、旧契约兼容、AI 方案编译和迁移执行。
- 前端：医生站 46 项测试（含复诊方案逐项取舍与合并）与生产构建通过。
- 待临床与产品共同提供真实查询、可见方案及相关性标注集，正式计算 `Recall@20 >= 0.95` 和 `NDCG@20 >= 0.85`。在此之前不得以少量合成测试替代该量化验收。
