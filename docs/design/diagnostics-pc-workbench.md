# 检验与检查 PC 工作台改版

## 设计依据

现有医技领域承担执行任务、逐管标本、报告草稿、正式版本、检查图片和打印；本次沿用这些事实及权限，重组作业入口，不建立多级审批状态机。

参考公开方案：

- [东软智慧实验室信息系统 LIS](https://www.neusoft.com/cn/products/医疗健康/面向大型医院的信息化建设整体解决方案/辅助诊断与诊疗/智慧实验室信息系统-lis/)：标本流程、报告发布、TAT 与院内系统衔接。本次落实队列、逐管操作、时间记录及报告查阅，不声称实现仪器流水线或完整质控。
- [东软 PACS/RIS](https://www.neusoft.com/cn/products/医疗健康/面向大型医院的信息化建设整体解决方案/辅助诊断与诊疗/智慧医学影像信息系统-pacs-ris/)：患者信息参考、结构化报告及检查闭环。本次落实执行前核对、所见与结论分区、关键图像、正式版本和更正。
- [创业慧康 BSLIS 产品公开介绍（Q医疗收录，非厂商官网）](http://www.qyiliao.com/product/detail/1046)：以患者标本为中心、条码管理、结果异常提示和修改留痕。只作为方向补充，不将第三方介绍当作实际界面或产品验收证据。

公开资料描述的是产品能力，不足以推断厂商具体布局。本次双栏布局来自项目共享模板与 PC 作业要求。

## 页面与操作

使用 `MasterDetailPage` 和共享 `DataTable / EditableTable / Tabs / Select / DateRangePicker / Alert / Button`。左侧固定队列标题和分页，正文使用患者申请摘要列表，展示姓名、性别、年龄、项目、状态和申请时间；右侧固定患者上下文及视图页签，结果录入正文滚动、保存与签发固定在底部。

| 作业阶段 | 检验 | 检查 |
| --- | --- | --- |
| 待结算 | 显示放行条件及结算入口 | 同左 |
| 待执行 | 选同患者同次就诊申请，生成条码，逐管采集 | 核对姓名、档案号、项目，再开始检查 |
| 已采集 | 逐管接收；所有有效标本收到后开始检验 | 不使用标本流程 |
| 执行中 | 横向多指标结果；机构模板字段只读，参考判定由服务器匹配 | 所见、结论并列；词条显式插入，关键图片依草稿版本保存 |
| 已出报告 | 默认展示正式报告，可打印或填写原因创建更正 | 同左 |
| 异常 / 取消 | 显示实际异常原因或取消状态，保留记录入口 | 同左 |

队列状态采用共享展示映射，不增加虚假的“待审核”任务状态。双签机构仍由第二名人员直接打开已保存草稿签发。

## 接口边界

`GET /api/diagnostics/worklist-page` 新增可选的 `status / createdFrom / createdBefore`。日期是申请时间：起点包含、终点不包含；前端将操作人员日期选择转换为本地日界的 ISO instant。结束日期包含整日，不按固定 24 小时换算，兼容时区夏令时。

筛选在数据库分页前执行，返回总数是匹配申请总数。已完成状态须具有匹配患者、就诊、机构、科室、类型且为最新有效的正式报告；不一致记录按待核对查询。原租户、工作上下文和权限校验保留。

任务展示新增性别、出生日期，复用健康档案模块已有快照，无新增表、迁移或跨领域数据读取接口。患者标识仍用于申请关联和一致性校验，摘要列表和患者信息区不重复展示档案号，任务号不冒充标本号。任务响应缺少性别或出生日期字段时，复用居民资料查询补齐；同一患者的多个申请与详情共享缓存，读取失败不显示成未登记。

扫码支持当前分页之外的任务；手动选择、查询或切换工作上下文后，迟到扫码响应不会覆盖选择。各任务未保存输入按机构、科室、任务隔离，视图切换、失败和患者切换均保留输入。

## 验收范围

实际自动验证记录见本任务 `.runtime/verification/`，不将 DOM 测试或编译结果记作视觉验收。

待人工验收：1280 / 1440 / 1920px 各自标准与大字模式；长申请号、多指标、较多图片、分页末页状态变化、双签身份、实际条码和报告打印。未执行真实系统浏览器 QA。

仪器协议、完整 LIS 质控、PACS 归档和阅片、预约叫号、CA，以及草稿阶段危急值通报仍按 [医技领域边界](../ai/diagnostics.md) 后续专项推进。
