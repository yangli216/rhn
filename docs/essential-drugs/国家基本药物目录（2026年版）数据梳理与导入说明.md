# 药品标准参考目录建设说明

本目录基于项目内用户提供的《国家基本药物目录（2026年版）》DOCX 重建，保留全部原文条目及出处，拆分可明确识别的剂型和规格。它是版本化的标准参考目录，可以浏览、检索并用于后续术语映射。2026-09-22 已核对中国政府网官方通知（国卫药政发〔2026〕17号）及原始 PDF，2026-09-01 起施行；发布事实记录在 `official-publication.json`。目前规格来自用户 Word 转录，发布事实确认不等于全部转录规格、厂家产品或临床知识已审核。

## 成果与入口

应用入口：基础数据中心 → 药品目录 → 标准参考目录。列表按品种查看，右侧展示独立规格、原文位置及核验事项。

后续业务接入已按用户约定推进：暂不增加数据核验和审核流程，可从具体规格点击“建立本院药品”，连续完成药品属性、厂家产品、包装和本院价格配置。参考目录的来源状态不阻止本院建档。操作方法与联调记录见 [业务链路联调说明](业务链路联调说明.md)。下述来源审核要求作为未来正式采纳建议，不是当前调试流程的前置条件。

| 文件 | 用途 |

## 修复的原始问题

1. **剂型规格混在一行**：阿莫西林的片剂、胶囊、颗粒剂、干混悬剂与 0.125g/0.25g 分为八条；缓释、肠溶、普通剂型保留独立标识。
2. **盐型或物质限定丢失**：钠盐、钾盐、头孢呋辛酯等原文限定单独保存，不以名称模糊匹配合并。
3. **名称截断**：维生素 B1、B2、B6、B12、K1、C、D2、两性霉素 B、碳酸钙 D3 保留完整名称及英文信息，避免字母或数字后缀被划入英文名。
4. **体积被当作药物含量**：阿米卡星的 1mL:0.1g 保存为分子 0.1g / 分母 1mL。仅有体积时不会伪造药物质量。
5. **复方被拆成多个药品规格**：每粒含多个成分时保留完整配方；复方比例及每成分数值不会缩成第一个数字。“D3 200 国际单位”等成分后缀与剂量之间的边界保留，不拼成“D3200”。
6. **推断临床属性**：停止按剂型、药名、类别自动生成途径、频次、皮试、抗菌药分级、处方属性和储藏条件；未知值保留为 null。
7. **范围条目伪装药品**：结核病用药、艾滋病用药、青蒿素类药物、血友病用药、抗蛇毒血清、国家免疫规划用疫苗、避孕药共七项按原文注释作为范围条目，不生成默认片剂。
8. **产物粒度不一致**：统一从同一标准目录派生查询资源和三张 CSV，不再维护 794 条 SQL 与 1,217 条导入表两种互相不一致的药品数据。

## 标准化与临床审核的边界

`GEN-*` 标识目录品种，`STD-*` 标识品种、物质限定、剂型及规格组合。标识基于规范化内容确定生成，不包含目录年份或导入顺序；标识字段变化会生成新标识，旧 `MED-2026-*` 来源编码保留为映射线索。当前提供首版快照，后续发布需保留旧版快照和变更映射，尚未实现在线历史版本管理。`sourceVersion` 为原始文件 SHA-256；`semanticVersion` 为本次标准化版本。源文档位置采用一基表序号/行号，跨分类出现保留全部出处。

目录所有条目默认 `orderable=false`、`reviewStatus=SOURCE_UNVERIFIED`。这表示目录尚未完成来源及临床审核，不能通过本接口直接开药。结构化成功不等于获得处方适用性批准。

强度模型分别表达单次制剂含量、质量/体积浓度、多成分数值、单纯体积、未明确基准的百分比和中成药制剂规格。`strength.computable` 仅表示该片段可表达确定的数值结构，**不表示可直接计算患者安全剂量**。尚需核对成分标识、含量计量基准、患者事实和用药方案；干混悬剂复溶后的浓度也不能由原粉末含量推断。

包装单位、批准文号、厂家、价格、库存、本院启停和处方默认用法属于后续产品/机构配置。原文没有的信息保持未确定，不由本生成器补造；颗粒剂不默认赋“袋”，注射用无菌粉末不默认赋“瓶”。

## 当前数据库处理

2026-09-15 只读盘点显示，两套人工验证服务连接同一 Oracle 配置；库内现有 14 条演示药品、12 条产品、11 条药品请求、2 条皮试事件，`MED-2026-*` 记录数为 0。旧导入数据未实际入库，因此无须删除患者、处方、库存或价格记录来修复旧文件。

本次重建的是标准目录产物和应用参考目录入口。用户已允许清空重建药品相关数据；实际根据盘点结果，保留现有演示业务，避免产生无意义的破坏。原生成物已归档至忽略目录 `output/medication-rebuild/legacy-generated-data-before-rebuild.tar.gz`，Git 历史亦可恢复。

已移除旧的两个 INSERT 脚本及旧导入 CSV/JSON，防止将自动猜测的属性批量启用。旧 SQL 位于未被当前 Flyway 配置扫描的 `db/seeds`，并非已经应用的迁移；本次未改写任何已执行的 `db/migration` 或 `db/oracle` 迁移。

## 重建与验证

```bash
python -m pip install -r docs/essential-drugs/requirements.txt
python docs/essential-drugs/build_essential_drugs.py
python docs/essential-drugs/build_essential_drugs.py --check
python -m unittest discover -s docs/essential-drugs -p 'test_*.py'
```

`--check` 校验来源抽取和已提交的目录资源是否一致。生成器不访问数据库、不自动启用药品、不调用 AI；新来源版本或解析逻辑变化必须运行回归并审阅差异后随构建发布。

后续正式采纳顺序：核实来源版本 → 完成待核验规格/成分映射 → 按说明书及适用制度核定临床属性 → 药学审核 → 关联具体厂家产品 → 本院采纳及价格/库存配置。即使后续增加批量采纳，也不得将本目录中的 null 临床属性转换成“无需皮试”“无限制”等否定性安全结论。
