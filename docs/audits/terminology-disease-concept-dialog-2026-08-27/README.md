# 疾病概念表单审查与优化

## 审查范围

- 流程：基础数据中心 → 疾病与术语 → 新增疾病概念。
- 用户目标：快速、准确地建立带标准编码、检索信息和有效期的疾病概念。
- 证据：[01-before.png](01-before.png)。

## 步骤 1：新增疾病概念表单

健康度：需优化，功能字段完整，但结构和密度影响录入效率。

### 优点

- 必填项、日期控件和主操作清楚。
- 双列布局在当前宽度下保持了较好的字段宽度。
- 关闭、取消、保存的位置符合平台统一习惯。

### 主要问题

1. 下拉框容器和触发器同时获得边框，出现双描边；标签关联的也是外层容器，影响点击标签聚焦和辅助技术识别。
2. 通用字段上下边距与网格间距叠加，行间距过大，表单被拉长到接近整屏。
3. 标准身份、目录检索、有效期和定义说明没有分组，所有字段视觉权重相同。
4. 检索码、章节信息和定义说明缺少示例，用户需要依赖既有经验理解填写规则。
5. 失效日期没有在界面侧约束必须晚于或等于生效日期。

### 已落实优化

- 修复自定义下拉框的单层边框、标签定位和 `aria-required` 传递。
- 取消表单网格内重复字段外边距，并为宽屏增加三列布局。
- 重组为“标准身份”“目录与检索”“有效期与说明”三个语义区块。
- 增加编码、章节、检索码、别名和定义说明示例。
- 失效日期使用生效日期作为最小值。
- 疾病概念弹窗使用桌面端宽屏布局和吸底操作区。

## 基础数据管理统一优化

本次优化已扩展到基础数据管理下的全部维护流程：疾病概念、诊疗项目、通用药品知识、生产企业、厂家产品、产品包装、机构采用和有效期价格。

- 以 PC 端为主要使用环境：复杂表单使用 64rem 宽弹窗和 3–4 列网格，短表单使用 52rem 宽弹窗，避免窄而长的单向排版。
- 按“身份信息—业务属性—生命周期/说明”组织字段，降低跨字段核对成本。
- 日期范围统一约束结束日期不得早于开始日期；能力项统一使用带标题的字段组。
- 列表与药品详情保留横向高密度信息架构，较窄视口仅做防破版降级，不作为专项移动端方案。
