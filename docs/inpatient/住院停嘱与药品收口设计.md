# 住院停嘱与药品收口设计

## 1. 建设目标

住院药品医嘱停嘱后，系统必须同时收口执行任务、药房任务、库存预留、病区配送、未用药退回和出院门禁，不能只把医嘱状态改为“已停嘱”。

基层简易模式坚持三个原则：

- 医生只确认停嘱时间和原因，不要求判断库存、配送或退药步骤。
- 系统自动冻结新的接方、预留、配药、发药和给药动作，并给药房、病区生成明确待办。
- 已经发生的发药、交接、给药和退药均保留原事实，不删除、不改写、不用状态备注冒充库存冲回。

## 2. 事实边界

继续复用现有事实源，不建立第二套医嘱、库存或收费账：

- 医嘱事实：`care_requests`、`medication_requests`、`inpatient_order_workflows`、`inpatient_order_tasks`。
- 药房履约：`dispense_tasks`、`dispense_task_lines`、`medication_dispenses` 及批次明细。
- 保管交接：`ward_deliveries`、`ward_delivery_lines` 和追加事件。
- 给药核销：`inpatient_med_consumptions`。
- 实际退药：`stock_returns`、`stock_return_lines` 和反向库存分录。
- 收费：实际发药记正向费用，实际退药按原价格冲销。

跨角色的“病区已申请、药房尚未接收”不是现有退药事实能够表达的状态，应使用独立、轻量的病区退药申请事实；该事实只负责编排，不复制库存和费用结果。

## 3. 停嘱阶段处理矩阵

| 停嘱时点 | 系统处理 | 后续责任 |
|---|---|---|
| 尚未药房接方 | 取消共享药品请求和未来执行任务 | 无 |
| 待审方/待干预/待拣货 | 自动取消药房任务 | 无 |
| 拣货中/已配药未发出 | 原子释放有效预留并取消药房任务 | 药房确认实物回架；基层默认一键完成 |
| 已发药、未建立配送或待送出 | 禁止继续送出，按原发药批次办理退药和费用冲回 | 药房 |
| 配送中 | 禁止给药，保持在途事实；病区先真实签收，再发起退回 | 药房与病区 |
| 病区已签收、尚未给药 | 计算全部可退量，形成病区退药待办 | 护士发起、药房接收 |
| 已部分给药 | 保留已核销剂次，只退未核销净量 | 护士发起、药房接收 |
| 已全部给药 | 医嘱和任务收口，无退药待办 | 无 |

在途药首轮不实现复杂路线召回。保持“先完成真实交接、再反向交接”的守恒路径，避免系统声称药已回库而实物仍在途中。

## 4. 数量与保管不变量

每条发药批次必须满足：

```text
实发量 >= 已给药核销量 + 已退药量
可退量 = 实发量 - 已给药核销量 - 已退药量
```

完整保管守恒为：

```text
实发量 = 药房待送量 + 在途量 + 病区持有量 + 已给药量 + 已退药量 + 已明确交付的出院带药量
```

首轮不把病区药柜建成独立库存账，但必须通过配送签收、给药核销和退药交接推导病区持有量。

## 5. 服务端硬门禁

- 停嘱截止时点后不得创建新的正向发药事实。
- 已取消药品请求不得继续预留、完成配药或发药；不能只在接方和审方入口校验。
- 配送中或病区已签收的药品，药房不能在缺少反向交接证据时直接登记回库。
- 已给药数量不得退回；超量退药由服务端拒绝。
- 同一停嘱、撤回、退药申请、接收命令必须幂等；重复提交不能重复释放库存、退药或冲费。
- 停嘱和给药执行采用一致的锁顺序，避免 workflow 与 task 反向加锁。
- 临床出院门禁必须检查待送出、在途、配送差异、病区可退余药和未完成的出院带药履约。

## 6. 基层页面交互

### 6.1 医生

停嘱弹窗显示系统推导的药品去向摘要。医生仍只填写停嘱原因：

- “未发药，将自动撤销药房任务”；
- “已发未送，将由药房撤回”；
- “配送中，病区签收后退回”；
- “病区余药 2 粒，待护士退回”；
- “已全部给药，无需退药”。

### 6.2 护士

在原护理给药工作面显示实收、已给、已退和可退数量。医嘱停嘱后且可退量大于零时提供“申请退回药房”；护士不决定重新入库、隔离或销毁。

### 6.3 药房

取消后的共享药品请求若仍有未完成药房任务，必须继续显示在收件箱中。药房按保管位置完成：

- 取消未发任务并释放预留；
- 撤回待送出药品；
- 接收病区退药并选择重新入库、隔离或待销毁；
- 继续复用既有批次、追溯、库存和费用冲回能力。

## 7. 出院带药边界

出院带药必须是独立、结构化的药品用途，至少包含药品、单次剂量、途径、频次、疗程或天数、数量和交付方式，并继续进入药房审方、发药、收费和患者交付流程。

病区余药不得通过“不退药”静默转为出院带药。正确顺序是：

1. 停止住院给药医嘱并清算病区余药；
2. 医生新建明确的出院带药计划；
3. 药房独立审方、发药并记录患者或床旁交付；
4. 出院门禁确认病区余药和带药履约均已收口。

病历中的“出院带药”文本只用于叙述和打印，不能替代结构化履约事实。

## 8. 首轮验收场景

1. 待审方、待拣货、拣货中和已配药未发出阶段停嘱，均不能再发药，且有效预留归零。
2. 部分发药后停嘱，未发余量取消，已发未用量可以退回，已给药量不能退回。
3. 待送出配送撤回后不能再次送出；在途药必须先完成真实签收再退回。
4. 护士重复发起退回、药房重复接收均返回相同业务结果，不重复库存或费用事实。
5. 其他病区不能读取或操作患者余药。
6. 存在待送出、在途、配送差异、病区余药或未完成出院带药时，出院门禁给出明确阻断原因。
7. 所有余量清零且出院带药已交付后，出院门禁通过。
