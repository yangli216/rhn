# 预检分诊辅助第一期

沿用现有 WorkbenchPage 分区原则、PageHeader、PanelHead、Button 和队列/作业/辅助区滚动；不新增页面壳、边距或业务组件外观。

## 边界与开关

- `TriageAssessmentEngine` 与保存服务负责确定性规则及最低安全分级；第一期决策不返回分级、诊断、治疗或绿色通道。
- `ClinicalTriageDecisionService` 复用 `DecisionModelGateway`，仅在真实机构科室候选中选择，保留 `NONE`；资料问题分别核对开始时间、变化过程、伴随症状、相关病史/近期用药。已明确记录或与本次主诉无关的资料不重复提示，未知不当作正常或否认。
- `decision-scene-outpatient-triage-enabled` 默认 false，与决策总开关共同控制。模型、独立密钥、超时及置信度继承共用配置；未配置、超时、格式错误、候选超限都回退原流程，不外显供应商异常正文。
- SHADOW 保留原规则/生成式分诊流程，记录旁路判断；响应不提供可采纳建议。ASSIST 使用规则分级并停用原生成式分诊调用，避免两个模型重复推荐；仅提供需人工采纳的科室建议及待核实资料，不自动填写科室。
- 护士在到院初筛点击「人工采纳科室建议」才改变去向；已有挂号的建议只供核对，继续使用现有转诊流程。低置信度或无匹配不猜科室；参考分与概率/置信度分开，不把分布集中程度展示为医学正确率。
- 查询键包含机构、科室、患者和完整评估输入；输入修改在防抖期间立即隐藏旧建议，切换患者后旧请求结果不能继续用于采纳或自动联动。

## 契约和观察证据

`POST /api/outpatient/triage/assessments` 返回原评估及决策模式；`POST /api/outpatient/triage/assessments/decision` 返回受限辅助结果。权限复用现有分诊评估权限，TS 新增类型从运行 OpenAPI 生成。

观察沿用共用决策的结构化日志：租户/机构、请求关联、追踪号、输入 SHA-256、规则/提示版本、模型、概率分布、阈值、耗时及与规则首选科室的一致性；不记录主诉正文、身份字段、密钥或供应商响应正文。分诊记录继续保存护士最终选择和原因。运行观察迭代已追加共用决策运行快照及人工研判，详见 `docs/ai/decision-observation.md`。当前尚未将最终分诊保存与决策运行记录持久化关联，也没有自动采纳率报表；输入快照用于人工核对，不是自动临床回放入口。

## 试用与验证

先配置独立服务连接，再以总模式 SHADOW + 分诊场景开关做旁路观察。用经审核的本地样例比较科室一致性、无法确定比例、资料提示是否重复/遗漏、服务失败和耗时；置信度阈值需要本地验证，默认门槛不是正确率承诺。评估通过后才切换 ASSIST；关闭场景即可回到原有流程。首次上线仍需临床负责人确认，本轮不修改人工服务配置。

自动检查入口：`./scripts/verify-scope.sh triage`。契约/迁移变更执行完整验证与临时 test 服务 OpenAPI 同步，测试使用随机 H2，不连接人工 Oracle。另需在 1280/1440/1920px 下人工确认标准/大字、辅助区滚动、加载/失败/不确定、患者切换和人工采纳；DOM 测试不等于临床有效性或视觉验收。
